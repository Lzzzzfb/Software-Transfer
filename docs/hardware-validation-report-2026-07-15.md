## 协议实测结果

- 普通响应：`0x24 | nLength(U16LE) | Cmd | Params | Checksum`，物理长度为 `4+nLength`。
- 三台现有固件的 `0x80` 数据帧均为：`Cmd + U16LE 包号 + U16BE 像素 + Checksum`。
- 实机 `nLength=3+2*N`，校验码不计入 `nLength`；程序同时兼容函数表中的 U32 包号新版格式。
- COM14/COM17 单帧物理长度 7395 字节，COM18 为 4111 字节；有效像素裁剪分别得到 3648、3648、2048 点。
- `DEVICE_INIT(0x10)` 的实机 ACK 使用响应 `Cmd=0x01, Status=0x61`，与函数表的响应 `Cmd=0x10` 不同；程序已显式兼容。
- `0x39/0x3A` 查询必须携带 U32 请求长度，不能作为空参数状态查询；界面已停止自动发送这两个命令。

## 本轮发现并修复

- 增加实机 U16 包号数据格式与函数表 U32 格式的无歧义双格式解析。
- 帧序诊断会跟随协议使用 16/24 位回绕，避免实机长时采集超过 65535 帧后误报。
- 初始化和参数查询改为节流发送，防止大响应与采集帧交叉导致解帧告警。
- 采集中禁止继续发送参数/查询命令，必须先停止采集。
- 参数对话框只提交实际改动项，并按 120 ms 间隔发送，等待各命令 ACK。
- 硬同步会先配置从机为外触发、内部主机为软件主机，全部收到 ACK 后再按从机优先、主机最后的顺序启动；上位机不发送逐帧 `0x54`。
- 新增 `--ports COM14 COM17 COM18`，可限制自动连接端口，避免同类 USB 串口被误连。

## 仍需具备现场条件后确认

- 物理硬同步接线的主机端口及信号方向尚未提供，因此未擅自切换三台设备做有线硬同步；外部硬同步还需要外部触发源。
- 绝对波长精度需要已知谱线光源；真实暗场、参考场和吸光度需要对应光学样品。

- 当前只有三台设备，无法完成四台 4096 像素、100 fps 的实机压力条件；三台默认 500 帧批次已验证。
