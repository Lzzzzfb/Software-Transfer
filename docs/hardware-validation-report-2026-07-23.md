# 采集控制、界面与存储实机联调报告（2026-07-23）

## 1. 结论

本轮代码在 Python 3.13.7 64 位、PySide6 6.11.1 环境完成全量自动测试、双 Qt 模拟端到端验证，并在当前可响应的 COM14 光谱仪上完成正式主界面控制链路回归。COM14 当前识别为生产序列号 `002`、固件 2.2、3648 有效像素。

COM17 和 COM18 当前无法完成协议握手，因此本轮新增功能尚未在三台同时在线的现场状态下全部复测。2026-07-22 的报告已经证明相同三台设备当时能够被识别并完成采集；本报告记录的是 2026-07-23 当前 USB/设备状态，不能用旧结果替代当前问题。

- PyQt5 全量测试：115 项通过。
- PySide6 源码编译和重点 UI 绘制通过。

- 尾批导出失败故障注入验证：存储线程立即退出、状态释放、`.part` 保留。

## 4. 正式主界面实机结果

COM14 已完成：

- 顶部总控连续开始/停止 10 轮；
- 独立采集和软件同步配置；
- 卡片单机开始/停止；
- 单机运行时拒绝总控和背景，总控运行时拒绝卡片和参考；
- 顶部新鲜背景采集和卡片新鲜参考采集；
- 固定 Y 后真实新帧不改变人工缩放范围，复位恢复 `0–65535`；
- 自动存储开启后的完整批和尾批；
- 无缺帧、重复、乱序或回绕诊断。

10 轮完整控制报告中共接收 68 帧；正式存储报告生成 3 个 CSV 和 3 个 Excel 批次文件。停止函数调用最大约 3.6 ms。

消除停止后每 33 ms 的无效整图重绘后，两个 3648 像素 CSV/Excel 批次的后台收尾时间从约 28.7 秒降至约 1.0 秒；GUI 不等待导出完成。冷启动后的单次整图绘制仍可能产生约 0.3 秒的最大心跳间隔，持续绘制典型耗时约 7–18 ms。

## 5. 存储结构核对

实机首批文件名符合人类可读规则，例如：

```text
20260723_092508_SN002_COM14_独立采集_B0001.csv
20260723_092508_多设备_独立采集_B0001.xlsx
```

Excel 工作表为“采集概要”和 `002`；设备工作表范围 `A1:G3649`，A/B 列是 Pixel/Wavelength，C–G 为 5 帧。CSV 同为 3648 行像素、5 帧列，首末帧序号与 Excel 对应。正常结束没有残留 `.part`。

## 6. 当前未完成的两台设备

Windows PnP 将三个端口都报告为 `CM_PROB_NONE`，但协议实测如下：

- COM17：串口可打开；115200、230400、460800、921600 波特率均收到 0 字节；发送停止 `0x52` 后再次发送版本 `0x01` 仍无响应。
- COM18：QSerialPort 打开失败，Windows 返回“连接到系统上的设备没有发挥作用”。
- 尝试用 `pnputil /restart-device` 重启 COM17 设备节点时系统拒绝访问，当前进程没有设备重启权限。

因此需要对 COM17、COM18 进行物理断电/重新插拔，或由管理员重启对应 USB 设备节点。恢复响应后应使用本轮新增的工具执行三机复测：

```powershell
.\.venv\Scripts\python.exe tools\hardware_ui_control_validation.py COM14 COM17 COM18 `
  --output-dir data\validation\hardware_ui_control_3dev `
  --expected-devices 3 --cycles 10
```

所有原始 JSON、截图、CSV、Excel 和结构核对结果保存在未纳入 Git 的 `data/validation/`。
