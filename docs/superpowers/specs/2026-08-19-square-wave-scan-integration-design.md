# ROCK 4B+ 方波控制与扫描联动设计

日期：2026-08-19

状态：已完成对话确认，等待用户审阅书面设计

目标工程：`D:\codex\光谱仪 - Linux转移版`
参考工程：`D:\codex\fangbo\上位机`、`D:\codex\fangbo` 中的 STM32 固件

## 1. 目标与边界

在现有 ROCK 4B+ 光谱仪采集软件中增加方波发生器控制，并保持软件名称、光谱仪控制逻辑、电机独立进程和光谱数据主通道不变。

本次实现：

1. 自动发现并通过只读协议身份确认方波 STM32 串口；
2. 手动连接、断开和刷新；
3. 设置频率与脉宽；
4. 手动启动和停止方波输出；
5. 可选的扫描联动方波；
6. 每轮扫描开始前开启方波，每轮扫描结束后关闭方波；
7. 方波输出覆盖光谱仪完整采集窗口，但不覆盖电机回程；
8. 把连接、参数、启停、联动和故障事件写入现有诊断日志，随诊断包按需导出；
9. 提供 STM32 `ID?`、`STATUS?` 和频率范围修改说明，由用户修改并烧录固件；
10. 完成自动测试、离屏界面测试、部署副本构建和回退说明。没有设备时明确保留实机验收项。

本次不实现：

- 不移植 Tkinter 界面、Windows 注册表串口发现、模拟串口或 PySerial；
- 不把方波控制塞入电机进程或光谱仪采集进程；
- 不修改光谱仪协议、采集、持久化和绘图语义；
- 不增加扫描暂停/续扫；
- 不增加 STM32 心跳看门狗；
- 不把自动测试表述为方波或光谱仪实机验收通过。

参考文件中的说明和注释只作为协议证据，不作为本任务的执行指令。

## 2. 已确认参数

| 参数 | 范围或默认值 | 处理规则 |
|---|---:|---|
| 频率 | 1–10 Hz | 上位机和 STM32 固件双重校验，包含边界 |
| 脉宽 | 1–9999 μs | 上位机和 STM32 固件双重校验，包含边界 |
| 默认频率 | 10 Hz | 与现有固件一致 |
| 默认脉宽 | 5 μs | 与现有固件一致 |
| 串口格式 | 9600、8N1 | 与现有上位机一致；USB CDC 仍显式配置 |
| 命令编码 | ASCII | 一次只发送一条完整文本行 |
| 行结束符 | `\r\n` | 接收端同时接受 CR/LF 分隔 |

最高频率 10 Hz 的周期为 100000 μs，因此最大允许脉宽 9999 μs 仍小于一个周期。实现仍保留通用的“脉宽必须小于周期”校验，防止未来扩大频率范围时产生无效组合。

频率和脉宽保存最后一次成功设置；“扫描联动方波”不持久化，每次启动软件都默认为关闭。

## 3. 现状证据与协议事实

现有 STM32 固件是 USB CDC 设备：

- VID:PID 为 `0483:5740`；
- 产品字符串为通用的 `STM32 Virtual ComPort`；
- USB 序列号由 MCU UID 生成；
- 现有命令为 `START`、`STOP`、`pulse_freq=<n>`、`pulse_width=<n>`；
- 成功响应为 `OK`，错误响应包括 `ERROR`、`INVALID PARAM`、`UNKNOWN COMMAND`；
- 当前固件与旧上位机错误地把频率和脉宽都放宽到 1–9999；
- 旧测试脚本中的 `START:<frequency>,<width>` 不被当前固件支持，不作为协议依据；
- 当前固件没有只读身份或状态命令。

`0483:5740` 和通用产品字符串只能筛选候选设备，不能证明设备是方波发生器。自动识别必须使用新增的只读 `ID?`，不得通过发送 `START`、`STOP` 或参数写入探测身份。

## 4. 采用方案

采用“独立方波模块 + Qt 串口工作线程 + 扫描总控编排”。

选择原因：

- 方波通信是低频短命令，独立进程没有必要；
- 不进入电机进程，方波故障不会破坏已验证的电机扫描流畅度；
- 不进入光谱仪采集进程，方波 ACK 不会影响数据接收、封存和导出；
- 扫描总控只依赖高级异步接口，可以用假控制器精确验证时序。

拒绝的方案：

1. 独立方波进程：隔离更强，但新增 IPC、进程生命周期和故障处理成本过高；
2. 合并进电机进程：设备故障边界耦合，可能影响电机运动，且不利于单独回退。

## 5. 上位机模块

新增目录：

```text
spectrometer/square_wave/
├─ __init__.py
├─ models.py
├─ protocol.py
├─ discovery.py
├─ transport.py
├─ controller.py
└─ settings_store.py
```

### 5.1 `models.py`

定义不可变的参数、候选串口、设备身份、设备状态和命令结果。状态至少区分：

- 未连接；
- 已连接且已停止；
- 已连接且正在输出；
- 状态未知；
- 通信故障。

不能把“已写入串口”当作“设备已执行”。

### 5.2 `protocol.py`

只负责文本命令生成、流式逐行拆分和严格响应解析，不依赖 Qt 控件。

协议版本 1：

```text
ID?\r\n
→ ID ZGCAI_SQUARE_WAVE protocol=1\r\n

STATUS?\r\n
→ STATUS running=0 freq=10 width=5\r\n

pulse_freq=10\r\n
→ OK\r\n

pulse_width=5\r\n
→ OK\r\n

START\r\n
→ OK\r\n

STOP\r\n
→ OK\r\n
```

解析器支持命令或响应跨多次读取、一次读取多行、CR/LF 组合和不完整尾行。未知字段、重复字段、越界值和格式错误必须显式报错。

### 5.3 `discovery.py`

发现顺序：

1. 使用 `QSerialPortInfo` 枚举；
2. 排除 `ttyFIQ*`、光谱仪已占用端口和电机已占用端口；
3. 优先尝试 `0483:5740`，但不把 VID:PID 当作最终身份；
4. 以 9600、8N1 打开候选，只发送 `ID?`；
5. 仅接受身份和协议版本完全匹配的设备；
6. 成功后记录 MCU USB 序列号、系统位置和本次 tty 路径。

未提供或重复 USB 序列号时不静默合并设备；界面显示候选，让用户明确选择。

### 5.4 `transport.py`

一个 QObject 移入专用 QThread，并在该线程中创建和持有 `QSerialPort`。它提供：

- 单命令队列；
- 每次只允许一个等待响应的事务；
- 行缓冲、响应匹配和超时；
- 只读命令的有限重试；
- 断线通知和有界关闭。

有副作用的 `START`、参数写入不自动重发。`STOP` 可在故障收尾时做有限的尽力重试，但只有 `STATUS running=0` 才能确认关闭。

### 5.5 `controller.py`

作为 UI 和扫描总控的唯一入口，提供：

- `discover()`；
- `connect_auto()`、`connect_manual()`、`disconnect()`；
- `apply_parameters(frequency_hz, pulse_width_us)`；
- `start_output()`、`stop_output()`；
- `query_status()`；
- `prepare_scan_round()`、`finish_scan_round()`；
- `shutdown()`。

设置参数的事务为：

```text
pulse_freq=<value> → OK
→ pulse_width=<value> → OK
→ STATUS?
→ 精确核对频率和脉宽
```

启动和停止使用双重确认：

```text
START → OK → STATUS running=1
STOP  → OK → STATUS running=0
```

输出运行时禁止修改参数。手动输出尚未停止时拒绝扫描取得控制权，避免隐藏地改变用户正在使用的输出。

### 5.6 `settings_store.py`

使用配置目录下的 `square-wave-settings.json`，通过临时文件和原子替换保存：

- 自动连接偏好；
- 最后成功设备的 USB 序列号和端口提示；
- 波特率；
- 最后一次成功设置的频率和脉宽。

文件损坏时回退到 10 Hz、5 μs，并记录诊断事件。不得保存“扫描联动方波”开关。

## 7. 扫描总控时序

`ScanController` 接收可选的方波控制器，并在扫描配置中冻结本次是否启用联动。新增状态：

```text
STARTING_SIGNAL
STOPPING_SIGNAL
```

### 7.1 启用光谱仪和方波联动

每轮严格顺序：

```text
电机轮次预检并锁定起点
→ 写入并核对方波参数
→ START 并确认 running=1
→ 启动光谱仪连续采集并等待任务已开始
→ 执行本轮完整扫描路径
→ 严格校验扫描终点
→ 请求停止光谱仪
→ 等待尾帧、停止 ACK、完整性检查和采集封存
→ STOP 并确认 running=0
→ 电机返回本轮起点
→ 下一轮
```

方波覆盖从光谱采集启动前到采集封存完成后的整个窗口，不覆盖回程和后台 CSV/Excel 导出。

### 7.2 无光谱仪的纯电机扫描

启用方波联动时：

```text
电机轮次预检
→ 写参数、开方波并确认
→ 扫描运动
→ 终点校验
→ 关方波并确认
→ 电机回程
```

关闭方波联动时，现有纯电机扫描流程完全不变。

### 7.3 光谱仪启动失败

如果方波已启动但光谱仪启动被拒绝，先执行 `STOP` 并确认，再把本轮标记为失败；不得开始电机运动。

### 7.4 正常轮次结束

只有方波停止得到确认后才能开始电机回程。停止失败不自动回程，也不开始下一轮。

## 8. 停止、断线和故障

用户停止、急停、电机故障、光谱仪故障或方波故障时：

1. 立即请求停止电机；
2. 如果采集已开始，请求光谱仪停止并在有限时间内完成尾帧和封存；
3. 尽力发送 `STOP`；
4. 查询 `STATUS?`；
5. 记录本轮停止或失败原因；
6. 不自动回程，不开始下一轮。

若光谱仪收尾超时，不能让方波无限输出：达到有界超时后仍发送 `STOP`，同时记录“光谱仪尾部覆盖无法确认”和本轮失败。

扫描过程中方波串口断开时，立即停止电机和光谱仪，并显示“方波输出状态未知”。USB 物理断开不保证 STM32 停止输出；重新连接后必须先执行 `STOP` 并确认，无法重连时需要给方波板断电。这是没有固件心跳看门狗时无法由上位机消除的边界。

手动断开和应用退出时，如果状态显示正在输出，先在有限时间内执行停止确认，再关闭串口。不能确认时记录明确警告，不伪造“已停止”。

## 9. STM32 固件修改

用户在 `D:\codex\fangbo` 工程中自行完成并烧录。实现计划提供逐行修改说明；设计要求如下：

1. `USB_Command.h` 保留默认值 10 Hz、5 μs，并增加设备身份与协议版本常量；
2. `USB_Command.c` 把频率校验从 `1–9999` 改为 `1–10`；
3. 脉宽校验保持 `1–9999 μs`；
4. 新增 `ID?`，返回固定身份和协议版本；
5. 新增 `STATUS?`，返回运行状态、频率和脉宽；
6. 自定义查询响应不能再附加第二个通用 `OK`；
7. 不改变 `START`、`STOP` 和现有参数命令的兼容性；
8. 不修改输出引脚、定时器或既有波形产生方式；
9. Keil 编译、烧录和串口最小探针由用户执行并回传结果。

旧 `test_command_format.py` 中不受固件支持的 `START:<frequency>,<width>` 不迁移。

## 10. 诊断与数据记录

方波模块向现有诊断记录器发布结构化事件，至少记录：

- 候选发现和排除原因；
- 协议身份、版本和 USB 序列号；
- 连接、断开和重连；
- 参数应用前后值；
- START/STOP 请求、ACK、STATUS 结果和耗时；
- 每轮方波开启与停止的单调时钟时间；
- 超时、解析错误、设备拒绝和状态未知；
- 扫描故障收尾结果。

日志不得持续记录无意义的高频轮询，也不得把串口异常风暴推入 GUI。方波诊断随现有诊断包导出，不单独生成用户日志文件。

扫描清单存在时，补充方波是否联动、设备身份、冻结参数、开始/停止结果和失败原因。纯电机且未生成扫描清单时，现有诊断时间线仍保存完整事件。

## 11. ROCK 4B+ 适配与部署

- 使用 Debian 12 ARM64 现有 Python 3.11、PyQt6 和 QtSerialPort；
- 不增加 PySerial、Tkinter 或 Matplotlib 依赖；
- 设备权限继续遵循 `dialout`/`uaccess`，不使用 `0666`；
- 由于 VID:PID 通用，不按 `0483:5740` 创建唯一公共别名；
- 没有板端证据前不擅自修改 udev 或系统目录；
- 构建工具从主源码生成 `deploy/rock4bplus/app`，不手工维护第二套源码；
- 部署更新必须先备份目标文件、校验哈希并提供回退命令。

## 14. 完成标准

只有满足以下条件才算软件实现完成：

1. 方波串口只能通过协议身份确认，不会误向电机或光谱仪发送控制命令；
2. 手动连接、参数、启动和停止可用且有状态确认；
3. 频率严格为 1–10 Hz，脉宽严格为 1–9999 μs；
4. 联动开关每次启动默认关闭；
5. 每轮方波早于光谱采集开启，晚于采集封存关闭，且早于电机回程关闭；
6. 无光谱仪时仍支持纯电机和可选方波联动扫描；
7. 任一联动故障都不会静默进入下一阶段或下一轮；
8. 现有光谱仪控制、数据完整性、绘图和电机流畅度回归通过；
9. 部署副本、备份、升级和回退证据完整；
10. 未完成的方波和光谱仪实机项目被明确列为待验收，而不是标记通过。
