# LK-MD2202 与光谱仪融合的预测扫描设计

- 日期：2026-08-18
- 状态：设计已确认，等待书面规格复核
- 范围：优化扫描区域内相邻电机运动段的衔接，同时保持当前PyQt6光谱仪采集、保存、绘图和故障逻辑

## 1. 背景与证据

ROCK 4B+诊断包 `003.zip` 记录了一轮无光谱仪的
`x=10 mm, y=1 mm, n=10, m=1, X/Y步数=1, 步时=0` 扫描。上一段运动
汇总后约0～3 ms即发送下一轴命令，证明当前`ScanController`没有增加换轴等待。

当前严格完成判定必须读取“已停止且到达目标”。状态读取无失败时，X轴动作耗时
约551～627 ms，Y轴扫描段约289～303 ms；出现两次100 ms状态读取失败时，
X轴增至约758～791 ms，Y轴增至约444～462 ms。剩余不流畅来自LK-MD2202
运动末端的状态无响应窗口，不是ROCK 4B+负载、绘图或光谱仪采集。

旧项目 `D:\codex\电机控制软件` 已针对同一驱动器实现并完成实机验收：通过末端
位置/时间预测绕过停止状态恢复滞后，并配套运动指令接收确认重试，处理驱动器忙碌
时可能既不回显也不执行下一条指令的现象。本项目只采用该实机结论和算法原则，
不复制旧项目的窗口、扫描线程、请求执行器或串口框架。

## 2. 目标与非目标

### 2.1 目标

1. 保持现有矩形蛇形路径、X/Y步数、步时、扫描次数和每轮返回语义。
2. 扫描区域内部根据可信位置样本预测末端交接，避免等待驱动器停止状态恢复。
3. 当前`ScanController`继续作为电机和光谱仪的唯一总控。
4. 光谱仪在每轮扫描区域运动期间持续采集，轮末严格确认运动与位置后才停止保存。
5. 使用绝对目标和接收确认重试，避免重复相对运动造成距离叠加。
6. 保留限位、方向、位置、急停、断线、安全锁和最终位置校验。
7. 未连接光谱仪时使用完全相同的电机扫描路径，只跳过采集与保存。

### 2.2 非目标

1. 不移植旧项目的Tk/Qt界面、线程、串口队列或完整扫描执行器。
2. 不修改普通光谱仪采集、存储、处理或绘图内部逻辑。
3. 不改变手动运动、软件回零、机械回零或脱离卡死的严格完成判定。
4. 不在驱动器中排队多条轨迹；任一时刻串口仍只有一个待响应Modbus事务。
5. 不增加用户可调的预测阈值、超时或安全余量。
6. 不声称预测交接等同于驱动器停止回读；无响应窗口内只能通过可信样本、保守余量、
   下一轴接收确认和轮末严格校验降低风险。

## 3. 方案选择

### 3.1 继续严格等待停止状态

安全语义最强，但`003.zip`已经证明驱动器的状态无响应会直接转化为不一致停顿，
无法达到连续扫描目标。

### 3.2 完全按设置速度定时

通信最少，但没有实际位置样本时无法及时发现卡滞、提前停止或速度偏差，风险过高。

### 3.3 在当前架构中融合预测交接（采用）

保留当前Qt异步串口和光谱仪状态机，新增纯计算估算器和扫描专用绝对运动阶段。
运动中期继续读取当前轴；进入末端窗口后根据可信样本预测交接。下一条指令经过
目标轴状态确认后才决定是否重发；每轮最后严格校验两轴位置，再停止光谱仪。

## 4. 架构与组件边界

### 4.1 `ScanController`

继续负责：

- 每轮启动一次光谱仪连续采集并等待真实启动事件；
- 按扫描计划提交电机段、步时和进度；
- 扫描区域结束后等待电机轮末严格校验；
- 停止光谱仪并等待保存完成；
- 严格返回本轮起点，再开始下一轮；
- 统一处理用户停止、电机故障和光谱仪故障。

它不计算串口时机，也不解析驱动器寄存器。

### 4.2 `MotorController`

新增扫描专用能力，负责：

- 冻结扫描起点原始脉冲、两轴速度和方向映射；
- 将扫描计划的累计逻辑位移转换为驱动器绝对目标；
- 发送扫描绝对位置命令并执行接收确认；
- 读取当前轴运行状态，向估算器提交可信位置样本；
- 对非最终扫描段产生“可交接”结果；
- 对最终扫描段和返回段执行严格停止与位置确认；
- 暂存本轮每轴计划目标，用于轮末双轴校验；
- 沿用现有急停、断线和安全锁路径。

扫描活动期间，手动运动和参数写入继续被锁定。

### 4.3 末端交接估算器

新增独立纯计算模块`scan_timing.py`。它不依赖Qt、串口、光谱仪或界面，只接收：

- 起点和目标脉冲；
- 指令发送单调时间；
- 当前轴配置位置速度；
- 成功读取的位置与单调时间样本。

它返回末端范围、有效速度和预测交接截止时间，便于使用虚拟时钟完整测试。

### 4.4 协议层

在现有`lk_md2202.py`增加绝对位置请求构造，使用轴基址`+0x12`的两个32位寄存器。
现有Modbus帧构造、CRC、严格响应校验和单事务队列保持不变。

## 5. 每轮数据流

```text
PRECHECK
  -> 冻结电机原始起点/速度/方向/扫描计划
  -> 有光谱仪：启动连续采集并等待task_started
  -> 无光谱仪：直接进入扫描
  -> 扫描区域运动
       -> 普通相邻段：预测交接 + 下一段接收确认
       -> 步时：在预测完成后执行，采集持续
       -> 最后一段：严格停止 + X/Y轮末位置校验
  -> 有光谱仪：停止采集并等待保存完成
  -> X/Y严格绝对返回本轮原始起点
  -> 下一轮或完成
```

光谱仪不会在换轴、子步、预测等待或步时期间停止。轮末位置校验期间也继续采集，
避免最后一段尚未完全结束时提前截断数据。

## 6. 坐标与绝对目标

每轮开始读取并冻结X/Y驱动器当前累计脉冲`raw_start`。扫描计划仍使用现有逻辑
距离；每段累计逻辑位移转换为：

```text
device_target = raw_start + direction_mapping(logical_cumulative_delta)
```

规则如下：

1. 已校准时继续执行0～4800 pulse软件行程检查。
2. 未校准时沿用当前风险确认，不把本轮逻辑0误写成驱动器绝对0。
3. 方向反转只作用于逻辑位移到驱动器位移的映射。
4. X/Y分步使用累计比例计算绝对目标，最后一步强制等于整段目标，不积累舍入误差。
5. 同一段重试始终写入相同绝对目标，不能改成重复相对位移。
6. 每轮返回目标是冻结的`raw_start`，不依赖扫描中软件坐标增量。

## 7. 指令接收确认

扫描绝对位置写入使用约60 ms响应期限且不由传输层自动重发。整个段的接收确认
期限为1秒：

1. 收到合法`0x10`回显：指令已接收，进入运动跟踪。
2. 写回显超时：读取目标轴状态，不能立即重发。
3. 目标轴已按正确方向运动、位置已朝目标变化或已经到位：指令已执行，仅回显丢失，
   不重发。
4. 目标轴停止在本段起点：确认未执行，立即重发同一绝对目标，不增加固定等待。
5. 状态仍无响应：继续独立读取，不能在无法判断是否执行时重发。
6. 限位、反向运动、越过目标、异常中间停止、明确Modbus异常或协议错误：立即故障。
7. 1秒内仍不能确认接收：故障并进入现有停止流程。

接收确认成功只证明目标轴开始执行，不代表该段已经完成。

## 8. 末端预测交接

扫描状态查询使用约150 ms单次期限、不在事务内部重试；驱动器明确报告运动中时，
约40 ms后发起下一次当前轴查询。

默认内部参数：

- 近终点范围：160 pulse（0.5 mm）；
- 终点超时范围：320 pulse（1 mm）；
- 安全余量：80 ms；
- 最短段期限：200 ms。

计算规则：

1. 至少取得一个可信的“朝目标运动”位置样本后，才允许预测交接。
2. 有最近两次有效样本时计算实测速度；无第二个样本时使用配置位置速度。
3. 有效速度不高于配置位置速度，避免按过高瞬时速度提前交接。
4. `remaining_time = abs(target-last_position) / effective_speed`。
5. 样本交接时刻为`last_sample_time + remaining_time + 80 ms`。
6. 最终交接时刻不早于指令发送后200 ms，也不早于当前计算时刻。
7. 位置进入160 pulse范围时停止等待旧轴的停止回复，等待预测时刻。
8. 最近位置不超过320 pulse后查询超时，进入相同预测阶段。
9. 查询超时时若可信样本推算的交接时刻已经到达，也进入预测阶段，避免采样直接
   跨过160/320 pulse窗口。
10. 没有任何可信运动样本时不得纯定时交接，退回严格停止确认。
11. 驱动器在预测前已经返回“停止且到位”时立即完成，不额外添加80 ms。

预测时刻到达后，当前段对扫描总控报告“可交接”，并进入用户设置的步时；步时为0
时立即开始下一段接收确认。预测过程不主动安排重叠，下一段能否真正启动仍由驱动器
接收窗口和接收确认状态机决定。

## 9. 最终段、返回与光谱仪边界

1. 每轮扫描区域最后一段不以预测结果作为完成。
2. 最后一段必须读到停止且目标位置误差不超过±1 pulse。
3. 随后在最多2秒内严格读取X/Y，确认均等于本轮计划最终目标±1 pulse。
4. 只有双轴校验成功，`ScanController`才停止光谱仪并进入保存。
5. 保存成功后，X/Y按现有顺序使用绝对目标严格返回`raw_start`。
6. 返回不使用预测交接，不要求视觉连续性。
7. 返回失败不会开始下一轮，且不会自动执行额外回零。

## 10. 停止、故障与恢复

- 用户停止：取消预测计时、步时、接收确认和待发扫描命令；急停两轴并停止光谱仪。
- 电机限位、反向、越界、异常位置或接收确认超时：中止本轮，停止两轴和光谱仪。
- 光谱仪启动、采集或保存失败：停止电机，不发送下一扫描段。
- 电机串口断开或停止状态未知：沿用现有安全锁和切断驱动板电源提示。
- 预测期间暂停不是本轮需求；现有界面没有扫描暂停按钮，不新增隐藏状态。
- 故障后不自动返回、回零或清除故障，防止在坐标不可信时继续运动。
- 重新连接不会自动恢复中断扫描，由用户检查机械状态后重新开始。

## 11. 诊断

继续写入现有诊断时间线并随诊断包导出，不生成独立日志文件。每段记录一条结构化
摘要，包含：

- 扫描ID、轮次、段号、轴、逻辑起点/目标和驱动器绝对起点/目标；
- 设置速度、运动写尝试次数、正常回显或状态确认结果；
- 有效样本数、最后位置、有效速度、剩余脉冲；
- 完成方式：严格停止、预测交接或无可信样本降级；
- 预测原因、预测等待、安全余量和总耗时；
- 状态查询次数、失败次数以及最终结果。

高频位置样本只在内存中维护最近两个并累计计数，不逐条写日志。轮级事件继续记录
光谱仪启动、最终位置校验、停止保存、返回和最终状态。

## 12. 界面

不新增预测参数或高级设置。现有扫描参数、按钮和状态显示保持不变。诊断信息只在
诊断页和导出包中体现；正常完成时不弹出额外确认框。发生接收超时、位置异常或最终
校验失败时显示明确的轴、目标和实际位置。

## 13. 自动测试

### 13.1 纯计算

- 正反方向、配置速度上限、两样本实测速度和单样本配置速度；
- 160/320 pulse阈值、80 ms余量和200 ms最短段期限；
- 超时跨过末端窗口和无可信样本禁止预测；
- 非递增时间、反向样本和无效速度拒绝。

### 13.2 电机控制器

- 绝对请求寄存器、32位编码、方向反转和未校准原始起点；
- 正常写回显、回显丢失但已执行、确认未执行后安全重发；
- 无法判断时不重发、1秒截止、限位、反向、越界和异常停止；
- 预测段、严格最终段、双轴最终校验和严格返回；
- 用户停止、断线、安全锁及手动操作不使用预测。

### 13.3 扫描与光谱仪

- 每轮只启动一次连续采集；
- 相邻预测段、分步和步时期间不停止采集；
- 轮末双轴校验前不停止光谱仪；
- 保存完成前不返回，返回完成前不开始下一轮；
- 电机、光谱仪、用户停止和无光谱仪模式的全部终态；
- 原蛇形`n+1`次X、`n`次Y、分步总脉冲和每轮返回不变。

最终执行电机定向测试、完整PyQt6回归、源码编译、部署镜像一致性和部署结构测试。

## 14. ROCK 4B+ 实机验收

1. 安装前备份所有替换文件并记录SHA-256，保留当前`c216da2`版本回退能力。
2. 先断开光谱仪，以安全小行程、步时0执行一次纯电机扫描。
3. 相同参数连续执行至少10次，确认无重复距离、反向、越界或明显两轴重叠。
4. 对比诊断摘要：预测交接的软件调度延迟应稳定，读取失败不再直接增加完整超时阶梯。
5. 验证X/Y分步、非零步时、用户停止、限位和断线。
6. 连接光谱仪执行单轮和多轮联动，确认持续采集、轮末停止保存、严格返回和文件完整。
7. 若仍有明显停顿，使用段摘要区分预测等待、下一指令接收确认和驱动器实际拒绝窗口。

## 15. 回退与保证边界

部署只替换本设计实际修改的运行文件，安装前逐文件备份。回退恢复这些文件，不删除
设置、数据、虚拟环境、诊断包或原光谱仪软件。

上位机可以保证：不盲目重复结果未知的相对运动、维持单事务串口、保留急停与限位、
轮末严格校验、在确认光谱仪保存后再返回。上位机不能在驱动器停止状态不响应期间
取得硬件级停止证明，也不能恢复驱动器未执行或机械已经丢步的运动；这些情况通过
接收确认、最终位置校验、故障停止和实机验收暴露，不用长等待掩盖。
