# ROCK 4B+ 电机独立进程与扫描延期导出设计

- 日期：2026-08-18
- 状态：方案已口头确认，等待书面规格复核
- 依据：ROCK 4B+ 实机诊断包 `006.zip` 及前序 `004.zip`、`005.zip`
- 范围：LK-MD2202 电机执行进程、扫描轮次调度、扫描专用光谱封存与延期导出

## 1. 目标与不变约束

本轮目标是让电机扫描的物理执行不再受 GUI 绘图、光谱显示、采集事件和文件导出
调度影响，同时继续保证每一帧光谱数据的完整持久化。

必须保持：

1. 矩形蛇形路径、`n+1` 次 X 行程、`n` 次 Y 行程、扫描次数和轮末返回不变；
2. 步时为 0 时沿用已实现的同一完整行程合并，步时大于 0 时严格保留全部子步和等待；
3. 15 mm 行程、4800 pulse、零点限位、急停、故障锁定、轮末严格终点校验和返回校验不降低；
4. 未连接光谱仪时仍可执行纯电机扫描；
5. 普通单机采集、总控采集、背景/参考、显示、处理和手动保存逻辑不变；
6. 光谱仪采集进程继续独占光谱仪串口，电机进程独占 LK-MD2202 串口；
7. 不以丢帧、降低协议校验、隐藏固定等待或关闭实时显示换取流畅；
8. 诊断继续写入现有飞行记录器并按需导出 ZIP，不新增独立扫描日志文件；
9. 原光谱仪程序、用户数据、设置、虚拟环境和既有备份不被删除或覆盖。

## 2. 已确认的实机证据

`006.zip` 中，相同扫描参数下：

- 五轮纯电机运动约为 `8.214–8.609 s/轮`；
- 五轮光谱联动运动约为 `9.577–10.549 s/轮`；
- 联动扫描主进程 CPU 中位值约 83%，纯电机约 63–66%；
- 联动中仍有 8 次预测交接未命中后转为严格完成观察，纯电机为 0 次；
- 控制器一旦确认一段完成，下一段在约 1.3–1.9 ms 内发起，因此主要抖动发生在
  完成识别和主进程状态机获得运行机会之前；
- 五轮光谱数据均满足完整帧数等于持久化帧数，缺失、无效和重新同步均为 0；
- 每轮电机终点严格校验后，正式 CSV/Excel 导出又占用约 12–14.5 s，下一轮返回和
  运动必须等待 `task_finished`，这不是机械运动必需等待。

结论：光谱数据主通道正确，但电机控制状态机仍部分位于 GUI 进程，并且正式导出仍
位于轮次关键路径。两项必须分开修复。

## 3. 方案比较与选择

### 3.1 方案 A：再增加一个 QThread

把 `MotorController` 移到新的 QThread，改动相对少，但 Python 状态机仍与 GUI、绘图
和采集代理共享同一解释器与 GIL。它能改善 Qt 事件归属，却不能可靠隔离联动时的
Python 调度竞争，因此不采用。

### 3.2 方案 B：电机独立进程 + 扫描延期导出（采用）

由独立电机进程拥有串口、Modbus 事务、状态轮询、预测交接、子步等待和整条扫描路径
调度；GUI 只发送冻结后的高层命令并接收摘要事件。每轮光谱采集停止后先封存并核对
轻量 `.zgs`，立即允许电机返回和进入下一轮；全部运动完成后再顺序生成正式 CSV/Excel。

该方案同时隔离 GIL/GUI 负载，并从运动关键路径移除大型导出，且不改变光谱全量落盘
方式，因此采用。

### 3.3 方案 C：电机和光谱仪放入同一个硬件总控进程

它可以在一个进程内统一调度，但会让两种串口、两套故障恢复和高吞吐光谱落盘相互
耦合。任一设备异常都可能扩大到另一设备，回归风险最高，因此不采用。

## 4. 目标进程边界

```text
GUI 主进程
  ├─ PyQt6 界面、绘图和用户输入
  ├─ ScanController：只负责轮次级编排
  ├─ MotorProcessProxy：电机进程代理和只读状态镜像
  ├─ AcquisitionController：采集任务与封存/导出编排
  └─ 诊断、清单和状态显示

电机子进程（单实例）
  ├─ MotorController 核心状态机
  ├─ MotorScanRunner：整条扫描/返回路径的连续调度
  ├─ Modbus 请求、响应、超时、预测和严格校验
  └─ QSerialPort：独占 LK-MD2202 串口

现有光谱采集子进程（每台光谱仪）
  ├─ QSerialPort：独占光谱仪串口
  ├─ 完整解析和顺序追加 `.zgs`
  └─ 容量 1 的最新显示旁路

现有导出工作进程
  └─ 全部运动结束后读取已封存 `.zgs`，生成并核对 CSV/Excel
```

任何时刻一个串口只能由一个进程持有。GUI 不直接打开电机或光谱仪串口。

## 5. 电机进程设计

### 5.1 生命周期和资源所有权

新增 `MotorProcessProxy` 作为 GUI 侧门面，使用 `multiprocessing` 的 `spawn` 上下文启动
电机子进程，避免在已有 Qt 进程中 `fork`。子进程创建 `QCoreApplication`，并在同一
事件循环中运行电机控制器和不另开线程的 `MotorSerialTransport`；串口对象、响应解析、
事务超时和运动定时器全部属于该进程。

代理保持现有界面需要的信号和只读属性，包括连接、候选端口、状态、配置、速度设置、
运动开始/完成、故障、轮次准备和轮次校验。连接、手动运动、机械回零、脱离卡死、
清故障和参数设置均通过 IPC 发送到子进程，不能在 GUI 侧保留第二套硬件控制状态。

ROCK 4B+ 正式运行若电机进程无法启动或异常退出，软件必须显示断开/故障并停止当前
扫描，不能静默退回 GUI 进程内执行。测试和显式仿真可继续注入现有直接控制器。

### 5.2 整条路径在子进程内连续执行

GUI 为每轮发送不可变的路径快照，包含：

- `scan_id`、轮次、路径类型（扫描或返回）；
- 每段轴、方向、脉冲、逻辑子步数和配置步时；
- 最终段、返回段和严格校验标记；
- 本轮已锁定的起点与预期终点。

`MotorScanRunner` 在子进程内逐段调用现有安全运动接口。上一段完成后，下一段直接在
同一子进程事件循环中发起；步时大于 0 时，等待定时器也位于子进程。GUI 是否正在
绘图或处理光谱事件，只能影响进度文字显示的时刻，不能影响下一条电机命令的发起。

扫描路径结束后，子进程执行现有双轴严格终点校验，再向 GUI 发送
`scan_round_verified`。返回路径也在子进程内连续执行并保持严格完成语义。

### 5.3 IPC 和背压

- 控制命令使用双向 Pipe，命令具有单调序号和请求 ID；
- 关键结果使用有界事件队列，状态快照合并为最新值，不能无限积压；
- 段开始/结束、限位、故障、急停和进程退出属于关键事件，不允许静默丢弃；
- 高频状态只按既有轮询节奏发布摘要，不跨进程发送原始 Modbus 字节流；
- 关键事件队列无法投递时，子进程受控停止当前运动并关闭串口，不能在失去主进程
  监管后继续扫描；
- 代理持续监测子进程存活，异常退出时立即镜像为断开并触发扫描故障。

急停命令进入子进程后清空扫描路径并调用现有两轴停止流程。机械零点限位仍由驱动板
直接参与停止，上位机进程隔离不替代硬件限位。

## 6. 扫描专用封存与延期导出

普通采集的结束和保存语义不变。只有 `AcquisitionOwner.SCAN` 且启用自动保存的任务
使用以下流程：

1. 本轮电机路径和双轴严格终点校验完成；
2. 停止光谱采集，接收尾帧，封存各设备 `.zgs`；
3. 核对 `raw_complete_frames == persisted_frames`，冻结设备元数据、波长、处理快照、
   文件命名和预期帧数，形成不可变导出上下文；
4. 释放本轮光谱仪任务占用，发出 `scan_capture_sealed`，但不启动 CSV/Excel 导出；
5. 电机返回起点并开始下一轮，已封存文件保持只读等待；
6. 最后一轮返回完成后进入新增的 `EXPORTING` 状态；
7. 按轮次顺序、单任务并发度 1 提交正式导出，避免同时启动多个 Excel 进程造成内存
   和 CPU 峰值；
8. 每轮成功后把最终文件写入扫描清单并清理对应封存源；全部成功后扫描才报告完成。

选择单任务顺序导出，是因为运动已经结束，继续追求导出并发收益有限，而 ROCK 4B+
内存和温度风险更重要。导出仍在后台工作进程，GUI 不同步生成文件。

扫描状态含义调整为：

```text
SCANNING
→ STOPPING_ACQUISITION（停止、尾帧、封存、完整性核对）
→ RETURNING
→ 下一轮或 EXPORTING
→ COMPLETED / FAULTED
```

`task_finished` 继续表示最终文件导出完成；新增的扫描封存信号只用于解除本轮设备占用
和驱动电机返回。扫描清单在封存时记录采集 ID、帧数和恢复文件，在正式导出后补写
最终文件，最后一次导出结束前不把清单标记为完成。

## 7. 故障、停止和退出

### 7.1 电机或 IPC 故障

- 电机进程故障、串口断开、协议错误、限位异常或严格终点失败时，立即停止路径；
- 若光谱仍在采集，按现有顺序停止、接收尾帧并封存；
- 不自动返回，也不开始下一轮；
- 已封存数据保留并在电机安全停止后尝试正式导出，失败时保留恢复文件。

### 7.2 光谱封存或完整性失败

封存失败或完整帧数与持久化帧数不相等时，本轮扫描失败，电机不自动返回，恢复文件
保留并报告精确路径。不得为继续扫描而忽略计数不一致。

### 7.3 正式导出失败

正式导出发生在全部运动和返回完成后。任一轮导出失败时，电机保持在已验证的返回
位置，扫描最终状态为故障并明确显示“运动已完成，数据导出失败”；成功文件不删除，
失败轮次的 `.zgs` 保留供恢复。

### 7.4 用户停止与应用退出

用户停止时立即停止电机且不自动返回、不开始下一轮；若光谱任务已启动，则停止并
封存已收到数据，随后在电机安全停止后完成或保留其导出。关闭应用时先禁止新操作，
再请求电机进程停止、停止采集、封存尾部数据并有界等待；超时只能保留恢复文件并
报告，不能删除未完成数据。电机进程停止失败时才允许在记录故障后强制终止。

## 8. 界面和诊断

界面不增加复杂参数。现有状态文字调整为：

- `STOPPING_ACQUISITION`：正在停止光谱仪并封存本轮数据；
- `RETURNING`：本轮数据已安全封存，电机正在返回；
- `EXPORTING`：全部运动已完成，正在生成并核对正式文件；
- 导出故障：运动已完成，恢复数据已保留。

现有诊断时间线增加：

- 电机进程启动、PID、退出和异常；
- IPC 命令序号、队列压力和丢弃的非关键摘要计数；
- 子进程内每段调度、开始、完成和下一段发起的单调时间；
- 光谱封存开始/完成、完整帧/持久化帧；
- 导出延期、真正开始、完成和失败；
- 扫描 ID、轮次和采集 ID 的既有关联。

诊断包仍不默认包含完整光谱数据，只包含时间线、指标、配置、摘要和校验和。

更新前逐文件备份并记录 SHA-256。依次验证：

1. 手动正反转、速度、参数设置、机械回零、脱离卡死、限位、急停和断线恢复；
2. 五轮纯电机扫描：`X步数=10, 步时=0`；

4. 10 ms 积分时间下五轮光谱联动扫描；
5. 联动时子进程内“上一段完成到下一段发起”P95 不超过 20 ms、最大值不超过
   50 ms，配置步时和轮末严格校验不计入；
6. 联动运动时长中位值相对纯电机同参数不增加超过 10%，如未达标必须用诊断事件
   说明是驱动器响应、机械运动还是调度造成；
7. 时间线证明全部电机运动结束前没有启动正式 CSV/Excel 导出；
8. 每轮满足 `完整帧 == 持久化帧 == 最终导出帧`，缺失、无效和重新同步均为 0；
9. 用户停止、限位、急停、电机拔插、光谱仪拔插和一次导出失败恢复均有明确结果；
10. 连续运行期间队列、内存和日志无无界增长，退出后无遗留电机进程。

Linux 是非实时系统，上述指标用于验收本软件调度隔离，不承诺 LK-MD2202 内部响应、
USB-RS485 转换器或机械负载绝对无抖动。
