# PySide6 串口通信与设备握手识别修复设计

日期：2026-07-22

## 1. 问题

在项目专用 Python 3.13 + PySide6 6.11 环境运行时，串口能够打开，但上位机无法发送初始化、查询和采集命令。实测异常为 `Q_ARG(bytes, ...)` 在 PySide6 中没有对应 Qt 元类型。界面因此把“串口打开”显示成“设备已连接”，但没有下位机信息，也收不到光谱数据。

COM10 与三台光谱仪使用相同 USB 串口 VID/PID，单靠端口描述和 VID/PID 无法区分，导致自动扫描误连接。

## 2. 目标

- PySide6 和 PyQt5 均能通过串口工作线程发送命令。
- 自动扫描时，只有返回合法 `0x01` 版本帧的端口才成为可采集光谱仪。
- COM10 等仅能打开、但不响应光谱仪协议的串口在握手超时后自动关闭并从设备列表移除。
- 采集开始按钮只使用已完成握手和初始化的设备。
- 保持现有协议双格式解析、校准系数、存储格式和硬同步逻辑不变。

## 3. 方案

### 3.1 Qt 跨线程数据类型

将 `DeviceManager` 到 `SerialWorker` 的写入调用从 Python `bytes` 元类型改为 Qt 原生 `QByteArray`：

- 调用方使用 `QtCore.QByteArray(packet)`；
- `QMetaObject.invokeMethod` 使用 `Q_ARG(QtCore.QByteArray, ...)`；
- 工作线程槽声明为 `Slot(QtCore.QByteArray)`，进入协议层前转换成 `bytes`。

整数像素信息仍使用现有 `Q_ARG(int, ...)`。

### 3.2 协议握手

端口打开后进入“识别中”状态，而不是立即视为正式光谱仪：

1. 发送初始化和 `0x01` 版本查询；
2. 收到字段长度和像素范围合法的版本响应后，将设备标记为 `initialized=True`；
3. 随后继续读取校准、生产序列号和运行参数；
4. 在限定时间内未收到合法版本响应，则记录“未通过光谱仪握手”，关闭端口并移除候选设备；
5. 周期扫描允许以后重新检测该端口。

握手成功前设备卡显示“识别中”，不能参与采集或批量存储；成功后显示“已连接”。

### 3.3 状态与错误处理

- “串口打开”与“光谱仪已识别”分开表达。
- 初始化完成状态只统计 `connected && initialized` 的设备。
- 点击开始时过滤未初始化设备；没有已识别设备时给出明确提示。
- 无响应候选端口属于正常探测结果，写入诊断日志，不弹出阻塞对话框。
- 真正的串口打开失败、协议损坏和已识别设备断线仍按现有错误/重连流程处理。

## 4. 测试

- 单元测试：PySide6 可构造并排队 `QByteArray` 写入；未初始化设备不参与采集。
- 自动识别测试：无版本响应的候选设备在超时后移除，合法版本响应保留。
- 回归测试：现有协议、序号、处理、存储和界面测试全部通过。
- 实机测试：在 `.venv` 的 PySide6 环境自动扫描 COM10/COM14/COM17/COM18，确认 COM10 被忽略，三台光谱仪显示序列号与像素信息，并完成连续采集和 CSV/Excel 导出。

## 5. 非目标

- 不使用固定 COM 白名单代替自动检测。
- 不修改下位机固件、波长校准系数或数据帧格式。
- 不根据 COM 号硬编码设备身份。
