# ROCK 4B+ 光谱仪诊断飞行记录器设计

## 1. 目标

为 Linux 专用光谱仪软件增加低开销的“诊断飞行记录器”和一键诊断包导出功能。问题发生后，即使采集已经停止或程序曾异常退出，也能还原设备通信、数据解析、全量持久化、界面显示和系统负载的时间关系。

该功能必须满足：

- 不阻塞串口接收、帧解析、全量缓存写入或界面线程。
- 默认不复制或导出完整光谱数据。
- 能区分下位机未发送、USB/串口异常、解析拒帧、持久化受阻和单纯显示卡顿。
- 仅清理诊断记录，不得删除或修改 `.zgs`、`.part`、CSV、Excel 或其他用户数据。
- Windows 与 Linux 版本继续分开维护；本设计只应用于 Linux 转移版及其 `deploy/rock4bplus` 副本。

## 2. 用户体验

诊断页增加：

- “导出诊断包”按钮。
- “包含最近 10 个完整原始帧”复选框，默认不勾选。
- 导出状态提示，包括正在生成、生成成功、失败原因和最终 ZIP 路径。

程序启动后自动记录轻量诊断，无需用户提前开启。按钮默认导出最近一次采集会话；采集进行中也允许导出当前一致性快照，不暂停采集。

若没有采集会话，则导出当前运行会话及设备连接、握手和系统信息，并在清单中标明“无采集会话”。

## 3. 总体架构

新增四个边界清晰的组件：

### 3.1 `DiagnosticRecorder`

位于主程序进程，接收结构化诊断事件并写入 JSON Lines。它不直接读取串口，不参与帧解析，也不处理光谱数据。

公开能力：

- 建立和结束运行会话、采集会话。
- 接收事件、性能样本、设备快照和采集计数。
- 保存帧摘要与可选的最近原始帧环形缓存。
- 提供当前/最近会话的只读快照描述。

### 3.2 `SystemSampler`

每秒采样一次 Linux 系统与进程状态：

- 主程序和采集子进程 CPU 时间、常驻内存、线程数和存活状态。
- 系统负载、总内存和可用内存。
- ROCK 4B+ 温度。
- 数据目录与诊断目录剩余磁盘空间。

数据来自 `/proc`、`/sys` 和 Python 标准库，不执行 `sudo`，不依赖 `top`、`pidstat` 或其他新增系统软件。读取不到的字段记录为 `null`，不得导致采集失败。

### 3.3 `DiagnosticRetention`

在程序启动和诊断会话结束后执行清理：

- 保留最近 7 天。
- 诊断目录总容量不超过 200 MB。
- 先按时间删除过期会话，再删除最旧会话直至满足容量限制。
- 只允许删除诊断根目录下经过校验的会话目录和临时诊断包。

### 3.4 `DiagnosticBundleExporter`

从已封闭文件和内存快照生成 ZIP。导出在独立工作线程执行，先生成 `.tmp`，完整写入并校验后原子改名为 `.zip`。

导出期间记录器继续追加新文件；导出器只读取开始导出时确定的字节边界，保证包内文件是一致前缀，不长时间锁住记录器。

## 4. 数据流与非阻塞保证

主线程和采集代理只将小型结构化对象放入有界诊断队列。专用低优先级写入线程消费队列并追加 JSON Lines。

事件分为两级：

- 关键事件：采集开始/停止、设备连接/断开、ACK 超时、解析重同步、缺帧、持久化失败、封存结果和受控停止原因。关键事件在队列中保留独立记录。
- 可合并样本：每秒性能与累计计数。队列压力较大时，只保留同类最新样本并增加 `coalesced_samples` 计数。

诊断队列不得反向阻塞生产者。若关键事件也无法入队，则增加内存中的 `dropped_diagnostic_events`，下一次成功写入时记录丢弃数量并在诊断页警告。该丢弃只影响诊断完整度，不影响采集数据。

光谱数据的主路径保持不变：

```text
串口 -> 完整帧解析 -> .zgs/.part 全量持久化 -> 显示限帧
```

诊断记录只旁路观察该路径：

```text
采集计数/事件 -> 有界诊断队列 -> 诊断写入线程
```

## 5. 会话与目录结构

诊断根目录使用现有平台状态目录：

```text
~/.local/state/ZGCAI/Spectrometer/diagnostics/
```

每次运行建立一个目录，每次采集使用唯一 `acquisition_id` 分段：

```text
diagnostics/
  run-20260729T153012-<id>/
    manifest.json
    timeline.jsonl
    performance.jsonl
    application.log
    frame-summaries.jsonl
    recent-frames/
```

所有 JSON/JSONL 文件使用 UTF-8、稳定字段名和显式格式版本。时间同时记录：

- ISO 8601 本地时间和时区。
- `monotonic_ns` 单调时钟，用于准确计算事件间隔。

应用正常退出时更新 `manifest.json` 的结束时间与完整性状态；异常退出留下 `status=incomplete`，下次启动仍可导出。

## 6. 记录内容

### 6.1 程序和系统

- 程序版本、Git 提交号、Python、Qt、PyQt、NumPy 和操作系统版本。
- ARM64 架构、主机名、显示会话类型和屏幕尺寸。
- 主程序及采集子进程性能时间序列。
- 系统负载、内存、温度和磁盘空间。
- `startup.log` 在会话时间范围内的内容或末尾受限片段。

不记录环境变量全集、SSH 密钥、用户密码或无关目录列表。

### 6.2 设备和参数

- 端口名、VID:PID、生产序列号。
- 固件/硬件版本。
- 总像素、起始像素、有效像素。
- 积分时间、采集间隔、触发模式及其他实际发送的采集参数。
- 协议变体：`legacy_u16` 或 `u32`。

### 6.3 采集时间线

- 自动识别、打开串口、握手、参数读取。
- 采集配置、开始、停止命令及 ACK 结果。
- 每秒累计值和增量值：
  - 完整帧；
  - 已持久化帧；
  - 显示帧；
  - 显示覆盖；
  - 缺帧；
  - 拒绝候选帧；
  - 重同步；
  - 诊断事件合并/丢弃；
  - 队列深度或最新可用压力指标。
- `.part`/`.zgs` 路径、封存状态、文件大小和帧数一致性。
- 自动停止阈值及触发原因。
- CSV/Excel 导出开始、完成、文件数量和错误。

## 7. 光谱帧隐私与样本

默认诊断包不包含完整像素强度，只记录首段、中段和末段抽样帧摘要：

- 包序号、协议格式、原始帧长度。
- 总像素、起始像素、有效像素。
- 最小值、最大值、均值、标准差。
- 原始像素字节的 SHA-256。

“中段”在采集进行中按固定周期更新代表样本；停止时保留最终中段代表值。摘要不能用于恢复完整光谱。

记录器始终只在易失内存中维护容量固定为 10 的原始帧环形缓存，因此用户可在采集停止后再决定是否附带样本。默认导出不读取、不写出该缓存；只有用户勾选“包含最近 10 个完整原始帧”时，导出器才将仍在内存中的帧复制进包内：

- `recent-frames/frames.npy`：原始传感器像素，保留大端 U16 的数值语义。
- `recent-frames/metadata.json`：每帧序号、时间、总/起始/有效像素和协议格式。

该选项不创建第二份连续全量采集文件，也不影响 `.zgs` 的权威地位。
若程序已经退出或异常崩溃，易失缓存不再可用，诊断包会明确标记原始帧样本不可用，而不会从完整 `.zgs` 中隐式提取数据。

## 8. ZIP 内容与清单

ZIP 至少包含：

- `bundle-manifest.json`：包格式版本、生成时间、会话范围、包含/缺失项目、校验结果。
- `system.json`：静态系统和依赖版本。
- `device.json`：设备身份和参数快照。
- `acquisition-summary.json`：采集总计、速率、异常比例、停止与封存结果。
- `timeline.jsonl`：结构化事件。
- `performance.jsonl`：每秒系统和进程样本。
- `diagnostics.txt`：便于人工阅读的诊断文本。
- `frame-summaries.jsonl`：默认帧摘要。
- `startup-log-tail.txt`：受限长度的启动日志。
- 可选 `recent-frames/`。

清单记录每个成员的大小和 SHA-256，导出器在原子改名前重新读取 ZIP 并验证成员可读。

## 9. 错误处理

- 诊断目录不可写：界面显示一次明确警告，采集继续。
- 系统指标读取失败：对应字段为 `null`，时间线记录一次降级原因。
- 导出目标不可写或空间不足：删除未完成的诊断 `.tmp`，保留原始诊断会话。
- 正在采集时导出：只导出快照边界之前的数据，并在清单标记 `live_snapshot=true`。
- 程序异常退出：保留未完成会话；下次启动可作为“最近一次采集”导出。
- ZIP 生成或校验失败：不得留下扩展名为 `.zip` 的不完整文件。

## 10. 性能预算

- 系统采样频率固定为 1 Hz。
- 常规诊断仅追加文本和小型 JSON，不调用 Excel 导出。
- 诊断写入不得执行每帧 `fsync`。
- 原始帧环形缓存最多 10 帧；3648/3694 像素设备占用远低于 1 MB。
- 持续记录的目标平均写入量小于 20 KB/s。
- 在模拟高帧率压力测试中，启用诊断前后全量持久化帧数必须一致。

## 11. 测试与验收

自动测试包括：

- 运行/采集会话边界和稳定格式版本。
- 单调时钟、累计值和增量值正确。
- 队列压力时性能样本合并且生产者不阻塞。
- 关键诊断丢弃能被计数和报告。
- 默认包不含完整光谱。
- 勾选后只包含最近 10 个完整原始帧及正确元数据。
- 正在采集时导出一致前缀快照。
- ZIP 清单、成员哈希和原子完成行为。
- 异常退出会话可在下次启动导出。
- 7 天与 200 MB 双重保留策略。
- 清理范围无法越过诊断根目录。
- 诊断目录不可写、指标缺失和磁盘不足的降级行为。
- 高帧率采集启用诊断前后，完整帧数与持久化帧数保持一致。
- ROCK 4B+ 部署副本与运行源码一致。

实机验收流程：

1. 不开启自动保存连续采集至少 2 分钟，期间导出一次实时快照。
2. 停止后导出最近一次采集，确认完整帧数等于持久化帧数。
3. 开启自动保存重复测试，确认 CSV/Excel 后台导出事件完整。
4. 人为拔出设备，确认断线、未完成会话和重连均进入诊断包。
5. 分别导出默认包和含 10 帧样本的包，确认内容及大小符合设计。

## 12. 非目标

本阶段不包括：

- 修改 MCU 协议或保证 MCU 未发送的数据。
- 上传诊断包到网络或云服务。
- 自动远程访问 ROCK 4B+。
- 在诊断包内复制完整 `.zgs`、CSV 或 Excel。
- 根据强度值自动删除或拒绝结构完整的光谱帧。
