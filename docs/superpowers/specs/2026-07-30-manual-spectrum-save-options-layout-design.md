# 选项布局与上一任务手动保存设计

## 1. 目标

在不改变现有采集默认值、自动批量存储格式、处理链和命名规则的前提下：

1. 将批量存储设置从左侧主界面移入“选项”；
2. 将采集方式保留在主界面，并放到上下文工具栏；
3. 新增“保存光谱”按钮；
4. 未启用自动批量存储时，保留刚刚正常结束的一次普通采集任务，供用户手动导出；
5. 未保存便开始下一次普通采集时，无提示清除上一任务缓存；
6. 收纳 Y 轴固定范围控件，为工具栏释放空间；
7. 继续保证采集主通道全帧优先、GUI 不被导出阻塞。

## 2. 范围与术语

### 2.1 “上一任务”

“上一任务”指一次普通采集从点击“开始”到完成“停止”之间的全部数据，不是
批量设置中的最后 500 帧。

如果一个任务包含多台设备，则待保存内容包含该任务的全部设备。

如果多个普通任务先后完成，只保留最近正常完成的那一个任务作为手动保存
候选。

### 2.2 普通采集

普通采集包括：

- 顶部总控启动的全局采集；
- 设备卡启动的单机采集。

背景和参考采集属于校准任务，不会覆盖或创建“上一任务待保存”状态。

### 2.3 不在本次范围内

- 不改变光谱仪通信协议；
- 不修改背景、参考、强度校准或 airPLS 算法；
- 不新增新的正式文件格式；
- 不把待保存光谱跨正常程序重启保留；
- 不修改原 Windows 项目；
- 不把设计文档、测试数据或技能放入 `deploy/rock4bplus`。

## 3. 已确认的界面设计

### 3.1 左侧设备栏

左侧栏标题从“设备与批量存储”改为“设备”。

左侧栏删除以下控件：

- 采集方式；
- 每批帧数；
- 存储格式；
- 采集时自动批量存储。

设备卡、设备选择、参与总控、积分时间、参数、开始/停止、背景和参考功能保持
不变。

### 3.2 上下文工具栏

文件与采集相关控件按以下顺序排列：

```text
打开文件 | 恢复缓存 | 保存光谱 | 保存图片 | 采集方式
```

“采集方式”仍提供：

- 连续采集；
- 单次采集。

启动默认仍为“连续采集”。本次不新增采集方式持久化，保持现有启动语义。

### 3.3 “保存光谱”按钮

按钮文本固定为“保存光谱”，位置严格位于“恢复缓存”右侧、“保存图片”左侧。

按钮状态：

| 状态 | 按钮表现 |
|---|---|
| 没有正常待保存任务 | 禁用，文本“保存光谱” |
| 有正常待保存任务且所有任务空闲 | 启用，文本“保存光谱” |
| 仍有采集、停止或收尾任务 | 禁用 |
| 正在手动导出 | 禁用，文本“保存中…” |
| 导出成功 | 禁用，恢复文本“保存光谱” |
| 导出失败且缓存仍完整 | 重新启用，恢复文本“保存光谱” |
| 被下一次普通采集覆盖 | 禁用，恢复文本“保存光谱” |

按钮提示应说明：

- 只保存最近一次正常完成且未自动存储的普通采集；
- 保存到“选项”中的数据目录；
- 新采集会覆盖未保存缓存。

### 3.4 系统选项

“系统选项”保留已有：

- 数据目录；
- 曲线宽度；
- 存储布局说明。

新增：

- 每批帧数：范围 1–1000，默认 500；
- 存储格式：
  - CSV + Excel；
  - 仅 CSV；
  - 仅 Excel；
- 采集时自动批量存储：每次程序启动默认未勾选。

持久化规则保持现有语义：

| 选项 | 默认值 | 是否保存用户修改 |
|---|---|---|
| 采集方式 | 连续采集 | 否 |
| 每批帧数 | 500 | 是 |
| 存储格式 | CSV + Excel | 是 |
| 自动批量存储 | 未勾选 | 否，每次启动强制关闭 |

系统选项只能在所有采集、停止、收尾和手动导出任务结束后修改。

### 3.5 Y 轴设置

从工具栏移除：

- 固定 Y 轴复选框；
- 最小值输入框；
- 最大值输入框；
- 应用 Y 轴按钮。

新增一个“Y 轴设置…”按钮。点击后打开模态对话框，包括：

- 固定 Y 轴复选框；
- 最小值；
- 最大值；
- 确定；
- 取消。

行为：

- 打开时显示当前界面状态；
- 取消不修改任何状态；
- 未勾选固定 Y 轴并确认时，解除固定范围；
- 勾选固定 Y 轴时，最大值必须严格大于最小值；
- 输入无效时保持对话框打开并显示错误；
- 确认后立即应用；
- 原有双击还原、框选放大和自动缩放联动保持不变；
- 本次不新增 Y 轴范围持久化。

## 4. 数据与状态设计

### 4.1 核心原则

手动保存不得建立第二条采集数据路径。继续使用现有独立采集进程和无损 spool：

```text
串口完整帧
→ 独立采集进程
→ 追加式 .part
→ 正常停止封存为 .zgs
→ 待手动保存
→ 现有后台 SealedSpoolExporter
→ CSV / Excel
```

GUI 只持有待保存任务的描述和文件路径，不在内存中保存整批光谱。

### 4.2 冻结导出上下文

普通采集开始时冻结以下信息：

- `AcquisitionRequest`：
  - 任务 ID；
  - 开始时间；
  - 设备集合；
  - 采集方式；
  - 同步方式；
  - 自动存储状态；
  - 存储格式；
  - 每批帧数；
- 每台设备的：
  - 端口；
  - 生产序列号；
  - 积分时间；
  - 触发模式；
  - 波长数组；
  - 文件命名标识；
- 每台设备的 `ProcessingSnapshot`：
  - 处理模式；
  - 自定义公式；
  - 背景；
  - 参考；
  - 强度校准及其 ID；
  - airPLS 参数。
- 采集开始时的数据输出目录。

点击“保存光谱”时只使用采集开始时冻结的信息。停止后修改系统选项、显示模式
或设备处理参数，不改变待保存任务。

### 4.3 待保存对象

新增一个边界清晰的待保存值对象，例如 `PendingManualCapture`。它只包含：

- 原始采集请求；
- 设备导出快照；
- 处理快照；
- 各设备封存路径；
- 各设备预期持久化帧数；
- 文件命名上下文。

它不得持有活动串口、Qt 控件或可变设备对象。

同一时刻只允许存在一个正常待保存对象。

### 4.4 正常停止

未勾选自动批量存储时：

1. 设备停止；
2. 等待尾帧静默；
3. 独立采集进程关闭 `.part` 并封存为 `.zgs`；
4. 核对每台设备：
   - 封存成功；
   - 完整帧数等于持久化帧数；
   - 持久化帧数大于 0；
5. 条件全部满足时登记为“待保存光谱”；
6. 释放采集控制状态；
7. 所有任务空闲后启用“保存光谱”。

正常停止不立即生成 CSV/Excel，因此不会把大文件导出放回 GUI 停止路径。

### 4.5 自动批量存储

勾选自动批量存储时保持现有流程：

1. 封存全量 spool；
2. 后台按冻结设置导出；
3. 成功后清理 spool；
4. 失败时保留恢复文件；
5. 不登记手动保存候选。

### 4.6 手动保存

点击“保存光谱”时：

1. 确认存在正常待保存对象；
2. 确认没有采集、停止、收尾或其他导出任务；
3. 将按钮切换为“保存中…”；
4. 直接保存到采集时冻结的数据目录；
5. 使用现有 `SealedSpoolExporter` 后台导出；
6. 导出成功后清理源 spool；
7. 清空待保存对象；
8. 记录生成文件和帧数；
9. 恢复按钮文本并禁用。

保存时不弹出目录或文件名窗口。

### 4.7 文件策略

保存格式、拆批和命名与现有自动存储一致：

- CSV + Excel：
  - 单设备任务生成 CSV；
  - 多设备任务生成一个 Excel；
- 仅 CSV：
  - 每台设备生成独立 CSV；
- 仅 Excel：
  - 生成 Excel；
- 每批帧数仍控制 B0001、B0002 等拆分；
- 每个文件仍为每帧一列、每像素一行；
- 中文标签、处理后数据和元数据不变；
- 发生重名时追加后缀，不覆盖已有文件。

## 5. 覆盖与清理生命周期

### 5.1 开始下一次普通采集

当用户启动下一次全局或单机普通采集时：

1. 如果存在上一任务待保存对象，先清理其全部 spool；
2. 清理成功后清空待保存对象；
3. 诊断页记录“上一任务未保存数据已被新采集覆盖”；
4. 再进入新任务配置和启动流程。

不弹出确认窗口。

如果任一旧缓存删除失败：

- 保留失败路径；
- 拒绝启动新普通采集；
- 在状态栏和诊断页显示原因及路径；
- 用户可重试“保存光谱”或处理文件权限后再次启动。

背景和参考任务不会触发覆盖。

### 5.2 新任务完成

新任务正常完成后成为唯一待保存任务。若并行单机任务使完成顺序与启动顺序
不同，以最近正常完成的普通任务为准。

替换旧待保存对象前必须先安全清理旧缓存；清理失败时，新任务缓存保留为恢复
文件并报告冲突，不能静默遗失任一份数据。

### 5.3 正常关闭

正常关闭程序时：

- 清理尚未保存的正常待保存缓存；
- 不保存跨重启待保存状态；
- 清理失败时记录明确警告和路径；
- 不因清理失败无限阻塞退出。

### 5.4 异常与恢复缓存

以下情况不得登记为正常手动保存候选：

- 没有完整帧；
- 任一设备封存失败；
- 完整帧数与持久化帧数不一致；
- 采集、停止、处理上下文或设备集合不完整；
- 控制或存储任务已标记失败。

这些缓存继续作为恢复文件：

- 不被下一次正常采集的“覆盖上一任务”逻辑自动删除；
- 在诊断页报告路径；
- 继续由“恢复缓存”流程处理。

正常待保存缓存与异常恢复缓存必须在日志语义和生命周期中分开。

## 6. 异步与并发规则

- 手动导出不在 GUI 线程执行；
- 手动导出复用现有单进程批量导出策略；
- 手动导出期间拒绝开始任何普通、背景或参考采集；
- 有任一普通采集仍活动时，“保存光谱”保持禁用；
- 自动导出和手动导出不能同时使用同一个 spool；
- 按钮重复点击不得启动第二个导出；
- UI 更新通过现有 Qt 信号回到主线程；
- 关闭程序时等待有限时间完成已开始的导出；超过上限时按恢复文件处理。

## 7. 错误处理

| 场景 | 行为 |
|---|---|
| 没有待保存任务点击保存 | 拒绝并提示没有可保存数据 |
| 本次任务 0 帧 | 不启用按钮，记录没有可保存数据 |
| 手动导出启动失败 | 保留缓存，按钮恢复可用 |
| 手动导出中途失败 | 保留缓存，报告已发布文件与恢复路径，允许重试 |
| 导出成功但缓存删除失败 | 正式文件保留，报告缓存清理警告，不重复把任务标记为未保存 |
| 新采集前清理旧缓存失败 | 拒绝新采集 |
| 正常退出清理失败 | 报告路径，不阻塞退出 |
| Y 轴最大值不大于最小值 | 对话框保持打开，设置不生效 |
| 忙碌时打开选项 | 拒绝并说明采集或保存尚未结束 |

## 8. 组件改动边界

### 8.1 `DeviceSidebar`

- 删除采集和存储设置控件；
- 标题改为“设备”；
- 设备卡接口不变。

### 8.2 `SettingsDialog`

- 增加批次大小、格式和自动存储；
- 使用现有禁止滚轮误操作的输入控件；
- 返回完整选项值；
- 自动存储值只在当前运行期使用，程序启动仍强制关闭。

### 8.3 Y 轴对话框

新增独立小型对话框，负责：

- 展示当前 Y 轴设置；
- 输入验证；
- 返回不可变设置值。

对话框不直接操作绘图控件，由 `MainWindow` 应用结果。

### 8.4 `MainWindow`

- 重排上下文工具栏；
- 持有采集方式控件；
- 管理“保存光谱”按钮状态；
- 将系统选项值转换为采集请求；
- 接收正常待保存、覆盖、导出完成和错误信号；
- 在关闭时请求清理正常待保存缓存。

### 8.5 `AcquisitionController`

- 区分正常待保存缓存和异常恢复缓存；
- 在未自动存储的正常任务完成后发布待保存上下文；
- 在下一次普通采集前执行安全覆盖；
- 保持背景/参考、ACK、停止尾帧和错误回滚逻辑不变。

### 8.6 `StorageSessionManager`

- 将创建封存导出上下文和启动封存导出分开；
- 让自动保存和手动保存复用同一个导出器；
- 接受冻结设备/处理/命名信息，不在手动保存时重新读取可变 UI；
- 保持导出、清理和错误信号异步。

### 8.7 部署副本

实现完成后使用构建工具同步 `deploy/rock4bplus`，不手工维护第二套源码。

## 10. 验收标准

满足以下条件才算完成：

1. 批量存储设置不再占用主界面左侧空间；
2. 采集方式位于“保存图片”右侧；
3. “保存光谱”位置、文本和状态符合设计；
4. 未自动存储的上一普通任务可以完整手动导出；
5. 手动导出使用采集开始时冻结的全部设置；
6. 未保存便启动下一普通任务时无提示清除旧缓存并记录诊断；
7. 正常关闭清除待保存缓存；
8. 异常恢复缓存不会被正常覆盖逻辑误删；
9. 自动保存格式、处理结果、命名和批次规则无回归；
10. 采集完整性和界面流畅性不因手动保存功能下降；
11. 自动测试、部署检查和 ROCK 4B+ 实机测试通过；
12. 原 Windows 项目和当前受保护的未提交文件保持不变。
