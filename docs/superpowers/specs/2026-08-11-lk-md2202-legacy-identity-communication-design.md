# LK-MD2202 旧固件身份与通信配置兼容设计

日期：2026-08-11

## 1. 背景与实机证据

ROCK 4B+ 已通过 `/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0`、地址 1、波特率 9600 与 LK-MD2202 建立 Modbus RTU 通信。完整只读探测可以依次读出身份、X/Y 配置、通信配置和 X/Y 状态，证明 USB-RS485、串口权限、接线、地址及波特率均正常。

本块驱动板返回的 0x0000..0x000F 身份寄存器为：

```text
0064 0014 FFFF FFFF FFFF FFFF 0002 FFFF FFFF FFFF FFFF FFFF FFFF FFFF FFFF FFFF
```

其中设备名区域并未返回当前软件原先要求的 ASCII `LK-MD2202`。现有严格设备名判断因此会拒绝该板。诊断命令输出中的 `"name": "LK-MD2202"` 是临时诊断函数填入的标签，不是驱动板返回的设备名，正式实现不得伪造此字段。

通信配置寄存器 0x0050..0x0054 的实测原始值为：

```text
0001 0003 0000 0000 0000
```

根据《LK-MD2202 两路微型步进电机驱动器使用说明 V2.0》，其语义为地址 1、9600 baud、8 数据位、1 停止位、无校验。当前代码把后三个寄存器的原始枚举码 `0, 0, 0` 直接当作语义值传给仅接受 `8, 1, 0` 的模型，因而错误报告“需要 8N1”。这是软件解码问题，不是板卡配置错误。

同一次只读探测还确认：

- X、Y 均为零点限位模式；终点位置均为 4800 pulse。
- X、Y 加速、减速和位置速度均为 10000。
- X、Y 当前均未触发零点限位，运行状态为停止。
- X、Y 当前位置均为 320 pulse，即按当前换算约 1 mm。

## 2. 目标

- 让具有本次实测旧固件身份特征的 LK-MD2202 可被自动识别并正常连接。
- 继续接受设备名符合 `LK-MD2202` 的标准固件。
- 正确把通信寄存器的原始枚举码解码为应用层 8N1 参数。
- 保持自动识别的严格性，不把任意设备名为空或异常的 Modbus 设备误识别为 LK-MD2202。
- 保持现有 X/Y 电机功能、扫描逻辑、光谱仪采集及二者联动逻辑不变。
- 保持源代码、ROCK 4B+ 部署镜像、Git 记录和板端更新均可验证、可回退。

## 3. 非目标

- 不写入驱动板寄存器，不改变地址、波特率或电机参数。
- 不改变运动、回零、限位、扫描或光谱仪采集行为。
- 不把旧固件诊断标签写成驱动板真实设备名。
- 不兼容尚未实测的其他空设备名、其他身份布局或近似签名。
- 不修改光谱仪现有控制逻辑，也不处理激光器或数据处理功能。

## 4. 已确认方案：精确旧固件签名兼容

统一的身份判定规则为：满足以下任一条件即为受支持的 LK-MD2202。

1. 按现有规范解出的设备名，经大小写、下划线、连字符和空格归一化后，以 `LK-MD2202` 开头；或
2. 0x0000..0x000F 共 16 个原始寄存器与本次实测旧固件签名逐项完全一致。

旧固件签名将作为只读常量保存在协议模块中。判定函数直接接收原始身份寄存器，在解码设备名的同时执行精确匹配；不在 `DeviceIdentity.name` 中填入虚构名称，也不把原始寄存器加入面向用户的身份 JSON 数据结构。

以下情况全部拒绝：

- 空设备名且原始签名不完全一致；
- 只有软件版本、某个保留寄存器或部分签名相同；
- 身份响应长度不足 16；
- 标准设备名不匹配且不属于精确旧固件签名。

这样可以兼容已验证的板卡，同时不会把“所有无设备名的 Modbus 从站”扩大到自动连接范围。未来若出现另一版旧固件，必须先取得完整只读证据并单独评审，不能使用通配规则。

## 5. 身份识别与连接流程

协议层提供一个统一的“受支持 LK-MD2202 身份”判定入口，控制器自动探测、命令行只读探测和修改通信参数后的重新连接均调用该入口，避免三处规则漂移。

首次自动连接仍沿用现有两阶段校验：

```text
候选串口/地址/波特率
  -> 读取完整身份寄存器
  -> 标准设备名或精确旧固件签名通过
  -> 读取并解析 X 配置
  -> 读取并解析 Y 配置
  -> 读取并解析通信配置
  -> 读取并解析 X 状态
  -> 读取并解析 Y 状态
  -> 全部成功后才标记为已连接并保存候选项
```

精确签名是第一层设备识别；完整只读初始化链是第二层协议与配置一致性校验。任何一步超时、Modbus 异常、响应长度错误或字段解析失败，都不得进入“已连接”状态。

修改地址或波特率后的重新连接已建立在修改前完成完整初始化的前提上。重连阶段使用同一身份判定规则确认新通信参数下仍是同一类受支持设备，再继续现有配置写入状态机；本次不扩大配置写入范围。

## 6. 通信寄存器解码

通信配置读取保持寄存器地址和数量不变，只修复原始码到语义值的转换：

| 字段 | 原始码 | 应用层语义 |
| --- | ---: | ---: |
| 波特率 | 0..7 | 1200、2400、4800、9600、19200、38400、57600、115200 |
| 数据位 | 0 | 8 |
| 数据位 | 1 | 9（当前应用拒绝） |
| 停止位 | 0 | 1 |
| 停止位 | 1 | 1.5（当前应用拒绝） |
| 停止位 | 2 | 2（当前应用拒绝） |
| 校验 | 0 | 无校验 |
| 校验 | 1 | 偶校验（当前应用拒绝） |
| 校验 | 2 | 奇校验（当前应用拒绝） |

应用层继续只支持 8N1 无校验。也就是说，实测原始值 `0,0,0` 将正确转换成 `8,1,0`；其他手册定义但本应用不支持的组合会在解码时给出明确错误，不会静默按 8N1 使用。未知枚举码同样明确拒绝。

通信配置写入逻辑不变：现有软件只写地址和波特率，不写数据位、停止位或校验位，因此本缺陷未造成错误写入。

## 7. 代码影响范围

预计只修改以下源文件及对应测试：

- `spectrometer/motor/lk_md2202.py`：增加精确旧固件签名、统一身份判定及通信原始码映射。
- `spectrometer/motor/controller.py`：自动探测与配置重连改用统一身份判定。
- `spectrometer/motor/probe.py`：只读探测改用统一身份判定。
- `tests/motor/` 下相关测试：覆盖身份与通信解码边界、探测和控制器连接流程。
- 由现有构建工具同步 `deploy/rock4bplus/app/` 中对应文件，不手工维护分叉副本。

不修改光谱仪采集模块、扫描状态机、电机运动命令、界面布局或配置默认值。

## 8. 测试设计

### 8.1 协议单元测试

- 标准 `LK-MD2202` 设备名继续通过。
- 本次实测的完整 16 寄存器旧固件签名通过，但解出的真实设备名仍保持为空或原始解码结果。
- 对旧固件签名逐个改变关键值的近似签名拒绝。
- 空名、全 `FFFF`、响应过短及无关设备名拒绝。
- 原始通信配置 `(1, 3, 0, 0, 0)` 解码为地址 1、9600、8N1 无校验。
- 数据位、停止位、校验位的手册枚举正确映射；非 8N1 组合被明确拒绝。
- 未知波特率码及未知通信格式码被明确拒绝。

### 8.2 工作流回归测试

- 命令行只读探测遇到精确旧固件签名后继续读取 X/Y 配置、通信配置和状态。
- 控制器仅在完整初始化链全部成功后发出已连接状态。
- 近似签名不会启动初始化链，而是继续下一个候选设备。
- 配置重连使用同一身份规则；不回归标准设备名路径。
- 完整项目自动化测试通过；若存在与本改动无关的环境跳过项，单独记录。

### 8.3 部署一致性检查

- 运行现有 ROCK 4B+ 部署构建脚本。
- 校验源文件与 `deploy/rock4bplus/app/` 镜像对应文件一致。
- 对部署目录执行 Python 编译检查，并执行项目测试。

## 9. ROCK 4B+ 实机验收

板端更新前先对被替换文件建立带时间戳的备份。更新后先进行 Python 编译检查，再运行正式、未注入诊断函数的只读命令：

```bash
cd /opt/zgcai-spectrometer
./.venv/bin/python -m spectrometer.motor.probe \
  --port /dev/serial/by-id/usb-1a86_USB_Serial-if00-port0 \
  --address 1 \
  --baud 9600 \
  --json
```

验收标准：

1. 输出 `"ok": true`，且不再需要 monkey patch 或伪造设备名。
2. 地址、波特率、X/Y 配置与本次实测值一致。
3. X/Y 状态读取成功，命令全程不写寄存器、不驱动电机。
4. 启动 PyQt6 主程序后可自动识别并连接该驱动板。
5. 光谱仪原有连接、采集和保存流程不受影响。

只读验收通过后，运动功能仍按既定安全顺序另行实测：先确认限位与急停条件，再做低速、短距离单轴运动，最后验证扫描及光谱仪联动。本兼容修复本身不授权直接执行运动。
