# ROCK 4B+ 光谱仪软件电机控制与扫描联动设计

## 1. 背景与目标

现有“光谱仪 - Linux转移版”已经在 Radxa ROCK 4B+（Debian 12 Bookworm ARM64）
上完成光谱仪控制和采集迁移。本次工作以该工程为唯一主工程，从
“SM2009 - 完整版”中提取电机规格、STM32/TMC2209 固件、通信协议和必要的
上位机行为，将电机控制嵌入现有 PyQt6 光谱仪软件。

最终软件名称和主要性质保持不变，仍是光谱仪采集软件。电机用于辅助光谱扫描，
不得改变现有光谱仪设备识别、参数设置、采集、完整帧持久化、数据导出和诊断逻辑。

## 2. 已确认范围

### 2.1 本次实现

1. 自动识别电机控制器串口；
2. 电机连接和断开；
3. X、Y、Z 三轴速度设置；
4. 单轴正向或反向移动指定距离；
5. 软件坐标显示、坐标清零、返回软件零点；
6. X/Y 矩形蛇形扫描；
7. 每轮扫描与现有光谱仪连续采集联动；
8. PB3、PB4、PB5 三轴机械零点限位；
9. 可选的机械回零和异常后的坐标恢复；
10. ROCK 4B+ USB、udev、部署、诊断和实机验收；
11. 将完整且可编译的 `TMC2209` 下位机工程纳入主工程。

### 2.2 明确不实现

1. 激光器控制及任何激光器联动；
2. 旧上位机“数据处理”功能；
3. Tkinter 和 Matplotlib 界面；
4. 旧上位机矩阵外部触发控制；
5. 下位机自主扫描状态机；
6. 未经确认的光谱仪协议或采集流程重构。

## 3. 采用方案

采用“PyQt6 进程内模块化集成”：

- 光谱仪工程仍是仓库根目录和部署入口；
- 电机串口、协议、坐标、扫描状态机使用独立模块；
- 电机串口在 Qt 工作线程中运行；
- 扫描总控通过现有 `AcquisitionController` 启停光谱采集；
- `MainWindow` 只负责界面装配和信号连接，不承载协议或扫描算法；
- 下位机只执行短命令、运动、限位和回零，不恢复旧的固件扫描状态机。

不采用把电机逻辑直接堆入 `MainWindow` 的做法，也不增加独立电机后台服务。

## 6. 现有与新增引脚

### 6.1 已有电机接口

| 轴 | STEP | DIR | 定时器 |
|---|---|---|---|
| X | PA8 | PA7 | TIM1 CH1 |
| Y | PA6 | PA5 | TIM3 CH1 |
| Z | PA0 | PA1 | TIM2 CH1 |

PB14 为 TMC2209 公共使能，低电平使能；PB12 为 SPREAD 配置。TMC2209 UART
继续使用 PA9、115200、8N1、仅发送。

### 6.2 机械零点限位

| 引脚 | 方向 | 角色 |
|---|---|---|
| PB3 | 输入上拉 | X 轴零点限位 |
| PB4 | 输入上拉 | Y 轴零点限位 |
| PB5 | 输入上拉 | Z 轴零点限位 |
| PB6 | 推挽输出低电平 | 三个开关的公共 0 V 参考 |

三个机械开关均为常开触点，到达零点时闭合：

```text
PB3 ─ X零点开关 ─┐
PB4 ─ Y零点开关 ─┼─ PB6（固定输出0V）
PB5 ─ Z零点开关 ─┘
```

输入语义统一为：

- 高电平：未触发；
- 低电平：零点限位触发。

固件配置 PB3～PB5 为上拉输入和下降沿 EXTI，PB6 在输入配置完成后才配置为
低电平输出。PB6 运行期间禁止输出高电平，PB3～PB5 禁止配置为输出。

串联电阻不是逻辑所必需。若 PCB 可以增加抗干扰器件，建议每个输入使用
4.7～10 kΩ 外部上拉和约 100 nF 滤波。常开触点无法识别断线，该限制需要
记录在验收和使用说明中。

PB3、PB4 原为 JTAG 引脚；现有工程已经关闭 JTAG 并保留 PA13/PA14 SWD，
因此可安全使用。PB3 占用 EXTI3 后停用当前无效的 PA3 DIAG 中断，不影响
SWD 下载调试。

## 7. 下位机设计

### 7.1 修改边界

优先只修改复制后工程中的：

- `Core/Src/main.c`；
- `MDK-ARM/hardware/PUL.c`；
- `MDK-ARM/hardware/PUL.h`；
- `MDK-ARM/hardware/USB_Command.c`；
- `MDK-ARM/hardware/USB_Command.h`；
- 必要时同一 `hardware` 目录下的其他文件。

限位和回零逻辑放入现有 `PUL.c/.h`，避免为新增源文件修改 Keil 工程项目配置。
如实机或编译证明确需修改边界之外的文件，必须先记录原因和回退点。

### 7.2 运动安全

`Motor_Device` 增加：

- 轴标识；
- 15 mm 最大行程；
- 坐标是否可信；
- 当前运动方向；
- 停止原因；
- 限位原始状态、稳定状态和故障锁存；
- 回零状态。

所有运动入口执行：

1. 参数、速度和距离合法性检查；
2. 当前运动互斥检查；
3. 方向相关的零点限位检查；
4. 坐标可信时的目标范围检查；
5. 设置“运动进行中”状态；
6. 启动 PWM。

不能只限制单条命令的脉冲数，还必须在坐标可信时限制累计目标位置为
`0.0～15.0 mm`。

### 7.3 限位处理

限位采用“立即停止、主循环确认”的两层策略：

1. EXTI 下降沿发生时立即关闭对应轴 PWM；
2. 中断只记录原始事件，不发送 USB、不执行延时；
3. 主循环进行约 5～10 ms 稳定性确认；
4. 稳定闭合时根据当前状态处理：
   - 显式回零：视为预期到位；
   - 正常朝零点运动：停止、坐标设为 0；
   - 扫描或其他非预期运动：锁存限位故障并中止任务；
5. 短毛刺仍保持安全停止，但不把坐标错误设置为 0；
6. 零点开关闭合时禁止继续朝零点方向运动，允许反向离开。

PB3 的 EXTI3 映射取代 PA3 DIAG。PB4 使用 EXTI4，PB5 使用 EXTI9_5。

### 7.4 可选机械回零

机械回零不是扫描前置条件，是坐标校准和故障恢复手段。每轴采用：

1. 若开关已闭合，低速反向离开直到释放；
2. 以回零快速速度朝零点搜索；
3. 首次闭合立即停止；
4. 反向退出约 0.5 mm；
5. 以低速二次接近；
6. 再次稳定闭合后把坐标设为 0 并标记可信；
7. 超过最大搜索距离或超时仍未触发时，锁存回零失败。

初始回零方向沿用当前固件语义 `DIR_CCW=0`，但 X/Y/Z 分别使用可配置常量，
在首次实机验收时低速确认，不把机械方向散落在业务代码中。

支持单轴和全部回零。全部回零按顺序执行，任何轴失败即停止后续回零。

### 7.5 协议

保留现有 `SPEEDn`、`MOVEn`、`STATUS`、`PB14` 等命令兼容性，新增短行协议：

```text
ID?
LIMIT?
POS?
POSSET=<axis>:<mm>
HOME=<axis|ALL>
STOP
FAULT?
CLEARFAULT
```

响应包含协议版本、控制器身份、轴、速度、软件坐标、坐标可信度、移动状态、
三个限位状态、回零状态和停止原因。响应保持短且可逐行解析。

同时修复：

- `STATUS` 临时缓冲区大于全局缓冲区导致的截断/越界风险；
- `SPEED` 成功后没有复制 ACK 的问题；
- 速度缺少可信上限的问题；
- `RESET` 实际只是停止却被描述为回零的问题；
- USB CDC 忙时响应可能丢失的问题；
- 命令接收按 USB 包而不是按完整文本行处理的问题。

`RESET` 不再承担含糊语义，停止统一使用 `STOP`，机械回零统一使用 `HOME`。

## 8. 电机自动识别与串口

自动识别采用三层确认：

1. 枚举 USB CDC 候选，优先匹配 STM32 CDC VID:PID `0483:5740`；
2. 发送 `ID?` 并验证电机协议身份与版本；
3. 使用 STM32 MCU UID 生成的 USB 序列号绑定设备和本地状态。

不得只依赖 `/dev/ttyACM*` 名称，也不得占用已经被光谱仪控制器使用的端口。
界面保留自动发现结果、手动刷新、连接和断开，不在未确认设备身份时发送运动命令。

电机串口通过 PyQt6 `QSerialPort` 和独立 `QThread` 工作，GUI 线程只接收 Qt
信号。命令严格串行化，一次只允许一个等待 ACK/完成的运动事务。

ROCK 4B+ 增加电机控制器 udev 规则：

- VID:PID `0483:5740`；
- `GROUP="dialout"`；
- `MODE="0660"`；
- `TAG+="uaccess"`。

## 9. 软件坐标与持久化

软件坐标范围固定为 `0.0～15.0 mm`，允许反向运动，但不允许目标坐标小于 0。

坐标是开环估算值。持久化文件至少记录：

- 电机控制器 USB 序列号；
- X/Y/Z 坐标；
- 坐标可信度；
- 是否正在运动；
- 正常关闭标记；
- 最后停止原因和时间。

运动开始前先持久化“运动中/坐标暂不可信”，运动正常完成后原子保存新坐标。
正常关闭、同一控制器重新连接且上次没有未完成运动时，可以恢复坐标。异常掉电、
断线、超时或中止时不得自动认定坐标可信。

扫描前不强制机械回零。可信坐标可以通过以下方式建立：

1. 恢复同一控制器的正常关闭状态；
2. 用户确认当前位置；
3. 软件坐标清零；
4. 可选机械回零。

“坐标清零”只改变软件坐标，不产生运动。由于正向端没有机械限位，在非机械零点
位置执行软件清零可能降低正向软限位的物理可信度，界面必须明确提示。

发生堵转时固件仍可能完成脉冲输出，软件无法仅凭脉冲确认机械位置。用户发现异常后
可触发“位置异常”，系统停止运动、停止扫描并把坐标标记为不可信。恢复时允许低速、
短距离、按住才运动的点动，或执行机械回零；不得盲目自动反向 15 mm。

## 10. 上位机模块

### 10.1 `models.py`

定义轴枚举、速度和行程常量、设备身份、位置可信度、限位状态、运动结果、
扫描参数、扫描路径点和扫描状态。模型不依赖 Qt 控件。

### 10.2 `protocol.py`

负责命令生成、响应分帧、语法校验和结构化解析。协议错误、超时、设备拒绝和
限位中止使用不同结果，不通过字符串包含关系判断。

### 10.3 `discovery.py`

基于 `QSerialPortInfo` 枚举候选、执行握手、去除光谱仪占用端口并稳定绑定
控制器 USB 序列号。

### 10.4 `transport.py`

持有 `QSerialPort`，实现文本行缓冲、命令队列、超时、断开、热拔插、有限重试
和线程安全关闭。运动命令不自动重发，避免重复移动。

### 10.5 `controller.py`

提供连接、断开、速度、点动、指定距离、停止、坐标清零、位置确认、软件回零、
机械回零、限位和故障接口。它是 UI 和扫描总控访问电机的唯一入口。

### 10.6 `scan.py`

包含无副作用路径规划器和异步扫描状态机。规划器先生成完整路径并验证所有坐标，
状态机再依次执行，不在运行途中临时改变参数。

## 11. 扫描路径

输入参数：

| 参数 | 含义 |
|---|---|
| `x` | X轴每个完整行程距离，mm |
| `y` | Y轴每次推进距离，mm |
| `n` | Y推进次数 |
| `m` | 完整矩阵扫描轮数 |
| `x_steps` | 每个X行程的细分步数，默认1 |
| `y_steps` | 每次Y推进的细分步数，默认1 |
| `dwell_s` | 每个子步完成后的等待时间，默认0 |

设本轮起点为 `(start_x, start_y)`。每轮：

```text
direction = +X
重复 n 次:
    沿 direction 移动 x，拆为 x_steps 个等距子步
    沿 +Y 移动 y，拆为 y_steps 个等距子步
    direction 反转
再沿当前 direction 移动一次 x
```

因此：

- X 总共执行 `n+1` 个完整行程；
- Y 总共执行 `n` 次推进；
- 矩形尺寸为 `x × (y×n)`；
- 每个 X 子步为 `x/x_steps`；
- 每个 Y 子步为 `y/y_steps`。

每个子步必须等待电机明确停止后才开始计时；计时结束后才能执行下一子步。
最后一个子步后的等待同时承担换轴等待，不重复增加一次等待。

路径预检使用绝对坐标：

```text
0 <= start_x
start_x + x <= 15
0 <= start_y
start_y + y*n <= 15
```

并验证 `x>0`、`y>0`、`n>=1`、`m>=1`、步数为正整数、步时非负、所有换算
脉冲均大于 0。

完成最后一次 X 行程后结束本轮采集，再把 X、Y 顺序移动回本轮起点。复位运动不做
子步细分、不应用扫描步时，也不采集光谱。复位失败时不开始下一轮。

## 12. 光谱仪采集联动

每个完整矩阵单独建立一次连续光谱采集：

1. 冻结本轮电机和光谱仪参数；
2. 通过现有 `AcquisitionController` 启动全局连续采集；
3. 等待控制器确认进入采集状态；
4. 执行全部 `n+1` 个 X 行程和 `n` 个 Y 推进；
5. 子步运动和步时等待期间持续采集；
6. 最后一次 X 行程完成后请求停止；
7. 等待尾帧、spool 封存和本轮保存完成；
8. 电机返回本轮起点，复位期间不采集；
9. 再开始下一轮，共执行 `m` 轮。

扫描总控不得直接发送原始光谱仪命令。现有普通采集、背景、参考、校准和手动保存
语义保持不变。扫描作为新的采集所有者或等价的附加入口接入同一生命周期互斥，
不能与普通采集并发启动。

每轮数据使用独立轮次目录或明确轮次上下文，并生成扫描清单，记录：

- 扫描 ID 和轮次；
- 开始、结束和中止时间；
- 全部扫描参数；
- 起点和规划路径摘要；
- 电机控制器身份、速度、限位与停止原因；
- 光谱仪设备身份和实际输出文件；
- 完成或未完成状态。

扫描中止产生的恢复 spool 和已有完整帧按现有数据完整性规则保留，不伪装成完整轮次。

## 13. 扫描停止与故障

本期提供开始和停止，不引入语义不清晰的暂停续扫。

用户停止、串口断开、限位触发、电机超时、光谱采集失败或应用退出时：

1. 立即请求停止电机；
2. 请求停止光谱采集并等待有限时间收尾；
3. 标记当前轮次未完成；
4. 保存停止原因和恢复文件位置；
5. 不自动复位；
6. 运动结果不确定时把相关轴坐标标记为不可信；
7. 禁止自动开始下一轮。

## 14. 界面

- 上方保留现有绘图区；
- 下方增加可折叠/可调整高度的电机控制面板。

电机面板包括：

6. 扫描参数、路径预检摘要、开始和停止；
7. 当前轮次、路径阶段、子步、步时倒计时和故障信息。

界面使用 PyQt6 和现有样式，不新增 Tkinter、Matplotlib 或第二套绘图后端。

## 15. 线程与状态

GUI、串口和采集任务之间只通过信号与不可变结果通信：

- GUI 主线程：控件和状态展示；
- 电机串口线程：串口读写、分帧和命令事务；
- 现有采集进程/线程：保持原架构；
- 扫描总控：事件驱动状态机，不使用阻塞 `sleep`。

扫描状态至少包含：

```text
IDLE
PRECHECK
STARTING_ACQUISITION
SCANNING_X
SCANNING_Y
DWELLING
STOPPING_ACQUISITION
RETURNING
COMPLETED
STOPPING
FAULTED
```

所有界面可用状态由控制器和扫描状态推导，不使用多个按钮各自维护互相矛盾的布尔值。
