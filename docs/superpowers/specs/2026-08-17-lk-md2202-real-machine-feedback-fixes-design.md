# LK-MD2202 实机反馈修复设计

## 1. 文档状态

- 日期：2026-08-17
- 状态：方案 A 已获用户确认，规格已自检，待用户复核
- 目标分支：`codex/lk-md2202-integration`
- 实施基线：`f8b6cc3`（ROCK 4B+ 电机恢复版部署镜像）
- 上位机平台：Radxa ROCK 4B+、Debian 12 Bookworm ARM64、Python 3.11、PyQt6
- 驱动板：LK-MD2202，X/M1、Y/M2 两轴，地址 1、9600 baud、8N1
- 机械常量：X/Y 行程均为 15 mm，终点位置均为 4800 pulse，换算为 320 pulse/mm
- 前置设计：`docs/superpowers/specs/2026-08-13-lk-md2202-stall-release-home-validation-design.md`

本文只覆盖最新一轮 ROCK 4B+ 实机验证发现的三个问题：运动结束后焦点跳转、脱离卡死停止误锁、无光谱仪时不能执行扫描。它不替代已有 LK-MD2202 总体设计，不改变已经通过实机验证的设速、正反转、机械回零、限位识别和 15 mm 行程保护。

## 2. 实机证据与问题定义

已经通过实机验证：

1. 机械回零卡住后，“脱离卡死”能够让电机脱离；
2. X/Y 电机参数能够正常设置，正反向定距运动正常；
3. 机械回零能够识别零点限位闭合并停止电机。

仍存在以下问题：

1. 每次电机动作开始后，原操作按钮被禁用，Qt 将键盘焦点自动转移到第一个仍可用的扫描参数控件，表现为“X 行程”数值被自动选中；
2. “脱离卡死”写入速度 0 后立即读取运行状态，LK-MD2202 可能短暂返回旧的“仍在运行”状态，或单次状态读取发生超时。现有控制器会立即进入“停止状态未知”安全锁，导致机械回零也被禁用；
3. 主窗口和扫描控制器均强制要求光谱仪设备列表非空，所以未连接光谱仪时无法验证纯电机扫描。

第二项不能通过简单忽略错误或直接清除安全锁解决。修复必须在“避免状态读取得过早造成误锁”和“真正无法确认停止时仍保持安全锁”之间建立可测试的边界。

## 3. 方案选择

### 3.1 方案 A：完善状态机并支持自动纯电机扫描

- 在禁用运动按钮前处理焦点，防止 Qt 把焦点转移到扫描输入框；
- 脱离卡死停止后采用短暂、有限次数的状态复核；必要时补发一次位置急停；
- 没有光谱仪时自动进入纯电机扫描，不启动、停止或重置光谱仪采集；
- 纯电机扫描记录进入现有诊断日志，需要时随诊断包导出，不创建独立扫描清单文件。

该方案已由用户选择。

### 3.2 方案 B：将速度 0 写入应答直接视为停止

改动较小，但写入应答只证明驱动板接收了命令，不能证明电机已经停止。该方案会把真正的停止失败伪装成成功，不采用。

### 3.3 方案 C：增加手动“纯电机模式”开关

模式表达明确，但用户需要额外切换，而且开关状态可能与实际设备连接状态不一致。当前规则可以由光谱仪设备列表可靠推导，因此不采用。

## 4. 界面焦点修复

### 4.1 根因

手动运动开始后，`MotorPanel` 会禁用速度、距离、运动和坐标按钮。鼠标点击的运动按钮此时持有焦点；按钮被禁用后，Qt 自动寻找下一个可聚焦且启用的控件，当前布局中的第一个候选正是“X 行程”，其文本因此被选中。

### 4.2 处理规则

1. 只在“空闲 → 运动中”的真实状态转换发生时处理焦点；
2. 如果当前焦点位于即将禁用的手动电机操作按钮，先清除该按钮焦点，再禁用控件；
3. 不主动把焦点设置到“X 行程”、其他扫描输入框或隐藏控件；
4. 运动结束后不自动恢复到某个输入框，用户下一次点击决定焦点位置；
5. 周期性状态刷新如果没有发生运动状态转换，不得清除用户正在编辑的扫描参数焦点；
6. 保留按钮的键盘可访问性，不采用把所有按钮永久改为 `NoFocus` 的做法。

该修复只影响焦点，不改变控件启用条件和电机运动互斥规则。

## 5. 脱离卡死停止确认

### 5.1 不变的运动边界

- 速度模式主动运行时间继续使用：

```text
release_timeout_s = min(1.0, 4800 / abs(signed_speed_pps))
```

- 达到限位转换条件或截止时间时，立即向速度控制寄存器写入 0；
- 新增的停止复核发生在写入速度 0 之后，不延长主动速度运行时间；
- 动作开始即把对应轴标记为未校准；脱离卡死本身永远不能重新建立坐标。

### 5.2 停止确认状态机

停止流程调整为：

1. 写入速度 0；
2. 给驱动板一个很短的状态更新时间，再读取该轴运行状态；
3. 如果已经停止，按原始停止原因结束动作，不进入安全锁；
4. 如果第一次仍上报运行中，视为可能的状态延迟，立即补发一次位置模式急停，然后继续有限次数复核；
5. 如果状态读取失败，记录错误并进入同一兜底停止与复核流程，不因单次读取失败立即锁定；
6. 只有在有界复核时间结束后仍持续上报运行中，或速度 0、位置急停和后续状态读取均无法确认结果时，才进入“停止状态未知”安全锁。

实现使用单一控制器状态机和定时器，不使用阻塞等待，不在 Qt 主线程中休眠。停止确认必须有明确的总截止时间和有限重试次数，不能无限轮询。

### 5.3 成功、业务失败与安全失败

结果分为三类：

1. **已确认停止且脱离条件成立**：提示脱离完成，保持未校准，允许机械回零；
2. **已确认停止但脱离条件未成立或方向错误**：提示对应业务原因，保持未校准，仍允许重新选择方向或机械回零；
3. **无法确认停止**：进入安全锁，禁用新的电机动作和扫描，提示切断驱动板电源或重新连接确认。

“已确认停止但需要重新机械回零”不能显示为“电机状态异常需要重连”。真正的安全锁规则仍保留。

## 6. 无光谱仪纯电机扫描

### 6.1 模式判定

扫描开始时根据参与扫描的已连接光谱仪数量自动判定：

- 数量大于 0：继续使用现有“电机扫描 + 每轮连续光谱采集并保存”模式；
- 数量等于 0：进入“纯电机扫描”模式。

不增加模式开关，也不创建虚拟光谱仪设备。

### 6.2 纯电机扫描行为

纯电机模式必须：

1. 使用与联动扫描完全相同的 `ScanParameters` 和 `build_scan_plan()`；
2. 保持 X 蛇形往返、Y 共走 n 次、X 共走 n+1 次、重复 m 轮以及每轮返回起点的既定逻辑；
3. 保持 X/Y 分步和步时规则；
4. 保持“扫描前不强制机械回零”，未校准时仍使用现有风险确认；
5. 保持 15 mm 软件行程检查、运动互斥、急停和安全锁；
6. 不调用光谱仪采集控制器的 `reset()`、`start_scan_global()`或`stop_global()`；
7. 每轮扫描动作完成后直接进入返回动作；返回完成后开始下一轮或结束任务；
8. 用户停止或电机故障时只停止电机状态机，不等待不存在的光谱仪任务。

### 6.3 联动扫描保持不变

只要存在参与扫描的光谱仪，当前联动逻辑继续保持：

1. 每轮先启动连续采集；
2. 采集启动确认后执行扫描运动；
3. 本轮扫描运动完成后停止并保存光谱；
4. 保存完成后电机返回起点；
5. 返回完成后进入下一轮。

不得为了实现纯电机模式改变独立光谱仪采集、设备初始化、绘图、保存或现有联动扫描的控制顺序。

## 7. 日志与导出

### 7.1 纯电机扫描不创建清单文件

纯电机扫描不得调用 `ScanManifestWriter.start()`，也不生成 `scan-*.json`。现有带光谱采集的扫描清单保持不变，因为它仍用于关联每轮光谱任务和保存文件。

### 7.2 使用现有诊断日志

纯电机扫描通过现有 `DiagnosticRecorder` 时间线记录结构化事件，并在“诊断”页显示可读摘要。至少记录：

- 扫描开始：扫描标识、模式 `motor_only`、全部参数、起始坐标和是否已校准；
- 每轮开始与完成：轮次、总轮数、扫描动作数、返回结果；
- 用户停止：已完成轮次和当前阶段；
- 故障：轴、阶段、失败原因和已完成轮次；
- 正常结束：总轮数和最终状态。

不逐步记录每一个 50 ms 状态轮询，避免日志洪泛。用户点击现有“导出诊断包”时，上述事件随时间线一起导出，不增加新的导出按钮和文件格式。

## 10. 测试设计

### 10.1 焦点测试

1. 运动按钮持有焦点时进入运动状态，“X 行程”不得获得焦点或自动全选；
2. 运动结束后不得自动聚焦扫描输入框；
3. 用户本来正在编辑扫描输入框且没有真实运动状态转换时，周期状态刷新不得抢走焦点；
4. 控件启用、禁用和键盘访问规则保持现有行为。

### 10.2 脱离卡死停止测试

1. 第一次停止状态即为停止：正常完成且不锁定；
2. 第一次仍为运行、补发位置急停后停止：正常结束且不锁定；
3. 第一次状态读取失败、兜底后确认停止：不锁定；
4. 多次状态持续上报运行：到截止时间后锁定；
5. 速度 0、位置急停和状态读取均失败：锁定；
6. 限位释放、错误方向、运行超时和限位未释放各自保留原业务结果；
7. 所有已确认停止的结果均保持未校准并允许机械回零；
8. 主动速度运行截止时间仍不超过原来的 1 秒/4800 pulse 理论上限。

### 10.3 纯电机扫描测试

1. `device_ids=()`可以启动扫描；
2. 不调用任何光谱仪采集开始、停止或重置接口；
3. 单轮、多轮、X/Y 分步、步时和返回路径与联动扫描计划一致；
4. 每轮扫描完成后直接返回，不进入采集停止状态；
5. 用户停止和电机故障不等待光谱仪任务；
6. 不创建 `scan-*.json`；
7. 开始、轮次、完成、停止和故障事件进入现有诊断时间线；
8. 无光谱仪的主窗口入口可以启动，未校准确认仍有效；
9. 有光谱仪的联动扫描测试结果和清单行为保持不变。

### 10.4 回归与部署

- 运行电机控制器、面板、扫描控制器和主窗口定向测试；
- 运行完整自动化测试，基线参考为 `f8b6cc3` 的 427 个通过测试；
- 运行 Python 编译检查和 `git diff --check`；
- 重新生成 ROCK 4B+ 部署镜像并验证主源码与部署副本一致；
- 部署前在板端创建时间戳文件级备份并记录恢复路径。

## 11. 实机验收顺序

1. 更新后先确认原光谱仪软件可以正常启动；
2. 分别执行 X/Y 定距运动，确认动作结束后“X 行程”不再自动选中；
3. 在安全位置执行 X/Y 脱离卡死，确认停止后可以直接点击机械回零，不要求重连；
4. 重复脱离卡死测试，确认状态延迟不会造成偶发安全锁；
5. 制造真正无法读取停止状态的通信故障，确认安全锁仍然生效；
6. 不连接光谱仪，使用小行程、单轮、步数 1、步时 0 验证纯电机扫描；
7. 再验证分步、步时、多行程和多轮扫描；
8. 验证每轮均返回扫描起点，急停可中断且不会自动续跑；
9. 在“诊断”页检查纯电机扫描日志并导出诊断包，确认没有生成独立扫描 JSON；
10. 连接光谱仪后完成一轮联动扫描，确认连续采集、保存和返回逻辑无回归。

首次纯电机扫描应使用远离机械边界的小行程，并由用户现场观察实际方向和位置。未经实机观察，不能仅凭累计脉冲变化宣告扫描运动成功。

## 13. 完成标准

只有同时满足以下条件才算完成：

1. 电机动作结束后不再自动选择“X 行程”或其他扫描输入框；
2. 脱离卡死停止状态的短暂延迟不会导致误安全锁；
3. 已确认停止后轴保持未校准，并允许直接机械回零；
4. 真正无法确认停止时仍进入安全锁；
5. 无光谱仪时可以执行完整电机扫描和返回，不调用采集接口；
6. 纯电机扫描不生成独立清单文件，记录可随现有诊断包导出；
7. 有光谱仪时原扫描采集、保存和清单逻辑保持不变；
8. 15 mm 行程、1 秒脱离卡死主动运行上限、未校准警告和机械回零规则保持不变；
9. 定向测试、完整回归、部署镜像检查和 ROCK 4B+ 实机验收通过；
10. 所有修改均有明确 Git 与板端回退路径。
