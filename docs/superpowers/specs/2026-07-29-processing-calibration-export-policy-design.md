# ROCK 4B+ 强度校准、airPLS 与导出策略设计

日期：2026-07-29
状态：已完成讨论，等待用户审阅
目标项目：`D:\codex\光谱仪 - Linux转移版`

## 1. 背景

Linux 专用版本已经具备原始、扣背景、吸光度、自定义公式、全量原始帧
缓存和 CSV/Excel 导出能力，但仍有三个产品链路需要补齐：

1. 强度校准只有数组乘法后端，没有系数导入、校验、持久化、自动加载和
   用户可见状态；
2. airPLS 算法已经存在，但没有完整界面、设备覆盖配置、采集快照和存储
   导出接线；
3. `CSV + Excel` 目前会同时生成两种文件，不符合新的单设备/多设备输出
   规则。

用户提供了四个单设备 CSV 和一个四设备 Excel 作为内容结构参考：

- CSV 先写设备和采集元数据，再以 `Pixel`、`Wavelength` 和每帧一列的
  形式保存数据；
- Excel 包含“采集概要”和每台设备一个工作表；
- 每个设备工作表同样是每帧一列、每像素一行。

本设计只修改 Linux 专用副本及其 `deploy/rock4bplus` 运行副本，不修改
原 Windows 项目，也不修改或纳入用户提供的样例文件、未提交 Excel、
DOCX、PDF 和诊断包。

## 2. 已确认的产品规则

### 2.1 统一处理链

每次采集开始时，为任务中的每台设备冻结一份不可变处理快照。实时绘图
和最终 CSV/Excel 导出必须使用同一份快照和同一个处理器。

固定处理顺序为：

```text
完整原始帧
→ 有效像素裁剪
→ 当前帧、背景和参考分别执行强度校准
→ 原始 / 扣背景 / 吸光度 / 自定义公式
→ airPLS 基线估计与扣除
→ 实时绘图或 CSV/Excel 导出
```

规则如下：

- `.part/.zgs` 始终保存未经强度校准、模式处理和 airPLS 处理的完整
  原始帧；
- 强度校准、背景、参考和当前帧的长度必须严格一致；
- 背景和参考继续以原始有效像素值保存，使用时与当前帧应用同一组强度
  校准系数；
- airPLS 可用于所有处理模式，包括吸光度；
- 绘图和导出只使用最终处理结果；
- CSV/Excel 不增加原始值、估计基线或其他中间结果列；
- 采集开始后修改界面参数只影响下一次任务，不改变正在运行任务的快照。

### 2.2 强度校准

当前强度校准模型保持为逐像素乘法：

```text
Ical[i] = Iraw[i] × coefficient[i]
```

当前帧、背景和参考都使用相同系数，因此：

```text
扣背景 = Ical - Idark_cal
吸光度 = -log10((Ical - Idark_cal) / (I0_cal - Idark_cal))
```

程序不自行推导厂家强度校准系数。系数由用户从 CSV/TXT 文件导入。

### 2.3 airPLS

顶部提供全局默认设置，每台设备默认跟随全局，也可以按设备生产序列号
保存独立覆盖配置。

全局默认值：

- 默认关闭；
- 平滑度 `lambda = 100000`；
- 差分阶数 `order = 2`；
- 最大迭代次数 `max_iter = 15`。

airPLS 永远是处理链的最后一步。启用后，最终结果为：

```text
final = mode_result - airpls_baseline(mode_result)
```

## 3. 数据模型与服务边界

### 3.1 处理快照

扩展 `ProcessingSnapshot`，至少增加：

- `intensity_calibration_id`；
- `baseline_enabled`；
- `baseline_lam`；
- `baseline_order`；
- `baseline_max_iter`；
- `processing_pipeline_version`。

现有 `intensity_calibration`、`background`、`reference`、`mode` 和
`custom_formula` 字段继续保留。

`ProcessingSnapshot.config` 必须构造包含完整 airPLS 设置的
`ProcessingConfig`，不得继续隐式使用 `baseline_enabled=False`。

### 3.2 强度校准记录

新增不可变强度校准记录，包含：

- 生产序列号；
- 有效像素数；
- 系数数组；
- 导入时间；
- 原始文件名；
- 原始文件 SHA-256；
- 校准记录 ID；
- 数据格式版本。

持久化位置使用 Linux 用户配置目录下的独立校准目录，例如：

```text
~/.config/ZGCAI/Spectrometer/calibrations/intensity/
```

记录以“生产序列号 + 有效像素数”定位，使用临时文件和原子替换更新。
校准文件不放入采集数据目录，用户更改采集输出目录不会使校准失效。

没有可靠生产序列号时，允许当前运行期间临时使用导入系数，但不进行跨
会话自动加载，避免将系数误用到另一台同型号设备。

### 3.3 airPLS 设置

全局默认参数写入现有用户设置。设备覆盖配置写入独立处理配置仓库，
以生产序列号为主键，内容包括：

- 是否跟随全局；
- 覆盖时是否启用；
- `lambda`；
- `order`；
- `max_iter`。

没有可靠生产序列号的设备覆盖仅在当前运行期间有效。

### 3.4 生效配置解析

新增单一解析入口：

```text
effective_processing_profile(device, global_settings, device_override)
```

优先级为：

1. 设备选择“跟随全局”时使用全局设置；
2. 设备取消跟随时使用设备覆盖；
3. 缺少覆盖时回退到全局设置。

主窗口绘图、采集快照和存储导出不得各自重复实现优先级逻辑。

## 4. 强度校准文件格式

导入器按 `UTF-8-SIG`、`GB18030` 的固定顺序解码；两者都失败时明确
报告编码错误。字段支持逗号、制表符或空白分隔。

支持两种结构。

单列：

```text
Coefficient
1.0021
0.9987
1.0045
```

两列：

```text
Pixel,Coefficient
0,1.0021
1,0.9987
2,1.0045
```

解析规则：

- 允许一个标题行；
- 允许空行；
- 允许以 `#` 开头的整行注释；
- 单列按文件行顺序对应裁剪后的有效像素 `0..N-1`；
- 两列的 Pixel 必须为整数，并从 0 连续递增到 `N-1`；
- 系数必须是有限正数；
- 系数数量必须严格等于设备 `valid_pixel`；
- 不接受自动截断、补齐、插值或重复最后一个系数；
- 任一错误使整次导入失败，原有校准保持不变。

## 5. 界面设计

### 5.1 顶部处理栏

在现有处理模式控件附近增加：

- `启用 airPLS` 复选框；
- `airPLS 参数…`按钮。

参数对话框包含：

- 平滑度 `lambda`；
- 差分阶数；
- 最大迭代次数；
- 恢复默认值。

所有参数输入继续使用项目已有的直接输入控件：隐藏增减按钮，屏蔽滚轮、
方向键和 PageUp/PageDown 误操作。

### 5.2 设备参数与校准

在现有“设备参数与校准”对话框中增加两个分区。

设备 airPLS：

- `跟随全局设置`，默认勾选；
- 取消跟随后显示或启用本设备的 airPLS 开关和三个参数；
- 显示当前最终生效来源：全局或设备覆盖。

强度校准：

- 状态文本：未加载，或“已加载，共 N 个系数”；
- 校准记录 ID 或短摘要；
- `导入系数…`按钮；
- `清除校准`按钮。

导入、清除以及修改设备覆盖只允许在该设备和所有相关采集任务完全空闲
时执行。失败原因同时显示在对话框和诊断页。

### 5.3 自动加载

设备协议握手成功并获得生产序列号、总像素、起始像素和有效像素后，
加载与“生产序列号 + 有效像素数”完全匹配的强度校准，再加载设备
airPLS 覆盖，并刷新设备对话框状态。

像素配置不匹配的记录不得静默加载。

## 6. 实时绘图性能

airPLS 默认关闭，因此普通实时绘图路径不增加额外计算。

启用 airPLS 后，不在 Qt GUI 线程同步执行稀疏迭代求解。新增有界后台
显示处理服务：

- 每台设备最多保留一个正在处理的帧和一个最新待处理帧；
- 新显示帧可以替换尚未开始处理的旧显示帧；
- 替换只影响显示，绝不影响采集进程和 `.part/.zgs` 全量写入；
- 每个任务携带设备 ID、采集任务 ID 和处理快照代次；
- 完成结果只有在任务 ID 和代次仍匹配时才允许绘图；
- 旧参数或已停止任务的迟到结果直接丢弃；
- 服务关闭时有界等待，不阻塞正常停止状态机。

差分惩罚矩阵按“像素数 + 差分阶数”缓存。缓存只包含可安全复用的稀疏
结构，不缓存与某一帧权重相关的求解结果。

airPLS 可能使校正后曲线的实际刷新率低于 25 FPS，但必须保证：

- GUI 持续响应；
- 串口独立采集进程不受影响；
- 完整原始帧数与持久化帧数一致；
- 显示任务不会形成无界队列。

## 7. 存储格式决策

新增唯一的纯函数，根据用户选择和本次采集任务设备数生成导出计划。

| 用户选择 | 一台设备 | 两台及以上设备 |
|---|---|---|
| 仅 CSV | 每台设备一个 CSV | 每台设备一个 CSV |
| 仅 Excel | 一个 Excel | 一个多工作表 Excel |
| CSV + Excel | 只生成该设备的 CSV | 只生成一个多工作表 Excel |

补充规则：

- “设备数”取 `AcquisitionRequest.device_ids` 的唯一设备数；
- 不使用当前连接设备总数；
- 全局任务只有一台参与设备时仍按单设备处理；
- 模拟路径、实时批次路径、封存 `.zgs` 导出路径和恢复导出路径必须
  共用同一决策函数；
- 当前批次大小 1–1000、默认 500 的规则不变；
- 未勾选自动存储时，成功停止后不生成 CSV/Excel；
- 当前 `.part/.zgs` 生命周期和停止后后台转换时机不在本次改变范围内。

## 8. 文件结构与元数据

### 8.1 CSV

每台设备、每个批次一个文件。结构保持：

1. 元数据区；
2. 空行；
3. `Pixel`、`Wavelength` 和每帧数据列；
4. 每帧一列、每个有效像素一行。

元数据至少包含：

- Device ID；
- Frame Count；
- Export Time；
- Port；
- Serial；
- Integration Time；
- Trigger Mode；
- Processing Mode；
- Intensity Calibration Applied；
- Intensity Calibration ID；
- AirPLS Applied；
- AirPLS Lambda；
- AirPLS Order；
- AirPLS Max Iterations；
- Processing Pipeline Version。

### 8.2 Excel

每批一个工作簿，包含：

- “采集概要”；
- 每台设备一个工作表。

采集概要保留会话、批次、同步方式和设备数量，并扩展设备明细，使每台
设备的处理模式、强度校准记录和最终 airPLS 参数可追溯。设备工作表继续
使用 `Pixel`、`Wavelength` 和每帧一列的结构。

### 8.3 文件名

文件名保持当前 Linux 版本规则，不恢复参考样例中的旧长文件名：

```text
20260729_SN003_B0001.csv
20260729_SN003_B0001.xlsx
20260729_多设备_B0001.xlsx
```

重名继续追加 `_01`、`_02`，不得覆盖已有文件。

## 9. 存储一致性和失败语义

CSV/Excel 导出在独立进程中对 `.zgs` 的每个原始帧执行完整处理链。
实时绘图可以跳过旧显示帧，但存储导出不得跳过任何完整持久化帧。

失败规则：

- 缺少处理快照时失败；
- 校准、背景、参考或当前帧长度不一致时失败；
- 强度校准或模式处理产生非有限值时失败；
- airPLS 参数或计算失败时失败；
- 任一目标文件生成失败时不发布对应临时文件；
- 失败后保留 `.zgs` 并在诊断页显示完整路径；
- 成功导出的帧数必须等于每台设备的 `persisted_frames`；
- 全部目标文件发布和计数核对成功后，才按现有生命周期删除 `.zgs`。

## 10. 测试设计

### 10.1 强度校准

- 单列、两列、标题、空行、注释、逗号、制表符和空白分隔；
- UTF-8 BOM；
- 像素序号不连续、重复和越界；
- 数量不足或过多；
- 零、负数、NaN 和无穷大；
- 导入失败不覆盖旧记录；
- 原子保存、自动加载、清除；
- 序列号和有效像素数隔离；
- 无生产序列号时不跨会话持久化。

### 10.2 处理链

- 全 1 系数不改变结果；
- 已知系数正确作用于当前帧、背景和参考；
- 原始、扣背景、吸光度和自定义公式后执行 airPLS；
- airPLS 也可作用于吸光度；
- 输出只包含最终处理结果；
- 快照冻结，采集中修改设置不改变当前任务；
- 处理元数据与实际参数一致。

### 10.3 airPLS 配置与显示

- 全局默认；
- 设备跟随；
- 设备覆盖；
- 重连和重启恢复；
- 无序列号临时覆盖；
- 后台显示处理只保留最新待处理帧；
- 过期代次结果不会绘制；
- GUI 关闭和任务停止无残留工作线程；
- 普通未启用 airPLS 路径不发生性能回退。

### 10.4 导出矩阵

- `仅 CSV`：单设备一个 CSV，多设备每台一个 CSV；
- `仅 Excel`：单设备和多设备均为一个工作簿；
- `CSV + Excel`：单设备只有 CSV，多设备只有 Excel；
- 尾批规则；
- 每帧一列、每像素一行；
- Excel 概要和设备工作表；
- 当前短文件名和冲突后缀；
- 模拟批次和封存 `.zgs` 导出结果一致；
- 处理失败保留恢复文件。

### 10.5 回归

- 完整自动测试；
- `compileall`；
- PyQtGraph 与旧绘图后端测试；
- `deploy/rock4bplus` 源码一致性检查；
- 不修改原 Windows 项目；
- 不暂存、覆盖或删除用户已有未提交文件和参考样例。

## 11. ROCK 4B+ 实机验收

1. 为 SN003 导入一组 3648 点全 1 系数，重启程序并确认自动加载；
2. 确认全 1 系数不改变绘图和导出值；
3. 使用已知测试系数验证指定像素变化；
4. 启用全局 airPLS，确认界面可操作且绘图与导出结果一致；
5. 配置 SN003 的设备覆盖，确认其优先于全局并能在重启后恢复；
6. 单设备分别验证三个存储选项；
7. 两台及以上设备分别验证三个存储选项；
8. 核对 CSV/Excel 结构、最终处理值、元数据和当前命名规则；
9. 导出诊断包，确认完整帧数等于持久化帧数；
10. 制造一次强度校准文件错误和一次导出处理错误，确认旧校准不丢失且
    `.zgs` 被保留。

## 12. 非目标

本轮不包含：

- 修改 MCU 协议或下位机固件；
- 从标准光源自动计算强度校准系数；
- 在 CSV/Excel 中同时保存原始、基线和最终结果；
- 修改当前文件命名规则；
- 修改当前 `.part/.zgs` 正常成功后的生命周期；
- 将停止后导出改为采集中实时生成 CSV/Excel；
- 修改原 Windows 项目；
- 四台实机和硬同步接线验收本身。
