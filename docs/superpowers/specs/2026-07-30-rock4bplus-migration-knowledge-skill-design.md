## 1. 目标

把本次 Python、Qt、USB 串口光谱仪迁移到 Radxa ROCK 4B+ 的实际经验
沉淀为两类可复用资产：

1. 当前项目中的完整迁移案例手册；
2. 可在任意项目直接调用的个人 Codex 技能 `$rock4bplus-migration`。

技能固定面向 Radxa ROCK 4B+，以 Python + Qt 桌面软件为主流程，同时保留
其他软件类型迁移时仍适用的通用环境、部署、诊断和验收框架。

最终目标不是保存一份问题清单，而是让未来迁移能够从工作区保护、环境核对、
架构设计、实施、部署、实机诊断到验收形成可重复执行的闭环。

```text

→ 修复
```

每个结论必须标注为以下三类之一：

- **经验性建议**：符合工程实践，但需要在新项目重新验证；

`references/`，可复制材料放入 `templates/`，避免每次调用都加载全部案例。

## 4. 案例手册内容

案例手册至少覆盖以下问题域。

### 4.1 工作区和版本保护

- 迁移前检查 Git 状态；
- 将 Windows 原项目与 Linux 专用副本分开维护；
- 识别并保护用户未提交文件；
- 使用明确文件列表暂存，避免 `git add -A` 纳入数据和资料；
- 修改后核对工作区、提交内容和部署副本。

### 4.2 Debian 12 ARM64 与依赖

- ROCK 4B+ 的 Debian、ARM64、Python 和 glibc 核对；
- PySide6 ARM64 wheel 与 Debian 12 glibc 不兼容的问题；
- 采用 Debian 官方 PyQt6、QtSerialPort 和 PyQtGraph；
- apt 系统包与 `venv --system-site-packages` 的职责边界；
- 为什么本项目没有采用 Qt 交叉编译或自行编译 PySide6。

### 4.3 图形会话与启动

- SSH Shell 中 `DISPLAY` 为空导致 Qt `xcb` 无法连接显示；
- 板端桌面会话负责显示 GUI，SSH 负责诊断命令；
- 桌面快捷方式、应用菜单和 `run.sh` 的不同用途；
- 启动日志位置和 `tail` 排查方法；
- `QT_QPA_PLATFORM=offscreen` 仅用于无界面测试和基准，不是日常 GUI 启动方式。

### 4.4 USB、设备身份和权限

- `1a86:fe0c` 只标识一类候选设备，不唯一代表某台物理光谱仪；
- VID:PID 初筛、协议握手确认、生产序列号区分的三层身份模型；
- `/dev/ttyACM*` 可能重新编号；
- `cdc_acm`、`dialout`、udev 规则和普通用户运行；
- 不使用所有设备共享的唯一软链接；
- 不使用宽泛的 `MODE="0666"`。

### 4.5 串口协议与重新同步

- 普通帧和 `0x80` 数据帧的长度定义不能混用；
- U16LE 与 U32LE 包号格式兼容；
- U16BE 像素解析；
- 实机 U16 格式中 CheckSum 不计入 `nLength`；
- 新版 U32 格式的长度语义；
- 数据帧 CheckSum 为任意值并消费但不比较；
- 使用单帧串口记录验证协议歧义；
- 限制候选命令、长度和像素数，损坏后逐字节重新同步；
- 控制 ACK 不能受显示节流影响。

### 4.6 数据完整性与性能分层

- 区分原始字节、完整解析帧、持久化帧、显示发布帧和 GUI 实际绘制帧；
- 为什么 4 FPS 绘图不等于设备只发送 4 FPS；
- 为什么显示抽帧造成的包号跨度不能报告为真实缺帧；
- 采集子进程作为完整帧和序号诊断的权威来源；
- GUI 队列容量为 1，只覆盖旧显示帧；
- 每个合法完整帧先进入顺序追加缓存，再进入显示旁路；
- MCU 未发送或 USB 层已丢失的数据不在上位机保证范围内。

### 4.7 GUI 绘图瓶颈

- 使用 `top -H` 区分主线程、Qt 线程和采集进程负载；
- 使用离屏基准区分曲线算法成本与真实 X11 绘制成本；
- 切换实时页和诊断页比较 CPU 与卡顿；
- 旧 QPainter 后端大量 Python `QPointF` 分配导致单核瓶颈；
- PyQtGraph、NumPy 连续数组、`setData()` 复用、`clipToView` 和
  `peak` 降采样；
- 不启用未经实机验证的 OpenGL；
- 依据 CPU、温度和实际绘制事件逐步选择 20、25 或 30 FPS；
- 本项目最终采用 25 FPS 目标，实机约 22 FPS。

### 4.8 自动保存与存储隔离

- GUI 进程同步生成 CSV/Excel 导致界面越来越卡和停止耗时；
- 独立采集进程、顺序追加 spool、独立导出进程的职责；
- 停止设备优先于 Excel 收尾；
- 显示处理可以丢弃旧帧，存储处理不能跳过完整持久化帧；
- 处理快照在采集开始时冻结；
- 背景、参考、强度校准、处理模式和 airPLS 的一致处理链；
- 不能用简单强度阈值删除暗光谱、饱和光谱或扣背景结果；
- 结构错误拒绝，可疑数据保留并诊断。

### 4.9 `.part/.zgs` 生命周期

- 临时文件是采集期间的数据事实来源，不是默认用户输出；
- 正常停止且未启用自动存储时删除；
- 自动导出全部成功且帧数一致后删除；
- ACK、串口、磁盘、计数、导出或清理异常时保留；
- 正常输出列表只报告 CSV/XLSX，恢复文件使用独立语义。

### 4.10 诊断飞行记录器

- 结构化记录通信、解析、持久化、显示和系统负载时间线；
- 1 Hz 系统采样和有界诊断队列；
- 默认不复制完整光谱；
- 可选最近 10 帧样本；
- ZIP 成员清单、哈希和原子发布；
- 用诊断包区分 MCU、USB、解析、存储和显示问题。

### 4.11 SSH、SCP 和现场操作

- `ssh` 用于进入板端执行 Linux 命令；
- `scp` 的本地源路径命令必须在 Windows PowerShell 执行；
- Windows 路径、反斜杠续行不能放入板端 Bash；
- `cd` 的目标必须是目录，不能进入 `install.sh` 文件；
- 含中文、空格和结尾反斜杠的路径需要正确引用；
- 传输、安装、运行和下载诊断包使用不同命令模板。

### 4.12 部署和一致性

- `/opt/zgcai-spectrometer` 是系统级程序安装目录；
- 配置、日志和数据保留在普通用户目录；
- 安装脚本负责环境检查、apt、venv、udev、`dialout` 和桌面入口；
- `deploy/rock4bplus` 由构建工具生成；
- 自动检查运行源码与部署副本一致；
- 部署包排除测试、文档、数据、Windows 打包文件和开发 venv。

### 4.13 未采用方案

案例手册明确记录以下方案没有成为最终方案的原因：

- 仅放宽或关闭普通帧校验；
- 一遇校验错误就重开串口；
- 用强度阈值直接删除异常帧；
- 只隐藏缺帧日志；
- GUI 主进程同步保存 Excel；
- 只调低显示 FPS；
- 为 Debian 12 盲目交叉编译完整 Qt/PySide6；
- 在未经验证的 Mali 驱动上直接启用 OpenGL；
- 用公共 VID:PID 或 `/dev/ttyACM0` 作为永久设备身份；
- 始终把 `.zgs` 当作正常用户输出。

## 5. 技能运行流程

调用 `$rock4bplus-migration` 后按以下阶段执行。

### 阶段 0：保护边界

- 确认源项目、迁移副本和目标板；
- 确认禁止修改目录；
- 检查 Git 状态和用户未提交文件；
- 明确本次允许的写入、安装和远程操作；
- 建立原始行为和测试基线。

### 阶段 1：项目盘点

- 识别入口、依赖、平台 API、文件路径、线程/进程和硬件接口；
- 识别编译型依赖及 ARM64 可用性；
- 画出业务、设备、显示、存储和部署边界；
- 记录需要实机才能验证的项目。

### 阶段 2：ROCK 4B+ 环境核对

- Debian、架构、Python、glibc 和桌面环境；
- apt 与 pip/venv 依赖；
- Qt 绑定和平台插件；
- USB 驱动、权限和设备节点；
- 屏幕分辨率、磁盘、内存和温度。

### 阶段 3：迁移设计

- 比较复用、适配、替换和重写方案；
- 优先使用 Debian 官方 ARM64 包；
- 明确数据完整性和性能保证边界；
- 设计部署目录、安装、运行、回退和诊断；
- 获得用户确认后才实施。

### 阶段 4：实施

- 使用失败测试先覆盖兼容点；
- 小步修改并保留清晰组件边界；
- 平台差异集中在适配层；
- 不进行与迁移无关的重构；
- 运行源码和部署副本通过构建工具同步。

### 阶段 5：分层验证

验证顺序固定为：

```text
静态检查
→ 自动测试
→ 无硬件模拟
→ 板端依赖自检
→ 单功能硬件探针
→ 正式 GUI 实机
→ 长时间采集
→ 自动保存
→ 停止和尾帧
→ 断线重连
→ 故障恢复
```

### 阶段 6：证据驱动诊断

遇到问题先判断它位于：

- 环境和依赖；
- 图形会话；
- USB/驱动/权限；
- 协议拆包；
- 控制 ACK；
- 全量持久化；
- 数据处理；
- GUI 显示；
- 导出；
- 部署操作。

只有确定层级后才修改对应组件，避免同时改协议、绘图和存储而无法判断效果。

### 阶段 7：交付

- 生成最小板端部署包；
- 给出明确的电脑端和板端命令；
- 提交自动测试和实机结果；
- 记录已知限制与回退方法；
- 用复盘模板沉淀新问题；
- 仅将跨项目有效的结论提升到个人技能。

## 7. 安全和错误处理

技能必须执行以下规则：

- 未确认工作区边界前不修改文件；
- 未确认用户已有修改前不进行批量暂存或覆盖；
- 未获得安装授权前不改变板端系统包、udev 或用户组；
- 不把串口可打开当作设备握手成功；
- 不把显示 FPS 当作采集 FPS；
- 不把序号跳变单独当作当前帧内容错误；
- 不伪造 ACK，不静默吞掉超时；
- 不以丢弃完整帧换取界面流畅；
- 不在 GUI 主线程执行大型导出；
- 不把临时恢复文件当作正常完成输出；
- 不声称能恢复 MCU 未发送或 USB 层已丢失的数据；
- 不在自动测试通过后跳过实机验收；
- 不在新项目中直接套用 CH569W 专用协议结论。

若证据不足，技能应输出需要追加的最小探针和预期判别结果，而不是同时修改
多个子系统。

## 8. 验收矩阵

每次迁移至少从五个维度验收。

### 8.1 功能

- 正常启动；
- 核心业务；
- 硬件发现与控制；
- 文件输入输出；
- 退出和资源释放。

### 8.2 性能

- CPU；
- 内存；
- 温度；
- GUI 响应；
- 输入、处理、持久化和显示速率。

### 8.3 完整性

- 输入记录数；
- 解析成功数；
- 持久化数；
- 最终输出数；
- 缺失、重复、乱序和拒绝计数。

### 8.4 恢复

- 无设备启动；
- 设备拔插；
- 进程异常；
- 磁盘和导出失败；
- 临时文件恢复；
- 重启后的配置和身份恢复。

### 8.5 部署

- 全新系统安装；
- 重复安装幂等；
- 普通用户运行；
- 桌面和命令行入口；
- 升级与回退；
- 部署包无开发文件和用户数据。

每个验收项记录命令、环境、预期、实际结果、证据路径和是否通过。

## 9. 持续学习

新迁移项目发现问题时：

1. 先使用 `incident-retrospective.md` 在该项目记录事实；
2. 区分设备专用结论和 ROCK 4B+ 通用结论；
3. 只有在自动测试或实机证据支持后，才更新技能源；
4. 更新后运行结构、自包含性和路径检查；
5. 重新安装到个人技能目录；
6. 在一个非光谱仪项目中进行最小调用验证；
7. 记录技能版本和变更摘要。

项目案例手册可以持续增长，但技能主文件必须保持简洁。详细新知识进入对应
参考文件，只有新的阶段门禁或高价值决策规则进入 `SKILL.md`。
