本文档取代上一代 STM32/TMC2209 运行方案中的电机通信、轴数、限位和位置实现。上一代方案及其代码仍作为历史回退资料保留，不参与新版本运行。

## 2. 背景与目标

现有“光谱仪 - Linux转移版”已经在 Radxa ROCK 4B+（Debian 12 Bookworm ARM64）上完成光谱仪控制和数据采集迁移。电机用于为光谱采集提供 X/Y 矩阵扫描能力，软件名称和主要性质仍保持为光谱仪采集软件。

电机驱动板由 STM32/TMC2209 更换为 LK-MD2202。LK-MD2202 本身提供两轴驱动、Modbus-RTU 通信、相对/绝对位置控制、运行状态、位置计数、零点限位和复位回零，因此新架构由 ROCK 4B+ 通过 USB 转 RS-485 直接控制驱动板，不再让 STM32 参与电机控制。

本次目标：

1. 在不改变现有光谱仪控制逻辑的前提下，把 LK-MD2202 两轴控制嵌入现有 PyQt6 软件；
2. 支持 X/M1、Y/M2 自动识别、连接、参数配置、速度、相对移动、停止、软件坐标、机械回零和限位状态；
3. 保留已经确认的蛇形扫描与光谱仪连续采集总控；
4. 在 ROCK 4B+ 上提供可靠的串口识别、权限配置、诊断、部署和实机验收流程；
5. 通过 Git 分支、标签和分阶段提交保证原光谱仪版本及上一代电机方案可回退。

## 3. 范围与非目标

### 3.1 本次实现

- LK-MD2202 Modbus-RTU 主站通信；
- USB 转 RS-485 自动识别和手动通信设置；
- 仅 X/M1、Y/M2 两轴；
- 两轴参数读取、差异显示、写入和回读校验；
- 两轴速度设置和指定距离正反向运动；
- 零点限位状态和单轴/双轴机械回零；
- 软件坐标清零和软件回零；
- X/Y 蛇形矩阵扫描；
- 扫描期间光谱仪连续采集、分轮保存和任务清单；
- 未回零扫描风险确认，但不强制回零；
- ROCK 4B+ 部署、诊断、自动化测试和实机验收。

### 3.2 明确不实现

- Z 轴；
- STM32 电机控制固件的新开发、编译、烧录或部署；
- TMC2209 运行时控制；
- 激光器控制和任何激光器联动；
- 旧上位机中的“数据处理”功能；
- Tkinter 或 Matplotlib 界面；
- 对现有光谱仪识别、参数、采集、保存和诊断协议的重构；
- 根据步进脉冲推断机械卡滞或真实位置闭环。LK-MD2202 与步进电机仍是开环系统。

## 4. 已确认的关键决策

1. 连接链路为 `ROCK 4B+ -> USB转RS-485 -> LK-MD2202`；
2. 上位机继续使用 PyQt6，串口层采用 `QSerialPort + QThread`；
3. 项目内实现精简、可测试的 Modbus-RTU 编解码和事务队列，不新增 `pymodbus` 依赖；
4. X 对应 M1，Y 对应 M2，运行时不再保留 Z 轴；
5. X、Y 行程均为 15 mm，终点均为 4800 pulse，换算均为 320 pulse/mm；
6. 限位模式固定为零点限位，纯开关量限位闭合接地；
7. 驱动板每次连接时读取实际配置，不自动覆盖硬件；
8. 用户点击“应用到驱动板”后才写寄存器，并执行回读校验；
9. 未机械回零时不禁用手动运动和扫描；启动扫描前弹出风险确认；
10. 支持 X/Y 软件方向反转，默认关闭；
11. 原光谱仪软件及其控制逻辑保留；旧 TMC2209 工程保留为 `legacy` 回退资料。

## 5. 总体架构

```text
PyQt6 主界面
  |-- 光谱仪现有控制与采集（逻辑冻结）
  |-- 电机控制器
  |     |-- LK-MD2202 设备语义适配层
  |     |-- Modbus-RTU 编解码/CRC
  |     `-- QSerialPort 单事务工作线程
  `-- 扫描+采集总控
        |-- 调用电机控制器执行扫描子步
        `-- 调用现有 AcquisitionController 启停连续采集

ROCK 4B+ USB
  `-- USB转RS-485
        `-- LK-MD2202
              |-- M1 -> X轴
              |-- M2 -> Y轴
              |-- M1-K -> X零点开关 -> GND
              `-- M2-K -> Y零点开关 -> GND
```

架构边界：

- `MainWindow` 只负责组装对象和连接 Qt 信号，不承载 Modbus、位置换算或扫描算法；
- 扫描计划保持纯数据和纯算法，可脱离串口及界面测试；
- 电机控制器只暴露轴、毫米、速度、回零和状态等业务语义；
- LK-MD2202 适配层负责寄存器地址、数据类型、字节序和动作命令；
- 串口工作线程严格串行执行事务，界面线程不得同步等待串口；
- 光谱仪控制器不感知 Modbus 寄存器或驱动板实现。

## 6. 硬件连接与电气边界

### 6.1 通信

- 驱动板电机供电：按 LK-MD2202 说明书使用 DC 5～12 V，并根据电机规格选定最终电压；
- ROCK 4B+ 通过隔离或可靠的 USB 转 RS-485 模块接入 A/B 总线；
- RS-485 A/B 极性、公共参考地、终端电阻和线缆屏蔽在实机阶段核对；
- 默认通信参数为地址 1、9600 baud、8 数据位、1 停止位、无校验；
- Linux 优先使用 `/dev/serial/by-id/` 稳定路径，不把 `/dev/ttyUSB0` 固化为设备身份。

### 6.2 两轴与限位

| 软件轴 | 驱动通道 | 零点输入 | 开关接法 |
|---|---|---|---|
| X | M1 | M1-K | 开关闭合时 M1-K 接 GND |
| Y | M2 | M2-K | 开关闭合时 M2-K 接 GND |

LK-MD2202 每轴只有一个零点输入。零点开关触发后，由驱动板停止该轴朝零点方向的运动，并只允许反方向离开。正向终点主要依赖回零后的 4800 pulse 终点参数；未回零时不能把正向终点保护视为已验证。

上位机的“方向反转”只改变普通相对运动和扫描的逻辑方向，不能改变 LK-MD2202 内部复位回零命令的搜索方向。电机相线和机构安装必须保证驱动板执行复位时实际朝零点开关移动；首次回零只能在低速、可立即断电的条件下验证。

### 6.3 电流注意事项

用户确认的软件默认运行电流为 50%。说明书不同章节对单轴最大输出电流的表述存在差异，因此 50% 的实际相电流、驱动板温升和电机温升必须在实机验收中测量，不能只根据百分比推断。

## 7. LK-MD2202 参数模型

### 7.1 用户确认的默认值

| 参数 | X/M1 | Y/M2 | 说明 |
|---|---:|---:|---|
| 步距角寄存器 | 1.8° | 1.8° | 编码 0 |
| 细分 | 8 | 8 | 编码 3 |
| 运行电流 | 50% | 50% | 编码 4 |
| 限位模式 | 零点限位 | 零点限位 | 编码 1，界面固定不可改 |
| 终点位置 | 4800 pulse | 4800 pulse | 15 mm |
| 停止电流 | 无锁定 | 无锁定 | 编码 0 |
| 加速参数 | 10000 | 10000 | 驱动板原始参数 |
| 减速参数 | 10000 | 10000 | 驱动板原始参数 |
| 位置速度 | 10000 pps | 10000 pps | 脉冲频率 |
| 软件方向反转 | 关闭 | 关闭 | 仅保存在上位机 |

机械常量：

```text
travel_mm = 15
end_position_pulses = 4800
pulses_per_mm = 4800 / 15 = 320
minimum_move_mm = 1 / 320 = 0.003125
```

步距角、细分、终点脉冲和 320 pulse/mm 必须作为一组配置校验。若未来修改步距角或细分，界面必须提示重新确认终点脉冲与毫米换算，不能悄悄继续使用不匹配的 320 pulse/mm。

### 7.2 主要寄存器映射

| 语义 | M1/X | M2/Y | 类型/操作 |
|---|---:|---:|---|
| 步距角 | 0x0010 | 0x0030 | uint16 R/W |
| 细分 | 0x0011 | 0x0031 | uint16 R/W |
| 运行电流 | 0x0012 | 0x0032 | uint16 R/W |
| 限位模式 | 0x0013 | 0x0033 | uint16 R/W |
| 终点位置 | 0x0014/15 | 0x0034/35 | uint32 R/W |
| 停止电流 | 0x0019 | 0x0039 | uint16 R/W |
| 加速参数 | 0x001A | 0x003A | uint16 R/W |
| 减速参数 | 0x001B | 0x003B | uint16 R/W |
| 位置速度 | 0x001E/1F | 0x003E/3F | uint32 R/W |
| 相对位置运动 | 0x0020/21 | 0x0040/41 | int32 W |
| 绝对位置运动 | 0x0022/23 | 0x0042/43 | int32 W，首版不作为主要入口 |
| 停止 | 0x0024 | 0x0044 | uint16 W |
| 复位回零 | 0x0025 | 0x0045 | 写 1 |
| 限位状态 | 0x0026 | 0x0046 | uint16 R |
| 运行状态 | 0x0027 | 0x0047 | uint16 R |
| 当前位置 | 0x0028/29 | 0x0048/49 | int32 R |

通信设置寄存器包括设备地址 0x0050 和波特率 0x0051。数据位、停止位和校验寄存器首版只读取并要求为 8N1、无校验，不在普通界面中开放，以减少设备失联风险。

## 8. Modbus-RTU 通信设计

### 8.1 支持功能码

- `0x03`：读保持寄存器；
- `0x06`：写单个寄存器；
- `0x10`：写多个连续寄存器；
- 异常响应：识别功能码最高位置位和异常码；
- CRC16-Modbus：发送及接收均为低字节在前、高字节在后。

32 位参数必须在一个位置集中定义“高寄存器/低寄存器”和带符号转换，禁止业务代码自行拼接。

32 位动作参数必须使用一次 `0x10` 多寄存器写入同时提交高、低寄存器，禁止用两个独立 `0x06` 请求分开写入，以免出现半更新或提前触发运动。

### 8.2 事务队列

每个事务包含：

- 设备地址；
- 请求帧；
- 期望功能码和长度；
- 超时；
- 是否允许重试；
- 业务标签和操作 ID；
- 成功、设备异常、协议错误、超时和连接丢失结果。

任意时刻只有一个在途事务。串口工作线程负责接收缓冲、帧完整性判断、CRC 校验、超时和结果派发。界面线程只接收 Qt 信号。

### 8.3 重试规则

| 操作 | 自动重试 | 原因 |
|---|---|---|
| 身份、状态、配置读取 | 最多 2 次 | 只读、幂等 |
| 参数写入 | 超时后先读回，不盲目重发 | 写入可能已经成功 |
| 相对移动 | 禁止 | 重发会造成重复位移 |
| 回零 | 禁止 | 重发可能改变运动时序 |
| 停止 | 允许再次发送 | 幂等安全动作 |

动作写入超时后，控制器进入“结果未知”状态，读取运行状态和位置并要求用户确认，不能把超时直接解释为动作未执行。

### 8.4 自动识别

识别顺序：

1. 排除光谱仪当前占用或保留的串口；
2. 优先尝试上次成功的 `/dev/serial/by-id/`、地址和波特率；
3. 再尝试候选 USB 串口和出厂通信参数地址 1、9600 baud；
4. 发送只读身份/版本寄存器请求；
5. 校验响应地址、功能码、长度、CRC 和设备特征；
6. 只有验证通过的端口才显示为 LK-MD2202。

自动识别不得发送配置写入、运动、停止或回零命令。若设备使用非默认地址或波特率且没有保存记录，用户通过设置弹窗手工指定。

### 8.5 断线处理

- 普通空闲状态断线：标记未连接，保留最后一次状态但显示为过期；
- 手动运动中断线：动作结果未知，不自动重连并补发；
- 扫描中断线：立即请求停止光谱仪采集，扫描标记故障，不自动返回起点；
- 重新连接后：读取配置、运行状态、限位和位置，坐标状态保守地标记为“未校准”，直到用户重新确认或机械回零。

## 9. 坐标与运动模型

### 9.1 三类位置

1. **驱动器位置**：从位置寄存器读取的带符号脉冲计数；
2. **机械坐标**：完成机械回零后可信的 0～15 mm 坐标；
3. **软件坐标**：`驱动器位置 / 320 - 软件零点偏移`。

软件零点可以在任意位置设置，所以软件坐标允许为负数。软件坐标不得用于绕过已知机械坐标的 0～15 mm 行程保护。

### 9.2 坐标操作

- 软件清零：记录当前驱动器位置为软件零点，不写 LK-MD2202 位置寄存器；
- 软件回零：按软件坐标计算相对位移回到软件 0 点；
- 机械回零：向相应轴写复位回零命令，等待空闲、限位/位置状态符合预期，再把机械和软件坐标设为 0；
- 全部回零：按顺序执行 X、Y，任一轴失败即停止后续回零；
- 软件零点偏移不作为掉电后的绝对机械位置依据。

### 9.3 未回零策略

用户明确要求：不强制回零，不因未回零禁用手动运动或扫描。

- 未回零时显示“坐标未校准”；
- 手动运动允许执行；
- 扫描启动前显示一次风险确认，用户确认后允许执行；
- 未校准扫描只验证矩阵自身 `x <= 15`、`y*n <= 15`，无法验证矩阵相对于实际起点是否越界；
- 若驱动板拒绝未回零的位置命令，显示设备错误，不自动回零；
- 完成回零后才启用基于当前机械坐标的目标范围检查。

### 9.4 距离与方向

- 毫米距离按 320 pulse/mm 转换并四舍五入到最近整脉冲；
- 零距离或小于 1 pulse 的有效距离拒绝执行；
- 界面显示量化后的实际执行距离；
- X/Y 软件方向反转仅在“软件正负方向 -> 驱动器脉冲符号”映射层生效；
- 所有手动和扫描移动使用相对位置寄存器，位置速度由相应轴配置提供；
- 每次运动完成后读取运行状态、限位状态和当前位置；
- 报告位置增量与目标脉冲不一致时进入故障状态。

零点限位只在以下情况视为预期到位：显式机械回零，或机械坐标已校准且本次负向运动目标恰好为 0。此时仍需确认最终位置为 0。未校准运动触发限位、目标大于 0 时触发限位、非运动轴触发限位或位置读回异常均视为故障。因此，已从机械零点开始的蛇形扫描在 X 轴反向准确回到 0 时，可以正常完成该段，而不是被误判为扫描故障。

步进电机卡住但驱动器仍正常计数时，上位机无法检测实际丢步。这一限制必须写入用户说明。故障恢复流程为：停止、人工排除机械卡滞、执行机械回零。

## 10. 扫描与光谱仪联动

### 10.1 参数

| 参数 | 含义 | 默认/约束 |
|---|---|---|
| `x_mm` | X 轴完整行程 | `0 < x <= 15` |
| `y_mm` | 每个 Y 行程距离 | `0 < y` 且 `y*n <= 15` |
| `line_count` (`n`) | Y 行程数 | 正整数 |
| `scan_count` (`m`) | 完整矩阵重复次数 | 正整数 |
| `x_steps` (`sx`) | 一个 X 完整行程的子步数 | 默认 1，正整数 |
| `y_steps` (`sy`) | 一个 Y 行程的子步数 | 默认 1，正整数 |
| `dwell_seconds` (`t`) | 相邻扫描子步之间等待 | 默认 0，非负数 |

每个 X/Y 子步换算后必须至少包含 1 pulse。

### 10.2 单轮蛇形顺序

单轮从当前起点开始：

1. 启动选定光谱仪的连续采集；
2. X 正向运行 `x`，拆分为 `sx` 个等脉冲子步；
3. Y 正向运行 `y`，拆分为 `sy` 个等脉冲子步；
4. X 反向运行 `x`；
5. 继续交替，直到 Y 完成 `n` 个行程；
6. X 再完成最后一个完整行程；
7. 单轮合计 X 完整行程 `n+1` 次，Y 完整行程 `n` 次；
8. 停止并保存本轮光谱仪采集；
9. 不采集地先将 X、再将 Y 返回本轮起点；
10. 返回成功后开始下一轮。

步时语义：首个子步立即开始；每两个相邻扫描子步之间等待一次 `t`。轴切换处也是一次等待，不额外叠加。最后一个扫描子步完成后不再等待，直接停止本轮采集。返回起点不拆分子步且不应用扫描步时。

### 10.3 示例验收计数

输入：

```text
x=10 mm, y=1 mm, n=10, m=2,
sx=10, sy=2, t=1 s
```

每轮：

- X 完整行程 11 次，X 子步 `11*10=110` 次；
- Y 完整行程 10 次，Y 子步 `10*2=20` 次；
- 扫描子步总数 130；
- 相邻子步等待 129 次；
- 扫描结束后返回本轮起点。

两轮总计 X 子步 220 次、Y 子步 40 次，并产生两轮独立的采集任务和文件记录。

### 10.4 停止和故障

用户停止、串口断开、光谱仪失败、设备异常、位置增量异常或扫描中意外触发零点限位时：

1. 停止等待定时器；
2. 向 M1、M2 请求立即停止；
3. 停止光谱仪扫描采集；
4. 将任务记录为 stopped 或 faulted；
5. 不自动返回起点；
6. 不自动重发未确认的运动命令。

### 11.3 配置写入流程

1. 要求设备已连接且两轴空闲、扫描未运行；
2. 读取并保存完整配置快照；
3. 校验字段范围和跨字段一致性；
4. 显示修改前后差异；
5. 只写用户实际修改的寄存器；32 位字段使用单个连续寄存器块原子提交。若实现采用较大的读改写块，必须从本次快照保留所有未在界面暴露的寄存器值，禁止用软件默认值覆盖隐藏字段；
6. 读回整块并逐字段比较；
7. 最后修改地址或波特率；
8. 使用新参数重新打开串口并验证设备身份；
9. 成功后保存主机侧连接参数和方向反转；
10. 失败时列出成功、失败和未知字段，尝试恢复快照并给出人工恢复步骤。

界面只有全部要求字段回读一致时才显示“应用成功”。

## 12. 错误、日志与诊断

用户可见错误使用中文，并附可复制的技术详情：

- 串口不存在、被占用或权限不足；
- 地址、功能码、长度或 CRC 不匹配；
- Modbus 异常响应及异常码；
- 响应超时；
- 写动作结果未知；
- 未回零位置命令被驱动板拒绝；
- 意外限位；
- 位置读回不一致；
- 扫描过程中电机或光谱仪断开；
- 参数写入后回读不一致。

诊断事件至少记录：

- 时间、端口稳定路径、设备地址和波特率；
- 请求类型、寄存器范围、操作 ID 和耗时；
- 接收长度、CRC/协议结论和设备异常码；
- 运动目标脉冲、开始/结束位置、限位和运行状态；
- 扫描参数、轮次、子步、采集任务 ID、输出文件和停止原因；
- 配置快照与差异。

默认日志不需要持续输出完整串口十六进制帧；诊断模式可开启受控的十六进制帧记录，并受现有诊断保留策略约束。

## 14. ROCK 4B+ 部署

- 使用系统 PyQt6/项目现有 Qt 运行环境，不新增 Tkinter、Matplotlib 或额外 Modbus GUI 依赖；
- 确认 USB-RS485 芯片在 Debian 12 ARM64 下对应内核驱动可用；
- 将运行用户加入 `dialout`，或使用最小权限 udev 规则授权目标 USB 串口；
- udev 规则按实际 VID/PID/序列号约束，不对全部 tty 设备放宽权限；
- 记录 `/dev/serial/by-id/`、USB 拓扑、驱动模块和串口权限；
- 部署包不包含旧 STM32 构建产物；
- 启动自检只读设备，不自动写参数或运动。

## 17. 已知风险与实施约束

1. LK-MD2202 是开环步进系统，寄存器位置不等于机械位置闭环；机械卡滞只能通过人工检查和机械回零恢复；
2. 用户选择未回零也可扫描，因此未校准状态下软件不能保证实际矩阵不越界，必须保留风险确认；
3. 说明书对最大电流和部分速度单位的表述存在不一致，首台实机必须低速、限流验证；
4. USB-RS485 自动收发方向和驱动兼容性取决于实际适配器，实机前不能宣称通信验收完成；
5. 修改地址或波特率可能造成设备暂时失联，必须最后写入并具备旧值/出厂值恢复路径；
6. 不得通过修改现有光谱仪控制逻辑来简化电机联动；
7. 用户工作区已有未提交文档和数据，实施期间不得暂存、移动、删除或覆盖。
