# LK-MD2202 扫描流畅度与联动隔离优化设计

- 日期：2026-08-18
- 状态：设计方向已确认，等待书面规格复核
- 依据：ROCK 4B+ 实机诊断包 `004.zip`、`005.zip`
- 范围：零步时子步执行、电机 Modbus 线程边界、多轮联动诊断包关联

## 1. 目标与约束

本轮解决两类已被实机证据区分的问题：

1. X/Y 被分成多个子步且步时为 0 时，每个短位置命令仍需独立完成至少 200 ms
   的预测观察，并可能经历 Modbus 应答超时、状态确认和同目标重发，造成明显且不等长
   的停顿。
2. 光谱仪以 10 ms 积分时间高速采集时，首次联动扫描比后续轮次卡顿；当前串口对象
   虽在专用线程，但事务队列、应答解析和超时计时仍在 GUI 主线程，可能受到首次绘图、
   处理和诊断负载影响。

必须保持：

- 原矩形蛇形路径、`n+1` 次 X 行程、`n` 次 Y 行程、扫描次数和轮末返回；
- 步时大于 0 时严格保留用户配置的全部子步和每步等待；
- 光谱仪采集、持久化、处理、绘图和导出控制逻辑不变；
- 扫描最终段、双轴终点、返回、限位、急停和故障仍使用严格校验；
- 不降低 80 ms 预测余量、200 ms 最短预测段或现有协议校验；
- 不创建独立扫描日志文件，继续使用现有诊断记录器和 ZIP。

## 2. 实机证据

`005.zip` 中五轮纯电机扫描每轮约 10.3～10.8 s；五轮光谱仪联动扫描依次约
25.0、23.7、20.8、19.9、20.1 s，具有明显首轮预热特征。

X 轴 10 步、步时 0 的联动扫描包含 119 个预测段：

- 相邻段的软件推进间隔平均 1.58 ms，最大 5.48 ms；
- 1 mm 预测段耗时约 205～488 ms，不均匀不来自步时定时器；
- 发生 23 次写入应答超时、21 次确认未执行后的同目标重发、27 次状态读取失败；
- 正常 X 子段平均约 237 ms，重发段约 347 ms，重发并读取失败时约 445 ms。

同一轮光谱仪以约 89.6 帧/s 完整接收并持久化，`3086 == 3086`，缺帧、错误帧和
重新同步均为 0。因此优化不得改变全量数据主通道。

## 3. 方案比较与选择

### 3.1 方案 A：执行合并 + 电机事务线程隔离（采用）

步时为 0 时，将同一轴、同一方向、同一完整行程内的连续子步合并为一个驱动器
位置命令；同时把 Modbus 队列、响应缓冲、解析、超时和重试全部放入电机专用线程。

优点：直接消除无等待子步的反复启停和大多数串口事务；光谱仪 GUI 负载不再使电机
应答产生主线程假超时；不改变非零步时语义和光谱仪数据路径。

### 3.2 方案 B：保留所有子命令并增加固定间隔或超时

实现简单，但会把 0 步时变成隐藏等待；增加 ACK 超时还会放大真正丢应答时的停顿，
不能解决 GUI 主线程与电机事务耦合，因此不采用。

### 3.3 方案 C：扫描期间降低光谱仪显示帧率或增加预热等待

可以减轻首轮负载，但会改变光谱仪显示体验并引入额外采集前数据；它只缓解现象，
不修复电机事务线程边界，因此不作为本轮主方案。

## 4. 零步时执行合并

### 4.1 语义

`x_steps`、`y_steps`描述的是行程的逻辑细分；`dwell_seconds`描述子步后的明确等待。
当步时严格等于 0 时，连续同轴同方向子步之间没有业务动作、采集触发或等待要求，
因此允许在生成执行计划时合并为一个物理位置命令。

示例：`X=10 mm, X步数=10, 步时=0`仍记录用户配置为 10 步，但每条完整 X 行程
只发送一次 3200 pulse 命令。`步时=0.1 s`时仍发送 10 个 320 pulse 命令，并在每个
子步完成后等待 100 ms。

### 4.2 规则

1. 只在 `dwell_seconds == 0.0` 时合并。
2. 只合并同一完整 X 或 Y 行程内部的子步，不跨轴、不跨方向、不跨蛇形行程边界。
3. 合并后的脉冲总数必须与原整数拆分之和完全相等。
4. 扫描参数、清单和开始事件继续保存用户输入的 X/Y 步数。
5. 执行事件增加逻辑子步数或合并标记，便于诊断说明执行命令为何少于逻辑步数。
6. 每轮最后一个执行命令仍为严格最终段；返回仍为严格返回。
7. `MAX_SCAN_MOVES`按实际执行命令限制，同时保留每个逻辑子步至少 1 pulse 的输入校验。

## 5. 完整 Modbus 事务线程隔离

### 5.1 当前问题

`MotorSerialWorker`和 `QSerialPort`当前在专用 `QThread`，但
`MotorSerialTransport`的事务队列、`ModbusResponseBuffer`、响应验证和 `QTimer`仍属于
GUI 主线程。串口线程收到字节后需要排队回到主线程；首次高速绘图或处理较忙时，
60 ms超时事件可能先于已到达的字节处理事件执行。

### 5.2 新边界

新增内部事务工作对象，由它在同一电机线程中独占：

- `QSerialPort`；
- 请求队列和活动事务；
- Modbus 响应缓冲与严格解析；
- 单事务超时定时器；
- 读请求重试、动作结果未知和紧急停止队列。

`MotorSerialTransport`保留为 GUI/控制器线程中的兼容门面，只负责：

- 通过 queued signal 提交打开、关闭、普通请求和紧急停止；
- 接收并原样转发连接、完成、失败和诊断信号；
- 保存只读连接摘要，不解析协议、不运行事务计时器。

所有现有公开调用方式、标签对象、错误原因和单事务顺序保持兼容。普通请求、扫描请求、
机械回零、脱离卡死和急停继续共用同一有序队列，不允许两个线程同时操作串口。

### 5.3 停止与故障

- 断开时在事务线程停止计时器、失败当前及排队事务、清空缓冲并关闭串口；
- 紧急停止在事务线程清除普通事务后按现有顺序提交两轴停止；
- 明确 Modbus 异常和协议错误不自动重发动作；
- 动作应答超时仍报告 `result_unknown`，由现有扫描绝对目标确认逻辑决定是否重发；
- `shutdown()`有界等待线程退出，超时不阻塞 GUI 永久关闭。

## 6. 多轮联动诊断关联

当前诊断 ZIP按最新 `acquisition_id`过滤。每轮扫描产生新的采集 ID，导致前几轮处于
采集期间的电机段、性能样本和光谱仪摘要被排除，只保留采集结束后的返回段。

修复方式：

1. `ScanController`在每轮 `task_started`后发出一个扫描—采集关联事件，包含
   `scan_id`、`round_number`和 `acquisition_id`。
2. 导出器读取未过滤时间线，根据目标采集 ID找到所属 `scan_id`。
3. 收集同一扫描 ID关联的全部采集 ID。
4. 时间线、性能和帧摘要保留：无采集 ID的全局事件，以及上述全部关联采集 ID事件。
5. 非扫描的普通诊断导出继续只保留目标采集 ID和全局事件。
6. ZIP清单增加 `scan_id`与 `related_acquisition_ids`，不改变现有成员名称。

## 7. 数据流

```text
扫描参数
  -> 计划器
       -> 步时=0：每条完整轴行程一个物理命令
       -> 步时>0：保留全部子步及等待
  -> ScanController（光谱仪总控保持不变）
  -> MotorController（绝对目标、预测、严格最终校验）
  -> MotorSerialTransport 门面
  -> 电机事务线程（队列/串口/解析/超时/重试）
  -> LK-MD2202
```

光谱仪仍在每轮第一段前启动，最终双轴严格校验后停止，保存完成后才执行严格返回。

## 8. 自动测试

### 8.1 扫描计划

- 步时 0、X/Y 步数大于 1 时，每条完整轴行程合并且总脉冲、方向和终点不变；
- 步时大于 0 时，子步数量、整数余数分配和每步等待完全保持；
- 不跨轴、方向和行程边界合并；
- 最后一段无额外步时且保持严格完成语义；
- 校准行程、未校准确认和最大计划限制无回归。

### 8.2 电机传输

- 请求在事务线程按顺序执行，拆分响应和多请求队列正确；
- 超时计时器和响应解析与串口位于同一线程；
- 读请求可按配置重试，动作请求不由传输层重发；
- 断开、协议错误、设备异常、紧急停止和关闭正确失败所有相关事务；
- 主线程短时繁忙时，事务线程仍能解析响应并在期限内停止自己的计时器；
- `own_thread=False`测试模式保持可确定、无需真实串口。

### 8.3 诊断包

- 一个扫描关联多个采集 ID时，全部轮次事件、性能和帧摘要均被导出；
- 目标采集不属于扫描时继续单采集过滤；
- 清单关联字段、SHA-256、脱敏和默认不包含完整光谱数据的规则不变。

### 8.4 回归

运行电机定向测试、完整 `tests/motor`、诊断测试、完整 PyQt6 回归、`compileall`、
部署镜像一致性和部署结构测试。测试不得通过调整安全常量或放宽协议校验。

## 9. ROCK 4B+ 实机验收

1. 更新前逐文件备份并记录 SHA-256，保留当前版本完整回退路径。
2. 纯电机执行五轮 `X步数=10, 步时=0`，确认每条 X 行程连续且路径、终点、返回正确。
3. 执行 `X步数=10, 步时=0.1 s`，确认仍有 10 个独立子步且每步等待存在。
4. 以 10 ms积分时间执行五轮光谱仪联动压力测试。
5. 验收时写入应答超时和同目标重发应显著减少；任何剩余异常必须在诊断包中完整关联。
6. 核对每轮严格终点、返回起点、限位、急停、用户停止和断线恢复。
7. 核对完整帧等于持久化帧，缺帧、错误帧和重新同步为 0。

## 10. 回退与保证边界

部署只替换本轮实际修改的运行文件，更新前复制到新的时间戳备份目录。回退不删除
设置、虚拟环境、光谱数据、诊断包或原光谱仪软件。

合并可以消除步时为 0 的软件分段，但不能改变 LK-MD2202内部加减速曲线；步时大于
0 时，每个位置子命令仍会发生物理减速和再次启动。事务线程隔离可以避免 GUI负载
导致的上位机假超时，但不能恢复驱动板未发送的响应，也不能证明机械系统绝对无丢步；
这些边界继续由严格终点、限位、故障停止和实机验收覆盖。
