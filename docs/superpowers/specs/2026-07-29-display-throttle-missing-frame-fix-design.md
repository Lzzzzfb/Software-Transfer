# ROCK 4B+ 显示节流与缺帧误报修复设计

## 1. 诊断证据

依据实机诊断包
`zgcai-diagnostic-20260729-110659-26ef2abf.zip`：

- 采集约 118 秒，最终封存 10622 个完整帧，约 89.9 FPS。
- 最近周期快照中完整帧与持久化帧均为 10552，二者相等。
- 采集子进程统计：
  - `missing_frames=0`
  - `invalid_headers=0`
  - `resync_count=0`
- 采集子进程发布显示帧约 17.9 FPS。
- 主程序约使用单核 36%，采集子进程约使用单核 17.5%。
- 可用内存约 3 GB，温度约 66～71℃，磁盘剩余约 21 GB。
- 主界面在同一采集中产生 2067 条“检测到缺少帧”日志，其中
  2043 条为“缺少 4 帧”。

因此设备通信、全量解析和持久化正常；缺帧提示来自显示抽帧之后的二次序号判断，是误报。日志风暴、重复显示节流和可见绘图区重绘共同造成 GUI 卡顿。

## 2. 方案比较

### 方案 A：只隐藏缺帧日志

优点是改动最少。缺点是仍保留错误统计和重复显示节流，只掩盖现象，不解决原因。

### 方案 B：只标记显示抽帧数量

在采集子进程发布显示帧时携带主动跳过数量，主界面序号检查可以扣除主动跳过。它能消除多数误报，但主界面仍有第二层 20 FPS 时间门，显示速率仍受两个独立时钟相位影响。

### 方案 C：单一显示节流并明确统计权威边界

保留采集子进程的 20 FPS 发布门，主界面只在自身绘图定时器到期时消费“最新可用帧”，不再执行第二个时间门。同时携带主动跳过数量，使兼容序号检查能够区分抽帧和真实缺口。全量缺帧、拒帧和重同步以采集子进程为权威。

选择方案 C。它直接消除误报和重复节流，不增加高频 IPC，也不改变全量持久化路径。

## 3. 数据流

全量数据路径保持不变：

```text
USB 串口
  -> 采集子进程完整帧解析
  -> 包号连续性检查
  -> 每个完整帧写入 .part/.zgs
```

显示路径调整为：

```text
采集子进程
  -> 最多 20 FPS 发布最新帧
  -> 携带自上次发布以来主动省略的帧数
  -> 主进程最新帧槽
  -> GUI 50 ms 绘图定时器直接取最新帧
  -> QPainter
```

主进程不得再对最新帧槽增加另一个 20 FPS 时间判断。

## 4. 序号与缺帧规则

- 采集子进程继续检查约 90 FPS 全量帧序号，是 Linux 实机缺帧统计的权威来源。
- 每个发布到 GUI 的 `SpectrumFrame` 填写 `intentionally_skipped`：
  表示从上一显示帧到当前显示帧之间，采集子进程主动未发布给 GUI、但已经成功持久化的完整帧数量。
- GUI 兼容序号检查使用：

```text
真实缺口 = 包号差 - 1 - intentionally_skipped
```

- 主动显示抽帧不产生 WARN，不增加缺帧数。
- 若全量序号确有缺口，仍继续按现有健康阈值处理并记录。
- Windows 兼容串口路径继续使用其已有的 `intentionally_skipped` 机制，不改变 Windows 原项目。

## 5. 日志与诊断

- 删除由主动显示抽帧形成的逐帧缺帧日志。
- 真实缺帧事件继续记录，但同一秒重复事件按汇总形式输出，避免信号风暴。
- 诊断飞行记录器新增：
  - GUI 实际处理/绘制 FPS；
  - 当前页签变化；
  - 子进程显示发布 FPS；
  - 主动显示覆盖 FPS。
- 任务结束前，子进程封存结果再次作为最终采集诊断发布，使
  `acquisition-summary.json` 使用最终 10622 等封存计数，而不是停止前一秒的 10552 周期快照。

## 6. 绘图处理

本次先消除已经被证据确认的上游问题：

- 重复 20 FPS 节流；
- 2067 条缺帧误报日志；
- 停止时摘要滞后一秒。

现有曲线按绘图区宽度降采样后交给 QPainter，暂不降低曲线精度或目标 20 FPS。实机复测若 GUI 实际绘制仍低于 15 FPS，再依据新诊断数据单独优化 QPainter 点数、自动量程和重绘区域，避免在缺少证据时牺牲显示质量。

切换到诊断页时，隐藏的绘图区可以不产生实际 paint 事件；采集和全量持久化继续运行。

## 7. 错误处理

- `intentionally_skipped` 必须为非负数，并在每次成功发布显示帧后清零。
- 显示队列覆盖失败不得影响全量帧持久化。
- 主进程绘图来不及消费时只覆盖旧显示帧，不形成采集背压。
- 最终封存诊断发布失败时保留周期快照并记录降级提示，不影响 `.zgs`。

## 8. 测试

自动测试覆盖：

- 90 FPS 输入、20 FPS 发布时，显示帧携带正确主动跳过数量。
- 连续显示帧经过 GUI 序号检查后真实缺帧为 0。
- 人为制造全量包号缺口时仍能得到正确真实缺帧数。
- GUI 绘图定时器每次直接取得最新帧，不受第二个时间门影响。
- 显示队列覆盖不改变完整帧和持久化帧计数。
- 主界面不会为主动抽帧写入缺帧 WARN。
- 最终封存计数覆盖停止前周期快照。
- 诊断包包含 GUI FPS 和页签切换记录。
- 完整回归和 ROCK 4B+ 部署副本一致性检查通过。

## 9. 实机验收

1. 连续采集至少 2 分钟。
2. 诊断页确认完整帧约 90 FPS、持久化帧与完整帧一致。
3. 确认不再持续出现“缺少 4 帧”。
4. 绘图区观察实际 GUI FPS，目标不低于 15 FPS，并记录稳定值。
5. 在绘图区和诊断页之间切换，确认界面均可响应。
6. 停止后确认最终诊断摘要与 `.zgs` 封存帧数相等。
7. 导出新的诊断包，用于决定是否需要下一阶段 QPainter 优化。
