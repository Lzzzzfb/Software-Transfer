# ZGCAI 光谱仪上位机优化与完善设计

日期：2026-07-15
状态：已批准
目标平台：Windows 10/11 64 位

## 1. 背景与目标

现有工程已经具备串口通信、多设备管理、光谱采集、基础处理、绘图和文件导出能力，但协议解析、无损采集、自动存储、同步控制、错误恢复和界面信息架构存在缺陷或缺失。本次工作在保留已验证业务逻辑的基础上，将程序迁移到 PySide6 + Qt Widgets，并按 `软件界面图.png` 的空间结构重建现代工业风格界面。

本次目标：

1. 修复协议解析和设备重连等已确认缺陷。
2. 支持最多约 4 台设备、每台不超过 4096 像素、100 fps。
3. 绘图维持约 30 fps，同时完整保存所有已接收帧。
4. 完善单次、连续、外触发、软同步、硬同步和同步信号相关功能。
5. 完善背景、参考、强度校准、吸光度、自定义公式和 airPLS 处理。
6. 提供可靠的批量 CSV 与多工作表 Excel 输出和异常恢复。
7. 提供清晰、可诊断、适合操作员使用的 Windows 64 位桌面程序。

不在本次范围内：

- Windows 32 位支持。
- TCP/UDP 高速设备和 500–1000 fps 设备适配。
- 移动端、Linux 或 Web 版本。
- 由上位机逐帧产生硬同步脉冲。

## 2. 依据与已确认决策

协议冲突时，以 `CCD_CMOS模块采集卡(下位机)函数表20251027.xlsx` 为准。

已确认的协议例外和保留行为：

- `0x80` 数据帧的 `nLength` 包含校验码。
- `0x80` 的 `nLength = 6 + 2 × nPixel`。
- `0x80` 校验字节包含在回传数据中，但不验证其数值。
- `nPacketNumb` 为 U32，其中高 24 位是帧序号，低 8 位保留。
- 像素 U16 数据高字节在前；其他 U16、U32 和 F32 按小端处理。
- 触发模式为 `0=软件触发、1=软件触发主机、2=外部触发`。
- 当前校准系数的收发反序逻辑已经实机验证，保持不变。
- 硬同步脉冲由下位机自动输出，上位机只负责配置、布防和接收数据；`0x54` 不进入逐帧同步路径。

功能和产品决策：

- 技术路线采用 PySide6 + Qt Widgets，不进行 C# 或 C++ 全面重写。
- 界面采用参考图布局的现代化方案 A。
- 默认批量存储，每批 500 帧，可在 1–1000 帧范围内调整。
- 多设备默认分别存储，合并存储作为可选项。
- 保留 CSV，同时支持 Excel；默认输出模式为 `CSV + Excel`。
- Excel 中每台设备使用独立工作表，每帧占一列，每个像素占一行。

## 3. 技术栈与迁移原则

目标技术栈：

- Python 3.12 64 位。
- PySide6 / Qt 6 Widgets、Qt SerialPort。
- NumPy、SciPy、pyqtgraph。
- 支持后台、低内存写入的 XLSX 生成器。
- Windows 64 位独立程序部署工具。

依赖使用经过兼容性验证的稳定版本，并在实施时锁定精确版本。迁移遵循以下原则：

1. 先用测试固定现有正确行为，再更换 Qt 绑定和模块边界。
2. 不改动已确认正确的校准系数语义。
3. 协议、采集、处理、存储和界面通过明确的数据对象连接，不共享可变临时属性。
4. 原始帧只解析一次；显示允许合帧，存储不允许静默丢帧。
5. 不进行与目标无关的重构。

## 4. 系统架构

### 4.1 模块边界

`communication`：

- `ProtocolCodec`：构建普通指令、解析普通响应和 `0x80` 数据帧。
- `ByteStreamDecoder`：处理半包、粘包、噪声重同步和异常长度。
- `SerialTransport`：每台设备独立串口线程，只负责字节收发和连接状态。

`domain`：

- `SpectrumFrame`：设备标识、U32 包号、有效帧序号、主机时间戳、原始像素。
- `DeviceConfig`：积分时间、平均次数、触发、增益、延时、校准参数等。
- `AcquisitionSession`：会话编号、设备清单、模式、开始/结束时间和统计信息。
- `SpectrumReference`：背景或参考数据、设备序列号、像素配置、时间和来源。

`services`：

- `DeviceService`：发现、连接、初始化、查询、重连和设备排序。
- `AcquisitionCoordinator`：状态机、独立/全局启停、布防和帧分发。
- `ProcessingService`：强度校准、背景扣除、吸光度、自定义公式和 airPLS。
- `StorageCoordinator`：临时缓存、分批、CSV、Excel、恢复和队列监控。
- `SettingsService`：持久化全局设置和设备配置。

`ui`：

- 主窗口、Ribbon、上下文工具带、设备侧栏、实时绘图、历史分析、诊断和设置页面。
- UI 只调用服务接口，不直接操作串口或文件。

### 4.2 线程模型

- GUI 主线程：窗口、控件、状态展示和约 30 fps 绘图。
- 串口线程：每台设备一个，负责读写、拆包和重同步。
- 处理工作线程：处理显示所需的最新帧，慢处理允许替换尚未开始的旧任务。
- 存储工作线程：处理全部原始帧、临时缓存、CSV 和 Excel 生成。

跨线程传递不可变 `SpectrumFrame` 或其只读 NumPy 数据。禁止使用当前代码中由工作线程写、主线程轮询并清空的 `latest_pixels` 共享属性模式。

### 4.3 数据流

设备字节流经 `SerialTransport` 和 `ByteStreamDecoder` 生成 `SpectrumFrame`，然后由 `AcquisitionCoordinator` 同时发送到：

1. 无损存储通道：保存每一个有效帧。
2. 显示处理通道：每台设备只保留最新待显示帧，并按约 30 fps 更新曲线。

处理或绘图变慢不会影响存储。存储队列不静默覆盖数据。队列默认容量按“每台活动设备 4 个批次”计算；使用率达到 50% 时警告，达到 90% 时受控停止采集并完成已入队数据。

## 5. 通信协议设计

### 5.1 普通指令

普通帧：

```text
0x24 | U16LE nLength | Cmd | Params | CheckSum
```

- `nLength` 包含 `Cmd + Params`，不包含校验码。
- 物理帧总长度为 `4 + nLength`。
- 校验范围为长度字、命令码和参数的逐字节累加和低 8 位。

### 5.2 0x80 数据帧

```text
0x24 | U16LE nLength | 0x80 | U32LE nPacketNumb | U16BE Data[N] | U8 nCheckSum
```

- `nLength = 6 + 2 × N`，包含命令码、包号、像素和校验字节。
- 物理帧总长度为 `3 + nLength`。
- 校验字节必须被消费，但不验证其数值。
- 解析器按版本信息返回的像素数、起始像素和有效像素裁剪数据。
- `nPacketNumb` 完整保留为 U32，同时提供高 24 位帧序号和低 8 位保留值。

### 5.3 完整性与错误处理

- 支持任意分块输入、连续多帧和帧头前噪声。
- 对普通帧和数据帧分别计算总长度。
- 限制最大协议帧长度，防止异常长度导致无界等待或内存增长。
- 验证数据区至少包含 U32 包号，像素字节数必须为偶数。
- 记录帧序号重复、倒退、缺口和回绕，不把低 8 位保留值误当作帧号。
- 协议错误记录设备、时间、命令码、期望/实际长度和有限长度的十六进制摘要。

### 5.4 参数与同步

- 版本响应支持新增曝光时间最小值和最大值。
- 完善 `0x01–0x03`、`0x10`、`0x20–0x2c`、`0x30–0x3c`、`0x50–0x54` 和 `0x80`。
- 强度校准数组通过函数表规定的校正参数接口管理。
- `0x54` 只用于手动输出或诊断，不用于硬同步的逐帧链路。

## 6. 采集状态与同步

每台设备的状态为：

```text
Disconnected → Connecting → Initializing → Ready
Ready → Armed/WaitingTrigger → Acquiring → Stopping → Ready
任意运行状态 → Error/Disconnected
```

规则：

- 单次采集收到第一帧后立即进入停止流程，不使用固定 500 ms 延迟猜测。
- 连续采集直到用户、错误策略或设备停止。
- 外触发模式开始后显示“等待外触发”，收到第一帧后显示“采集中”。
- 参数设置只在设备确认成功后更新已生效状态；失败时恢复界面值并报告原因。
- 断线后保留端口标识并按退避策略重连；用户可关闭自动重连。

同步规则：

- 软同步：上位机向全部已启用设备发送启动命令，并记录实际发令时间差。
- 总内硬同步：先把副机配置为外部触发并布防，再配置/启动软件触发主机。
- 总外硬同步：完成主机和副机的外触发布防后等待外部信号；主机下位机自动输出同步脉冲，上位机只接收采集数据。
- 主机、设备延时和同步布线关系在界面中明确显示并保存到会话元数据。

## 7. 光谱处理

原始传感器计数是可追溯数据源，默认原始文件不覆盖为处理结果。处理后的曲线可以另存，并在元数据中记录处理模式和参数。

处理顺序：

1. 原始像素。
2. 可选强度校准。
3. 显示模式：原始、扣背景、吸光度或自定义公式。
4. 对非吸光度模式可选 airPLS 基线校正。

背景和参考光谱：

- 按设备生产序列号、像素数、起始像素和有效像素关联。
- 默认使用本设备最新的兼容记录。
- 用户可以从历史记录中选择；不允许自动跨设备套用。
- 缺少背景或参考时不返回伪造结果，界面明确提示采集或选择数据。

自定义公式：

- 对每个像素/波长点计算新曲线，不修改原始帧。
- 允许变量：`I`、`Idark`、兼容别名 `Ib`、`I0`、`x`。
- 允许运算：`+ - * / **`、正负号和括号。
- 允许函数：`log10`、`log`、`loge`、`abs`、`sqrt`。
- 使用语法树白名单解析，拒绝未知名称、属性访问、下标、导入或任意 Python 代码。
- 公式语法、数组形状、除零和非有限结果均给出明确反馈，不静默退回原始数据。

## 8. 界面设计

界面沿用参考图的布局：

1. 顶部标题区：产品名、版本和在线设备数。
2. 主 Ribbon：开始/停止、背景、参考、触发、同步、查找设备、新建页面、历史、设置、诊断、帮助和退出。
3. 页面工具带：打开、保存、显示模式、自定义公式、基线、缩放和坐标轴控制。
4. 左侧设备区：总控和设备卡片。
5. 中央工作区：实时、历史和诊断标签页及光谱图。
6. 底部状态栏：采集状态、接收帧、包序号缺口、绘图帧率、存储队列和磁盘空间。

交互规则：

- 单次/连续模式使用显式选择，不再隐藏在右键菜单中。
- 设备卡片只保留积分时间、平均次数、启停、背景、参考和详细参数入口。
- 增益、校准、触发、延时和同步参数放入结构化详细参数页面。
- 背景、参考和校准状态显示有效性、采集时间和来源。
- 实时曲线、对比曲线和基线曲线使用独立集合，清除一种不会删除其他种类。
- 实时页支持最多 64 条对比曲线；历史查看器支持至少 12 个标签和每标签 64 条曲线。
- 短暂错误使用非阻塞提示；断线、写盘失败等重要错误使用顶部警示条并进入诊断日志；只有需要用户选择时才弹窗。

## 9. 存储与文件格式

### 9.1 批次和输出模式

- 默认每批 500 帧，可在 1–1000 帧范围内配置。
- 输出选项：仅 CSV、仅 Excel、CSV + Excel；默认 CSV + Excel。
- 多设备默认分别保存。
- 合并模式下，CSV 仍按设备分别保存；Excel 为一个工作簿，包含“采集概要”和每台设备的独立工作表。

### 9.2 数据方向

CSV 和设备工作表使用相同方向：

```text
Pixel | Wavelength | Frame_1 | Frame_2 | Frame_3 | ...
0     | 340.12     | 3969    | 3964    | 3963
1     | 340.37     | 3951    | 3950    | 3973
```

- 每帧一列，每个像素一行。
- 帧标题区域记录完整 U32 包号、有效帧序号和采集时间戳。
- Excel 单批 500 帧远低于工作表列数上限；界面只接受 1–1000 帧，超出范围时拒绝保存设置并提示允许范围。

### 9.3 元数据

每个文件或工作表记录：

- 会话编号、批次编号、开始/结束时间。
- 设备编号、端口、生产序列号和控制器序列号。
- 波段、像素数、起始像素、有效像素。
- 积分时间、平均次数、增益。
- 触发模式、同步模式、主机和各设备延时。
- 波长和强度校准信息。
- 接收帧数、保存帧数、包号缺口和软件错误统计。

### 9.4 临时缓存与恢复

- 当前批次先写入版本化的 `.part` 二进制缓存。
- 每条缓存记录包含设备标识、包号、时间戳、像素长度、像素数据和记录 CRC32。
- 达到批次边界后关闭 `.part`，优先生成 CSV，再生成 Excel。
- 导出在后台执行；下一批采集不等待上一批 Excel 完成。
- 启动时扫描未完成缓存，验证记录 CRC32，恢复完整记录并报告被截断的尾记录。
- Excel 失败时保留缓存和 CSV，可由用户重新生成。
- 背景和参考光谱立即独立保存，使用唯一文件名，不覆盖历史记录。

## 10. 错误处理与诊断

- 串口错误、协议错误、设备 NAK、状态机错误、处理错误和存储错误使用分类错误对象。
- 用户提示包含可执行建议，诊断日志保留技术细节。
- 单台设备故障不停止其他设备，除非当前同步组要求整体一致性。
- 同步组中任一必需设备断线时，受控停止整个同步组并保存已接收数据。
- 存储队列使用率达到 50% 时提示；达到 90% 或磁盘空间不足时受控停止，不覆盖旧数据。
- 所有异常路径都更新状态栏和诊断页，禁止静默 `except`。
