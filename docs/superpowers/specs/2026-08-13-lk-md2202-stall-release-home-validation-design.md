# LK-MD2202 脱离卡死与机械回零有效性校验设计

## 1. 文档状态

- 日期：2026-08-13
- 状态：用户逐节确认
- 目标分支：`codex/lk-md2202-integration`
- 实施基线：`bbd85f5`（LK-MD2202 旧版身份与通信兼容修复）
- 上位机平台：Radxa ROCK 4B+、Debian 12 Bookworm ARM64、Python 3.11、PyQt6
- 驱动板：LK-MD2202，X/M1、Y/M2 两轴，地址 1、9600 baud、8N1
- 机械常量：X/Y 行程均为 15 mm，终点位置均为 4800 pulse，换算为 320 pulse/mm
- 上一版总体设计：`docs/superpowers/specs/2026-08-10-lk-md2202-motor-integration-design.md`

本文是在现有 LK-MD2202 电机集成基础上的定向修复设计。它不替代原总体设计，只覆盖脱离卡死、机械回零有效性校验、运动停止不确定性以及本轮已经发现的串口和界面状态问题。

## 2. 故障证据与问题定义

实机已经得到以下证据：

1. X 轴机械回零时，手动闭合零点限位能够让电机立即停止；驱动板随后上报累计位置 0、限位闭合，上位机显示已校准。
2. 一次未及时闭合限位的回零中，电机到达机械硬端后继续输出，直到切断驱动板电源。
3. 重新上电时限位处于闭合状态，现有程序能够直接得到“累计位置 0 + 限位闭合”，并把该轴判定为已校准，但这并不能证明本次真的发生过回零运动。
4. 松开限位后执行远离零点的普通位置运动，电机发出声音但不转；驱动板累计位置却从物理零点继续增加到 1280 pulse。由此证明 LK-MD2202 的累计脉冲是开环命令计数，不能单独证明电机实际移动。
5. 使用厂商调试软件的“速度控制”功能，向相应轴写入正速度并在脱离后写入速度 0，可以让电机恢复运动；随后重新机械回零可恢复正常。
6. 当前上位机“设速”写入的是位置模式最大速度寄存器，不是厂商软件使用的速度控制寄存器，因此此前改变位置速度并不能复现厂商工具的恢复方法。

因此，本次要解决的不是普通位置速度选择问题，而是：

- 把厂商速度模式恢复手段安全地集成进现有 PyQt6 软件；
- 防止“上电时限位已经闭合”被误认为一次有效机械回零；
- 缩短无效回零的机械硬顶时间；
- 在通信结果未知时不伪造“已经停止”；
- 保持用户原先确定的“机械回零可选，未校准扫描只警告、不强制禁用”规则。

## 3. 方案比较与选择

### 3.1 仅检查回零后的累计脉冲

回零结束后检查累计位置是否为 0。改动最小，但现有程序已经同时检查累计位置 0 和限位闭合，本次故障仍然通过了校准判定，因此该方案不能覆盖实际问题，不采用。

### 3.2 继续依赖厂商调试软件

发生故障后退出本软件，使用 Windows 厂商工具写速度模式，再返回 ROCK 4B+。该方案能恢复实机，但依赖另一台电脑和另一套软件，操作链长，也不能统一处理停止确认和坐标失效，不采用。

### 3.3 集成受控的“脱离卡死”动作

在每个轴的主界面增加“脱离卡死”，单击后使用驱动板速度控制寄存器运行，按照限位变化、1 秒绝对超时和 4800 pulse 理论行程上限停止。恢复结束后保持未校准，必须由后续机械回零重新建立零点证据。

这是已确认采用的方案。它保留厂商工具已经验证有效的恢复原理，同时加入上位机状态机、停止确认和失败锁定。

## 4. 协议与速度语义

### 4.1 LK-MD2202 寄存器

| 语义 | X/M1 | Y/M2 | 类型 |
|---|---:|---:|---|
| 速度控制 | `0x001C/0x001D` | `0x003C/0x003D` | int32，正负表示方向，0 表示减速停止 |
| 位置模式最大速度 | `0x001E/0x001F` | `0x003E/0x003F` | uint32 |
| 相对位置运动 | `0x0020/0x0021` | `0x0040/0x0041` | int32 |
| 位置模式立即停止 | `0x0024` | `0x0044` | 写 1 |
| 机械回零 | `0x0025` | `0x0045` | 写 1 |
| 限位状态 | `0x0026` | `0x0046` | uint16，只读 |
| 运行状态 | `0x0027` | `0x0047` | uint16，只读 |
| 累计位置 | `0x0028/0x0029` | `0x0048/0x0049` | int32，只读 |

速度控制的 32 位有符号值必须通过一次 Modbus `0x10` 多寄存器写入提交，禁止拆成两个单寄存器写入。运动命令不得因为超时而自动重发。

### 4.2 主界面速度框的双重语义

每个轴仍只保留一个主界面速度输入框，但允许输入正值或负值：

- 点击“设速”时，向位置模式最大速度寄存器写入输入值的绝对值；
- 点击“脱离卡死”时，直接读取输入框当前带符号值，写入速度控制寄存器；
- 正反向定距运动、扫描和机械回零始终使用位置模式速度的正值；
- 输入 0 时拒绝“设速”和“脱离卡死”；
- 速度绝对值继续使用现有正常运动速度范围 `100～14000 pps`，不因为加入速度模式而开放驱动板的完整极限范围；
- 点击“设速”后，提示应同时说明正常运动速度和当前脱离卡死速度，例如：`运动速度已设为 5000 pps；脱离卡死速度为 -5000 pps`。

输入框的正负号属于当前连接会话：

- 设置成功后，当前界面保留用户输入的正负号，不被驱动板回读到的正数覆盖；
- 断开、重连或重启软件后，从驱动板读取位置模式速度，并以正值显示；
- 不永久保存负号，防止下一位操作人员误用旧方向。

## 5. “脱离卡死”状态机

### 5.1 入口与互斥

- X、Y轴控制行分别在“机械回零”旁增加“脱离卡死”按钮；
- 采用单击后自动运行，不采用按住运行、松开停止；
- 设备必须已连接，速度非 0，当前没有其他电机运动或扫描任务；
- 脱离卡死、机械回零、定距移动、软件回零和扫描互斥；
- 动作开始即把对应轴坐标标记为未校准；
- 运行期间禁止重复点击“脱离卡死”，但急停始终可用。

### 5.2 启动

启动前读取并记录：

- 轴；
- 输入框的带符号速度；
- 初始限位状态；
- 初始运行状态；
- 动作开始时间。

随后向对应轴速度控制寄存器写入带符号速度。该符号直接使用 LK-MD2202 驱动板原生方向，不经过普通位置运动的“上位机方向反转”映射。

### 5.3 停止条件

动作启动后持续读取该轴状态，满足任一条件即进入停止流程：

1. 初始限位闭合，随后观察到“闭合 → 断开”：认为已经离开零点开关，提前停止；
2. 初始限位断开，随后变为闭合：可能选择了朝零点的错误方向，立即停止并提示检查速度正负号；
3. 达到 1 秒绝对超时；
4. 达到 4800 pulse 理论行程时间上限；
5. 用户急停；
6. 串口错误、设备断开或应用退出。

单次允许运行时间为：

```text
release_timeout_s = min(1.0, 4800 / abs(signed_speed_pps))
```

例如：

- 10000 pps 时，最迟约 0.48 秒停止；
- 5000 pps 时，最迟约 0.96 秒停止；
- 更低速度时，仍不得超过 1 秒。

4800 pulse 是理论命令量上限，不代表编码器反馈；它只用于限制一次速度模式命令的最长持续时间。

### 5.4 停止与结果

正常停止流程：

1. 向速度控制寄存器写入 0；
2. 回读运行状态，确认该轴已经停止；
3. 再次读取限位和累计位置用于诊断；
4. 显示`脱离卡死命令已结束，请确认实际位置并重新机械回零`；
5. 轴始终保持未校准，脱离卡死本身不能建立坐标可信度。

如果速度 0 写入或停止回读超时，则补发一次位置模式立即停止命令。该命令是额外兜底，不能替代速度模式写 0，也不能在通信失败时被描述为已经生效。

## 6. 机械回零有效性校验

### 6.1 回零入口

- 机械回零不是扫描前置条件；用户可以自行决定是否回零；
- 如果回零开始时驱动板上报限位闭合，拒绝本次回零，并提示先执行“脱离卡死”；
- 只有开始时限位断开，才发送对应轴机械回零命令；
- 发送后记录本次回零专属的限位变化，不使用连接前或上一次动作留下的限位状态作为证据。

### 6.2 有效回零判据

机械回零只有同时满足以下条件才标记为已校准：

1. 本次回零开始时限位断开；
2. 本次回零过程中实际观察到“断开 → 闭合”；
3. 驱动板最终运行状态为停止；
4. 驱动板最终累计位置为 0；
5. 驱动板最终上报限位闭合。

累计位置为 0 和限位闭合只是必要条件；没有本次动作中的限位转换证据，不能判定有效回零。

### 6.3 动态超时

现有固定 60 秒回零等待过长，改为按当前位置模式速度计算：

```text
calculated_s = 4800 / abs(position_speed_pps) * 3 + 0.5
home_timeout_s = clamp(calculated_s, 2.0, 5.0)
```

例如：

- 10000 pps 时使用 2 秒下限；
- 5000 pps 时约 3.38 秒；
- 很低速度时仍最多等待 5 秒。

超时后立即发送位置模式急停，回读运行状态并把该轴标记为未校准。如果无法确认已经停止，则进入“停止状态未知”锁定。

## 7. 未校准扫描与运动锁定

保持用户原先确定的策略：机械回零可选，未校准不直接禁用扫描。

- X或Y未校准时启动扫描，弹出一次警告：`X/Y轴坐标未经机械回零校准，扫描路径可能与实际位置不一致，是否继续？`；
- 用户确认后仍允许扫描；
- 未校准状态下只能验证扫描矩形本身不超过 15 mm，不能保证它相对于真实机械起点不越界；
- 电机正在运动、脱离卡死正在执行、急停或通信异常后无法确认停止时，禁止新的电机动作和扫描；
- 重新连接并确认两轴均停止后解除该锁定，但坐标继续保持未校准；
- 普通独立光谱仪采集不受电机运动锁定影响，现有光谱仪控制和采集逻辑不作改变。

## 8. 通信异常与恢复

### 8.1 停止结果未知

若速度 0、位置急停或运行状态回读无法完成：

- 不宣称电机已经停止；
- 状态显示`电机停止状态未知，请切断驱动板电源`；
- X、Y坐标标记为未校准；
- 禁止新的电机动作和扫描；
- 软件和独立光谱仪功能继续保持可响应；
- 记录轴、速度、初始与最终限位、累计脉冲、通信错误和停止命令结果。

动作命令超时表示结果未知，不得自动重发持续运动命令。

### 8.2 重连

重新连接后先读取 X、Y 运行状态：

- 两轴均停止：解除运动锁定，坐标仍未校准；
- 任一轴仍在运行：先向该轴写速度 0，再补发位置急停，并在确认停止后解锁；
- 仍无法确认停止：保持锁定并提示切断驱动板电源。

## 9. 串口发现、状态栏与限位显示

本轮同时修复已经纳入后续任务的三个问题。

### 9.1 自动发现

- 自动发现明确排除 Linux 板载调试串口 `ttyFIQ*`；
- 自动发现只探测 USB 串口候选，优先使用稳定的 `/dev/serial/by-id/` 路径；
- 仍以 LK-MD2202 只读协议响应作为最终身份依据，USB 名称本身不是设备身份；
- 手动端口设置继续保留；
- 自动发现不发送配置写入或运动命令。

### 9.2 状态栏

状态栏必须跟随识别生命周期显示：

- 识别中：`正在识别电机串口……`；
- 成功：`电机已连接：ttyUSB0`或对应稳定路径的友好名称；
- 失败：`未找到LK-MD2202电机驱动板`；
- 断开：`电机已断开`。

发现流程结束、取消或失败后必须清除“正在识别”状态，不能无限保留等待提示。

### 9.3 限位状态

- 连接空闲时每 500 ms读取一次 X、Y 状态；
- 运动期间沿用运动状态轮询；
- 界面文字使用：`驱动器上报：限位闭合`、`驱动器上报：限位断开`、`限位状态未知`；
- 实机已经表明驱动板空闲时的限位采样可能不及时，因此空闲显示只表达“驱动器当前上报值”，不表达机械触点的绝对实时状态；
- 校准判定只认可本次机械回零运动期间实际观察到的限位转换。

## 10. 组件边界

### 10.1 LK-MD2202 协议适配层

负责：

- 速度模式 int32 编码；
- X/M1、Y/M2 速度寄存器地址；
- 写入带符号速度和写入 0 停止的请求构造；
- 保持位置速度、相对运动、急停和回零现有接口不变。

协议层不负责计时、界面提示或校准判定。

### 10.2 电机控制器

负责：

- 脱离卡死状态机和截止时间；
- 限位转换记录；
- 速度 0、急停和停止确认；
- 机械回零动态超时和有效性判据；
- 未校准、停止未知和运动互斥状态；
- 连接空闲状态轮询。

控制器是唯一决定按钮可用性和运动锁定的业务状态来源，避免界面控件各自维护冲突布尔值。

### 10.3 PyQt6 界面

负责：

- 有符号速度输入；
- “脱离卡死”按钮和状态文字；
- 未校准扫描确认；
- 自动发现完成提示和限位显示；
- 把用户操作转换为控制器请求，不直接构造 Modbus 帧。

### 10.4 自动发现

负责过滤 `ttyFIQ*` 和非 USB 自动候选，并保持协议身份确认。手动端口路径不受自动过滤规则影响。

## 11. 测试设计

### 11.1 协议测试

- X/M1 速度模式写入 `0x001C～0x001D`；
- Y/M2 速度模式写入 `0x003C～0x003D`；
- 验证正数、负数和 0 的 32 位有符号编码；
- 验证速度模式使用一次 `0x10` 写入；
- 验证“设速”继续写位置速度寄存器，并使用绝对值；
- 验证动作命令超时不自动重发。

### 11.2 控制器状态机测试

- 初始限位闭合，释放后提前停止；
- 初始限位断开，触发闭合后立即停止并报告方向风险；
- 初始限位断开且不变化，1 秒停止；
- 10000 pps 按 4800 pulse 上限约 0.48 秒停止；
- 5000 pps 按 4800 pulse 上限约 0.96 秒停止；
- 急停、速度 0 写入超时、状态回读超时、断开和重连；
- 停止状态未知时锁定，确认两轴停止后解锁；
- 回零必须观察到本次“断开 → 闭合”；
- 累计位置不为 0、最终限位未闭合或仍在运行时不校准；
- 回零超时按速度动态计算，并限制为 2～5 秒；
- 脱离卡死结束后始终保持未校准。

### 11.3 界面与发现测试

- 速度框支持正负数和拒绝 0；
- “设速”写入绝对值，界面保留当前会话的负号；
- 断开、重连后速度恢复驱动板正值；
- `ttyFIQ0`及`ttyFIQ*`不参与自动探测；
- 识别成功、失败、取消和断开时状态栏结束等待提示；
- 限位状态按“驱动器上报”语义显示；
- 未校准扫描弹出警告，用户确认后仍可启动；
- 无法确认停止时锁定电机动作和扫描，但不锁定独立光谱仪采集。

### 11.4 回归测试

- 现有 LK-MD2202 身份、配置、通信和运动测试继续通过；
- 扫描 `n` 次 Y、`n+1` 次 X和光谱仪联动采集逻辑不变；
- 原光谱仪连接、采集、绘图、保存和诊断测试不回归；
- 构建 ROCK 4B+ 部署镜像，并确认新增代码从主源码生成，不手工维护第二套运行副本；
- 执行完整自动化测试、Python 编译检查和差异格式检查。

## 12. ROCK 4B+ 实机验收

实机按照由低风险到高风险的顺序进行：

1. 更新前在 ROCK 4B+ 备份当前 `/opt/zgcai-spectrometer` 中所有将被替换的文件，并记录恢复路径；
2. 先确保机构处于中间安全位置或卸除负载；
3. 分别使用正、负速度验证 X/Y“脱离卡死”的方向、速度 0 停止和急停；
4. 限位初始闭合时执行脱离，验证释放后提前停止；
5. 限位初始断开时执行错误方向，验证闭合后立即停止并提示方向风险；
6. 验证 1 秒绝对超时和 4800 pulse 理论上限均能结束动作；
7. 故意不闭合零点限位，验证机械回零在 2～5 秒动态超时内急停；
8. 完成一次真实“断开 → 闭合”机械回零，确认最终累计位置 0、限位闭合、停止且显示已校准；
9. 断开 RS-485 制造通信异常，验证停止未知锁定和重连后的停止确认；
10. 验证 `ttyFIQ0`不再出现为候选，自动识别完成后状态栏提示正确；
11. 验证未校准扫描警告、用户确认继续、正常扫描及光谱仪联动采集；
12. 验证独立光谱仪采集、绘图和保存不受影响。

每个实机用例记录输入速度、方向、开始与结束限位、运行状态、累计脉冲、实际机械现象、停止原因和结果。未经实机观察，不能仅根据累计脉冲变化把普通运动判为真实成功。

## 13. 回退与工作区保护

- 所有实现继续在 `codex/lk-md2202-integration` 分支进行；
- 实现前记录当前提交和工作区状态；
- 只暂存本任务明确修改的源代码、测试和文档；
- 不修改或清理用户现有的表格、Word文档、CSV、PDF、诊断包和临时资料；
- 每个可独立回退的阶段单独提交；
- ROCK 4B+ 部署前创建带时间戳的文件级备份，并提供恢复命令；
- 不改变原光谱仪控制逻辑，不删除原光谱仪软件，不覆盖历史 TMC2209 回退资料。

## 14. 非目标与保证边界

- 不增加编码器或闭环位置反馈；
- 不保证仅凭累计脉冲发现普通运动失步、堵转或丝杆未转；
- 不把机械回零改为扫描强制前置条件；
- 不自动执行“脱离卡死后立即回零”，两步由用户分别发起；
- 不移植激光器、旧数据处理、Tkinter 或 Matplotlib；
- 不改变现有光谱仪设备协议、采集、绘图和保存逻辑；
- 不承诺软件能够在 RS-485 完全断开时让驱动板停止；此时必须明确提示切断驱动板电源；
- 机械限位转换只为零点提供独立物理证据，15 mm另一端仍没有机械终点反馈。

## 15. 完成标准

只有同时满足以下条件才算完成：

1. X/Y均可通过主界面单击“脱离卡死”执行带符号速度模式，并在所有停止条件下进入可验证的停止流程；
2. “设速”使用绝对值，负号只影响当前会话的脱离卡死方向；
3. 单次脱离卡死不超过 1 秒和 4800 pulse理论时间上限；
4. 机械回零必须观察到本次“断开 → 闭合”，并满足停止、累计位置 0、限位闭合后才校准；
5. 回零超时按公式计算并限制在 2～5 秒；
6. 停止结果未知时不伪造成功，锁定新的电机运动和扫描；
7. 未校准扫描仅警告，用户确认后仍可继续；
8. 自动发现排除 `ttyFIQ*`，状态栏能正确结束识别提示，限位显示采用“驱动器上报”语义；
9. 自动化测试、完整回归、部署镜像检查和 ROCK 4B+ 实机验收通过；
10. 原光谱仪功能保持不变，所有修改均有明确备份和回退路径。
