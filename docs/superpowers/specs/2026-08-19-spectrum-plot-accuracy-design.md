# 光谱曲线精确绘制修复设计

## 1. 背景与结论

本设计用于修复光谱曲线在抽样或无效数据处理过程中可能产生的窄峰丢失、峰值比例变化和跨断点连线问题。目标运行平台是 ROCK 4B+（Debian 12 ARM64、PyQt6），同时保证备用绘图后端行为一致。

检查结果如下：

- ROCK 4B+ 默认使用 PyQtGraph。当前实现保留完整数组，并在 3648 点合成数据上成功显示了 1945、1948、1951 三个窄峰，因此未复现旧后端“放大后仍无法恢复已丢点”的直接故障。
- PyQtGraph 仍启用了自动降采样，使用 `connect="all"`，并拒绝包含非有限 Y 值的数据，尚未建立严格的精确绘制保证。
- 备用 legacy 后端会根据绘图区宽度使用 `linspace` 对整帧等距抽样。以 3648 点、约 430 个显示点为例，选中索引包含 1938、1946、1955，却跳过 1945、1948、1951，因此确定存在与参考问题相同的缺陷。
- 小屏幕自适应问题已确认存在，但用户决定本次不修改界面布局。

## 2. 目标

1. 始终保留每帧完整 X/Y 数组，不按窗口宽度破坏性删除绘图点。
2. 当前可见 X 范围内的所有原始点均参与绘制。
3. 可见范围两侧各保留至少一个相邻数据点。
4. Y 中的 NaN/Inf 形成曲线断点，不能跨越无效区域直接连线。
5. 缩放只改变视图范围，不修改峰的位置、数量、高度和相对比例。
6. 连续采集期间继续显示最新帧，并保持用户手动选择的视图范围。
7. 支持设备实际报告的任意有效像素数，不假设每台设备为 3648 或 4096 点。
8. PyQtGraph 和 legacy 后端遵循相同的数据准确性约定。

## 3. 非目标

本次不实施以下内容：

- 主窗口 1024×600 响应式布局；
- Ribbon、参数工具栏、设备侧栏、设备卡片或电机区重排；
- 设置对话框自适应；
- 帧序号、更新时间或像素数的新界面控件；
- 光谱仪采集协议、数据解析、校准、处理、存储或导出逻辑；
- 电机控制、机械回零、扫描运动或光谱仪联动逻辑；
- 平滑、插值、峰值重构或以美观为目的的数据修改；
- OpenGL 绘图。

## 4. 数据约定

绘图入口接收一维 X/Y 数组：

- X/Y 长度必须相同；
- 数组长度由当前帧和设备配置决定，不设置固定像素数；
- 多台设备可以同时使用不同数组长度；
- X 必须全部为有限值；
- Y 可以包含非有限值，非有限位置表示曲线断点；
- 输入数组转换为连续的 NumPy 浮点数组，并作为该曲线的完整最新数据保留；
- 空数组或少于两个有效连续点时不绘制折线，但不得导致程序崩溃。

若 X/Y 维度或长度不合法，或 X 包含 NaN/Inf，则拒绝本次更新并保留上一帧已显示曲线。该错误沿用现有上层异常记录路径，不改变采集任务状态。

## 5. PyQtGraph 后端

`spectrometer/ui/pyqtgraph_plot_widget.py` 调整如下：

1. `setData()` 始终接收完整数组，不在调用前抽样。
2. 关闭自动降采样：`autoDownsample=False`。
3. 保留可见范围裁剪：`clipToView=True`。
4. 使用 `connect="finite"`，让非有限 Y 值形成断点。
5. 不启用跳过有限值检查。
6. 自动范围和边界计算只使用 X 中的有限值以及 Y 中的有限值。
7. 更新现有曲线对象，不为每帧重建曲线和图例。

`clipToView` 仅减少不可见区域的渲染工作，不得删除当前可见范围内的原始点。

## 6. Legacy 后端

`spectrometer/ui/plot_widget.py` 调整如下：

1. 删除 `_curve_point_limit()` 驱动的全帧 `linspace` 等距抽样及其索引缓存。
2. 每次绘制都从曲线保存的完整数组中选择当前视图 X 范围内的数据。
3. 对每个可见连续片段，在范围左右各加入一个原始相邻索引；边界不存在时只保留可用一侧。
4. 根据 Y 的有限性将数据拆成连续段，分别调用 `drawPolyline()`。
5. 禁止先删除所有无效点后将剩余点连成一条折线，因为该做法会跨越 NaN/Inf 区域。
6. 全局视图绘制全部原始点；不以绘图区像素宽度限制原始数据点数量。

可见区选择按数组实际长度和 X 值计算，不依赖固定像素编号，也不要求不同设备具有相同长度。

## 7. 缩放和连续更新

- 鼠标左键框选后关闭自动调整范围，并保存当前 X/Y 视图。
- 后续最新帧替换曲线完整数据，但不重置手动视图。
- 新帧长度变化时仍保留当前视图；用户主动恢复初始视图或开启自动缩放后才重新计算范围。
- 鼠标左键双击恢复当前完整数据对应的初始坐标范围，但不自动重新启用持续自动缩放。
- 固定 Y 轴和框选缩放继续遵循现有交互约定，不改变原始数据。

连续采集仍使用现有“最新显示槽”：旧的待显示帧可以被更新帧覆盖，避免 GUI 积压；完整采集、持久化和缺帧统计路径不受本次修改影响。

## 8. 性能边界

准确性优先于显示刷新率：

- 不允许通过删除可见区点、平滑或插值提高绘图速度；
- 复用曲线对象、连续 NumPy 数组、`clipToView`、关闭抗锯齿和限制十字光标频率等现有优化继续保留；
- 页面不可见时继续沿用现有暂停显示处理、只保留最新帧的策略；
- 若 ROCK 4B+ 在最高实际负载下显示性能不足，只允许降低显示刷新频率，不改变采集、保存速率，也不恢复破坏性降采样。

## 9. 自动测试

### 9.1 窄峰准确性

- 构造在 1945、1948、1951 位置具有三个窄峰的数据；
- 在完整视图和局部放大视图验证三个峰全部存在；
- 验证峰的 X 坐标和 Y 强度与输入数组一致。

### 9.2 峰值比例

- 构造在 618、624、633 位置具有不同高度的三个峰；
- 验证完整视图和放大视图中的强度顺序、坐标和原始值不变。

### 9.3 动态像素数

- 使用多种数组长度参数化测试；
- 同时创建不同长度的设备曲线；
- 验证可见区选择和边界相邻点按各自实际数组计算。

### 9.4 非有限值

- X 含 NaN/Inf 时拒绝更新并保留上一帧；
- Y 含 NaN/Inf 时接受更新并产生断点；
- legacy 后端验证不会跨无效区域绘制直线；
- PyQtGraph 验证使用有限值连接规则。

### 9.5 交互和连续更新

- 手动缩放后更新多个最新帧，验证视图范围不变；
- 新帧长度变化时验证视图不被自动重置；
- 双击恢复初始范围后验证持续自动缩放未被擅自开启。

### 9.6 回归

- 更新目前要求 `autoDownsample=True` 的测试；
- 删除或改写目前要求“每水平像素最多一个点”的 legacy 测试；
- 运行绘图后端、缩放、主窗口显示相关测试；
- 运行完整测试集，覆盖采集、电机、扫描、存储、处理和导出。

## 10. ROCK 4B+ 验收

部署前建立明确的文件级备份和回退路径，然后依次验证：

1. 板端导入和离屏控件构造；
2. 合成三窄峰及不等高三峰数据；
3. 实际光谱仪连续采集、框选放大和双击恢复；
4. 使用现有可用设备验证不同实际像素数；
5. 尽可能使用三台设备，或使用现有设备与等效模拟负载，验证最高实际显示负载；
6. 比较输入、处理、显示发布和实际绘制速率；
7. 观察 GUI 响应、CPU、内存和温度；
8. 确认完整采集、存储、扫描联动和停止流程未受影响。

验收必须记录环境、命令、预期结果、实际结果和诊断证据。自动测试不能替代真实桌面和真实设备验收。

## 11. 部署与回退

- 仅部署本设计涉及的绘图和必要状态衔接文件；
- 部署前按时间戳保存板端原文件；
- 通过 Python 编译检查、文件哈希和定向测试后再启动正式软件；
- 实机异常时先停止软件，再用备份文件原位恢复并重新校验哈希；
- 不覆盖用户数据、设置、诊断包或未涉及的光谱仪/电机代码。

## 12. 完成标准

只有同时满足以下条件才视为完成：

- 两个绘图后端均不做破坏性全帧抽样；
- 可见区窄峰、峰值高度和相对顺序与原始数组一致；
- Y 非有限值显示为断点；
- 动态像素数和多设备不同长度测试通过；
- 手动视图在连续更新中保持稳定；
- 完整自动测试通过；
- ROCK 4B+ 实机验证通过或明确记录尚待用户执行的实机项目；
- 部署和回退步骤可重复执行；
- 未实施任何界面自适应改动。
