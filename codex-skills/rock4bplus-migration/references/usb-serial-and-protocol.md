## 1. 分层身份

不要把一个字段承担全部身份职责。

```text
VID:PID / USB class
  → 候选设备
协议握手
  → 确认设备类型
生产序列号或设备证书
  → 物理设备身份
tty 路径 / USB 拓扑
  → 当前连接位置和诊断信息
```

同型号设备通常共享 VID:PID。`/dev/ttyACM0` 会因拔插和枚举顺序变化。只有
协议返回的可靠唯一身份才适合关联持久配置。

序列号为空或重复时：

- 不静默合并设备；
- 显示身份冲突；
- 记录当前 tty 和 USB 拓扑；
- 将持久化配置降级为当前会话；
- 让用户明确选择，而不是猜测。

## 2. 驱动与 USB 拓扑

只读检查：

```bash
lsusb
lsusb -t
ls -l /dev/ttyACM*
udevadm info --query=property --name=/dev/ttyACM0
sudo dmesg --since "10 minutes ago"
```

分别回答：

- USB 设备是否枚举；
- 使用哪个内核驱动；
- 连接在 USB 2.0 还是 3.x 路径；
- 是否出现 reset、disconnect、overflow 或 error；
- 是否生成预期字符设备；
- 当前用户是否有权限。

USB 总线显示空闲不证明设备固件持续发送正确数据；同样，GUI 卡顿也不证明
USB 丢帧。

## 3. 权限与 udev

推荐 udev 原则：

- 精确匹配子系统和已确认候选属性；
- 将字符设备分配给专用组或 `dialout`；
- 普通用户加入对应组；
- reload/trigger 后重新登录或重插设备；
- 不使用 `MODE="0666"`；
- 不为多台同型号设备创建同一个公共软链接；
- `/dev/serial/by-id` 仅在设备确实提供可靠序列号时使用。

安装脚本改变 udev 和用户组前必须说明影响。验证时使用新登录会话中的 `id`。

## 5. 长度与字节序

协议最常见错误不是“大小端完全错”，而是同一帧不同字段使用不同端序，或
`nLength` 是否包含命令、数据、包号、校验字节存在歧义。

验证方法：

1. 停止正式软件，确保串口只被一个程序占用；
2. 发送版本/参数查询确认命令通道；
3. 使用单次采集，不必先连续采集；
4. 保存完整十六进制响应；
5. 从帧头计算长度字段；
6. 以候选公式计算物理总长度；
7. 对下一帧头位置和像素数；
8. 再用连续采集验证帧边界和包号。

单帧足以判断大部分长度语义；连续采集用于验证相邻帧、回绕、尾帧和 ACK
夹杂。

## 6. 流式拆包

串口是字节流，不是消息队列。拆包器必须支持：

- 帧头被拆在多次读取；
- 多帧一次到达；
- 控制帧和数据帧交错；
- 像素/负载中出现与帧头相同的字节；
- 尾部只到达半帧；
- 噪声或丢字节；
- 不同协议版本的合法物理长度。

在缓冲中只在满足全部候选约束时消费完整帧。区分：

- 缓冲区容量上限；
- 单帧物理长度上限；
- 当前协议精确长度。

不要把 2 MiB 缓冲上限当作合法帧长度。

## 7. 重新同步

安全策略：

1. 寻找候选帧头；
2. 检查长度字段是否在可接受集合；
3. 检查命令码；
4. 检查当前协议/元素数；
5. 普通控制帧检查可靠校验；
6. 候选失败时只丢弃当前帧头字节；
7. 继续扫描同一缓冲；
8. 找到合法帧后增加恢复计数。

不要：

- 一次丢弃候选声明的巨大长度；
- 在负载中遇到帧头就立即切帧；
- 关闭所有校验；
- 每次错误都重开串口；
- 用 GUI “就绪”状态代替真实 ACK。

错误日志应汇总，避免错误风暴反过来阻塞事件循环。

## 8. 控制 ACK 与数据

高速数据和控制响应共享串口时：

- 控制帧永远不受显示节流影响；
- 停止命令在采集中仍可发送；
- ACK 必须匹配等待中的命令；
- 数据尾帧在停止 ACK 前后均可能到达；
- 停止状态机需要 ACK、尾帧静默和超时；
- 超时后报告设备可能仍在输出，不伪造成功；
- 新开始命令不能与未完成停止重叠。

若错误拆包后 ACK 超时，先修复字节流恢复，不要只延长超时。

## 9. 序号诊断

分别统计：

- 正常连续；
- 缺口；
- 重复；
- 回退/乱序；
- 回绕；
- 显示主动跳过。

序号检查必须知道位宽和预留位。显示通道只看到抽样帧时，包号跨度不等于真实
缺帧；全量接收层才是权威。

序号缺口证明有帧未被当前层观察到，但不能单独证明当前帧的像素内容错误。

## 10. 断线重连

断开时：

- 立即标离线；
- 停止接收新数据；
- 安全结束当前任务；
- 保留或封存恢复数据；
- 释放串口和 worker；
- GUI 保持可操作。

重连时：

- 重新枚举，不死守旧 tty；
- 重新握手；
- 重新读取身份和参数；
- 用可靠物理身份关联配置；
- 防止重复 worker；
- 回到就绪，不自动续接旧采集会话。
