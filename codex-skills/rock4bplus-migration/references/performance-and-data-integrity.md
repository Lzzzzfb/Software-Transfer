## 1. 先定义保证

高吞吐硬件软件应先写清：

> 已送达操作系统并能恢复为完整合法单元的数据，要么持久化成功，要么明确
> 报错并受控停止；不得因 GUI、绘图、处理或导出负载静默丢失。

不要承诺：

- 设备固件未发送的数据；
- USB/驱动在应用可见前已丢失的数据；
- 没有端到端校验时每个负载值绝对正确；
- 突然断电前尚未刷盘的最后窗口。

保证边界决定架构和验收计数。

## 2. 分层速率模型

至少记录：

```text
raw_bytes_per_second
complete_units_per_second
persisted_units_per_second
processed_units_per_second
display_published_per_second
display_painted_per_second
exported_units
```

再记录累计：

- 缺失；
- 重复；
- 乱序；
- 拒绝候选；
- 重新同步；
- 显示主动覆盖；
- 队列压力；
- 写盘错误。

不能用 GUI 状态栏 FPS 代表设备输入。一个系统可以同时有 90 FPS 完整持久化、
25 FPS 显示发布和 22 FPS 实际绘制。

## 3. 数据主通道与显示旁路

推荐：

```text
硬件输入
→ 完整解析
→ 结构/序号检查
→ 顺序追加持久化
├→ 最新显示槽 → GUI
└→ 停止后处理/导出
```

主通道观察每个完整数据单元。显示旁路有意允许丢弃旧画面：

- 队列容量 1；
- 新画面覆盖旧画面；
- 覆盖数单独统计；
- GUI 卡顿不形成采集背压；
- 页面恢复时画最新数据。

显示抽帧发生在持久化之后，而不是解析之前。

## 4. 线程、进程与 GIL

选择 QThread 当：

- 主要工作是 Qt I/O；
- 计算轻量；
- 需要与 Qt 信号槽整合；
- GIL 争用可忽略。

选择独立进程当：

- 持续高频解析或转换；
- GUI 与采集会互相争用单核/GIL；
- 需要串口和持久化故障隔离；
- 导出大型 CSV/XLSX；
- 算法计算明显。

进程拥有资源的原则：

- 一个采集进程独占一个设备句柄；
- GUI 不直接读同一串口；
- 控制通过明确 IPC；
- 数据落盘后再向 GUI 发布摘要或最新帧；
- 工作进程异常必须被主进程观察。

## 5. 有界队列和背压

所有队列都要回答：

- 容量；
- 满时策略；
- 哪些数据可覆盖；
- 哪些数据不可丢；
- 水位警告；
- 受控停止门限。

典型策略：

- 显示：容量 1，覆盖旧项；
- 诊断采样：合并同类最新值；
- 关键诊断：尽力保留并统计诊断丢弃；
- 全量数据：先落盘，不通过 GUI 队列；
- 导出任务：有界，满时不退回 GUI 同步执行。

不要使用“无限队列 + 以后会消费完”的假设。

## 6. 顺序追加缓存

高吞吐采集期间优先写轻量二进制记录，而不是持续更新 XLSX。

记录应包含：

- 魔数和格式版本；
- 设备/会话身份；
- 序号和位宽；
- 单调时间和系统时间；
- 数据维度；
- 原始负载；
- 记录长度；
- 记录级 CRC/哈希。

规则：

- 顺序追加；
- 有界批次 flush/fsync；
- 完整停止后原子封存；
- 异常保留 `.part`；
- 恢复只读取完整校验记录；
- 不把未封存文件伪装为完整输出。

## 7. 处理快照

任务开始时冻结：

- 处理模式；
- 校准；
- 背景/参考；
- 算法参数；
- 单位和坐标；
- 自定义公式；
- 处理管线版本。

GUI 显示和最终导出使用同一算法和快照。采集中修改设置只影响下一任务。

对全量数据执行复杂处理时，放到独立处理/导出进程。显示处理只需最新画面。

## 8. 导出与原子发布

导出流程：

1. 从封存缓存读取；
2. 校验记录；
3. 执行冻结处理链；
4. 写临时目标；
5. 重新打开并核对结构/计数；
6. 原子改名为最终文件；
7. 全部目标成功后清理临时缓存。

失败时：

- 不发布半成品；
- 保留恢复缓存；
- 报告精确路径和原因；
- 不阻塞 GUI；
- 不把正确采集标成“没有数据”。

最终至少核对：

```text
complete_units == persisted_units == exported_units
```

若业务允许拒绝数据，另列 `rejected_units`，并证明每个输入单元都有去向。

## 9. 异常数据策略

先在原始、未做背景/校准的数据上判断结构有效性。

可靠拒绝条件：

- 长度无效；
- 维度不符；
- 可靠校验失败；
- 负载无法完整解析；
- 会话协议不匹配。

以下不能单独证明帧错误：

- 大量接近 0；
- 整体饱和；
- 强度快速变化；
- 背景扣除后负数；
- 序号跳变；
- 与上一帧差别大。

统计异常优先标记“可疑并保留”。只有经过数据集和物理实验验证的组合特征
才能升级为拒绝规则。

## 10. 性能诊断

建立 A/B：

- 自动保存开/关；
- 实时页/诊断页；
- 旧/新绘图后端；
- 处理算法开/关；
- 不同显示 FPS；
- GUI 进程/采集进程 CPU；
- 离屏/桌面；
- 不同采集间隔。

常用只读证据：

```bash
top -H -b -n 10 -d 1 -p "$pid"
ps -p "$pid" -o pid,stat,pcpu,pmem,rss,vsz,etime,cmd
cat /sys/class/thermal/thermal_zone0/temp
df -h
```

判断：

- 单线程 100% 且系统多数核心空闲：单核/GIL/绘图；
- 仅实时页高：绘制路径；
- 自动保存后主进程高：处理/导出未隔离；
- persisted 跟不上 complete：主通道或磁盘；
- complete 连续但 display 低：显示节流/GUI，不是采集丢帧。

## 11. 停止和恢复

停止顺序：

1. 优先发送设备停止；
2. 等待对应 ACK；
3. 继续接收尾部数据；
4. 达到静默窗口；
5. flush 并封存；
6. 核对完整/持久化计数；
7. 异步导出；
8. 成功后清理恢复缓存；
9. 失败时保留并报告。

停止、保存和 GUI 状态必须区分。按钮不能在设备已停但文件尚在导出时误报
“就绪且全部完成”。

- [ ] 高吞吐计算/导出已评估独立进程
- [ ] 每个队列有满载策略
- [ ] 缓存记录有版本和完整性校验
